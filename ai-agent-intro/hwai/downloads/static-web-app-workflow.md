# 六步驟工作流程（Workflow）

1. **需求**：用四句話寫使用者、輸入／操作、輸出、限制。列三個以上預期案例；先人工計算或確認來源。
2. **專案**：資料夾內保留 brief.md、各版本 prompt.md、assets/ 和 notes.md。Basic 在空白資料夾新對話開始，只接收 Basic 提示。後續功能需求在 Minor 才加入。
3. **最小版本**：做出可操作的 index.html，保存為 01-short。先跑正常案例，記錄 AI 自行補出的決定。
4. **實測**：使用真實瀏覽器。表格欄位為「操作／輸入、預期、實際、通過／待修／未測」。測空白與錯填、邊界、鍵盤、手機、離線；數字題另測精度、單位與四捨五入。截圖必須對應版本、操作與結果。
5. **修改**：02-full 明確完整功能且只指定白底、藍色按鈕、單欄。03-improved 複製完整功能後，依一般用語指定的配色、區塊位置、文字大小與手機排列改變外觀。每版都可獨立開啟；保留功能回歸案例。
6. **交付**：README 說明開啟方式、使用範例、素材位置、限制與未測項目。三版本各保存提示與截圖，附一份版本比較和驗收紀錄。

問題回報格式：版本／視窗寬度、輸入、操作、預期、實際、希望修改的位置。修好後重做原案例，避免只看新畫面。

若瀏覽器工具不可用，先交付可審查檔案與操作步驟，明列「尚未瀏覽器驗證」，不可假造截圖或通過數。
