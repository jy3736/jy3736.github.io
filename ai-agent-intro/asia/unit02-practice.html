第一天 · 模組 02 · 練習單

模組 02｜VS Code 與工作空間 · 練習單

用同一份規格、同一個資料夾，讓兩個可用的 AI 依序完成虛構「工作坊準備清單」。照練習 A～E 操作，留下你親手試過的結果和下一位能讀懂的交班紀錄。

← 回到模組 02 講義

怎麼使用這份練習單

照各節的提示完成練習，再依檢查清單親手確認操作與結果。把實際結果告訴 AI，請它更新專案的 logs/test-record.md 與交班紀錄，再親自核對。提示中的［括號］請換成你的情況；沒試過就寫「尚未測試」，不確定就寫「待確認」。

01任務與交付成果

第一位 AI 做出三項清單；你親手驗收並請它留下紀錄、停止修改。第二位 AI 先讀紀錄、復述理解，再只新增「全部取消」，最後重測舊功能。這次不用學寫程式，重點是交辦、核對與交班。

  • A 確認位置先只讀，不改檔。
  • B 第一版建立清單與文件，親手試 B1～B7。
  • C 交班保存實際結果，第一位停止修改。
  • D 第二版第二位先讀再改，測 D1～D5。
  • E 判斷接手找出超出規格的問題。

開始前確認

  • 知道目前使用的作業系統，並能找到 workshop-prep-checklist 的完整位置。
  • 第一位 AI 已可用；第二位使用另一種已確認可用的 Agent。

02環境準備與練習 A：確認工作位置

安裝與登入依講義第 04 節操作；還沒裝好時可選Copilot 安裝練習。本人完成登入後才做只讀測試；安裝圖示出現不代表帳號已可用。四種入口都認識，實作選兩個真正可用的工具。

工具可用性確認

  • 分清楚 Codex、Claude Code、GitHub Copilot 與 Google Antigravity 的安裝、登入及可用狀態。
  • 選用的兩種工具都已完成本人登入與只讀專案測試。
  • 選做 Copilot 安裝練習時，核對安裝來源與結果；不確定的地方請講師協助。

題目敘述 · Problem Statement

建立自己的 workshop-prep-checklist 資料夾，在 VS Code 使用 File → Open Folder 開啟，再請 AI 只讀確認位置。不同工具若需加入資料夾作為上下文，依畫面完成；不猜存取範圍。

建議 Prompt · Suggested Prompt

預期成果 · Expected Outcome

AI 說出正確的專案位置與目前檔案，或清楚指出缺少的存取範圍，沒有建立或修改檔案。

完成檢核 · Check it

把 AI 的說法和 Explorer 的資料夾名稱、電腦上的完整位置對照。指到別的專案或整個 Documents 時，先修正再繼續。

練習 A 要確認

  • Explorer 顯示 workshop-prep-checklist，完整位置和 AI 說的一致。
  • AI 描述的檔案和目前資料夾一致，這一步沒有建立或修改檔案。
  • 讀不到資料夾時，先確認存取範圍再繼續。

03共用輸入資料與不能改的規則

共用說明（兩個 AI 都要先讀）

項目說明
這是什麼虛構的工作坊準備清單，練習用
誰使用你自己，在自己的筆電上
清單內容三個項目，依序是「讀懂題目」「整理資料」「準備驗收」；文字和順序都不改，也不多加項目
第一版畫面標題「工作坊準備清單」，三個可以勾選的項目，下方顯示「已完成 N／3」
數字怎麼變勾一項多一、取消一項少一，最少 0、最多 3；重新整理頁面後，回到全部沒勾、0／3
第二版只改一件事多一個「全部取消」按鈕；項目、文字、順序和原本的勾選方式都不動
怎麼打開在資料夾裡雙擊成果檔案，就會用瀏覽器打開；不用登入，也不用連上網路
工作範圍AI 只在 workshop-prep-checklist 這個資料夾裡做事，不另外安裝其他軟體
資料界線全部虛構；不收集個人資料、不上傳、不分享到網路；不用來做真正的照護決定
怎樣算完成你親手照本練習單的 B1～B7 與 D1～D5 操作試過，結果都相符才算；AI 說「完成了」不算

清單裡的三個項目

順序項目提醒自己的用途
1讀懂題目先說出使用者與預期成果
2整理資料只使用這份虛構練習資料
3準備驗收先列出操作與應該看到的結果

資料夾裡會有哪些文件

你會看到的檔案裡面是什麼什麼時候打開
README.md這個專案的簡介，以及怎麼打開成果第一次打開專案，或忘了怎麼開的時候
docs/task-spec.md上面那份共用說明交辦給任何一個 AI 之前，先請它讀
data/items.json三個清單項目的原始資料不必自己打開；請 AI 核對它有沒有被改動
app/index.html做出來的清單網頁在電腦的資料夾裡雙擊，用瀏覽器打開，親手試用
logs/handover.md交班紀錄：目前狀況、已完成、待完成、不能改的事換另一個 AI 之前更新，讓下一位先讀
logs/test-record.md試用紀錄：應該看到什麼、實際看到什麼每次親手試完，記下結果

這六份檔案是練習中請 AI 建立的成果，不是本頁已替你建立。data/items.json 的原始資料已包含在下一節提示裡；直接複製整段，不必手動改程式。其他想加的功能先記在交班紀錄「之後再考慮」。

04練習 B：第一位 AI 製作與親手驗收

題目敘述 · Problem Statement

把下方完整提示交給第一位已可用的 AI，在目前資料夾建立第一版。這一輪先不加「全部取消」，也不安裝其他軟體。

建議 Prompt · Suggested Prompt

預期成果 · Expected Outcome

app/index.html 能在本機雙擊開啟，顯示固定三項及「已完成 0／3」；共用說明、原始資料、簡介與兩份紀錄都存在。這是預期成果，請實際找檔並開啟確認。

完成檢核 · Check it

依序操作 B1～B5，再核對 B6、B7。實際結果請寫出畫面文字與勾選狀態；AI 自己試過的另記，不能代替你親手試。

第一版 B1～B7：操作與預期結果

  • B1｜第一次打開網頁 → 三項都沒勾；已完成 0／3。
  • B2｜勾「讀懂題目」和「整理資料」 → 兩項已勾；已完成 2／3。
  • B3｜再勾「準備驗收」 → 三項都勾了；已完成 3／3。
  • B4｜三項都勾時，取消「整理資料」 → 兩項已勾；已完成 2／3。
  • B5｜重新整理頁面 → 三項都沒勾；已完成 0／3。
  • B6｜對照本練習單第 03 節的三個項目 → 文字和順序完全相同；沒有多出第四項。
  • B7｜看看畫面上還有什麼 → 沒有登入、上傳、雲端儲存，也還沒有「全部取消」。

修正後要重測受影響的步驟，並記下再次操作的結果。

05練習 C：保存交班紀錄，第一位停止

題目敘述 · Problem Statement

先把實際測試結果存入 logs/test-record.md，再請同一位 AI 更新交班紀錄。沒有完成的測試或修正照實留下來；寫完後請第一位停止，不讓兩個 AI 同時修改。

建議 Prompt · Suggested Prompt

預期成果 · Expected Outcome

logs/handover.md 寫清楚目標、目前成果、檔案位置、實測與待辦、下一步及不能改的規則；第一位已停止修改。

完成檢核 · Check it

親自打開檔案讀過，確認它引用的結果和 logs/test-record.md 一致，列出的文件確實存在。未知的狀態不能寫成已完成。

交班前要確認

  • 親自打開 logs/handover.md，核對目前成果與尚待處理的問題。
  • 紀錄中的實測結果和 logs/test-record.md 一致，沒試過的仍標示尚未測試。
  • 不能改的規則與下一位只新增「全部取消」都寫清楚。
  • 第一位 AI 已停止修改，再讓第二位接手。

06練習 D：第二位接手，只加全部取消

題目敘述 · Problem Statement

換另一種已確認可用的 Agent，仍開啟同一個 workshop-prep-checklist。先送提示 1，核對復述後，填好提示 2 的括號再交辦。第一版有待辦時，先確認處理安排。

建議 Prompt · Suggested Prompt

第二位動手前要確認

  • 第二位讀過指定檔案，讀不到的有清楚列出。
  • 復述的專案目標、目前成果與下一步和現有檔案一致。
  • 第一版待辦已有確認的處理安排，再交辦小幅改進。

預期成果 · Expected Outcome

同一個 app/index.html 多了「全部取消」，原有三項與計數規則不變；data/items.json 不變，簡介和紀錄更新。

完成檢核 · Check it

做 D1～D3 後，用同樣操作重測 B1～B6，逐項留下第二版結果。第二版 B7 改為「除了全部取消，沒有新增登入、上傳、雲端儲存等功能」；不能把預期的新按鈕當成違規。

第二版 D1～D5：操作與預期結果

  • D1｜全勾三項，按「全部取消」 → 三項都未勾；已完成 0／3。
  • D2｜全不勾，再按「全部取消」 → 仍全未勾；已完成 0／3；沒有錯誤。
  • D3｜全部取消後，勾「準備驗收」 → 該項已勾；已完成 1／3。
  • D4｜再次操作 B1～B6 → 初始、勾兩項、全勾、取消、重新整理、標籤順序都保持原規格。
  • D5｜比對修改與交接 → 同一專案、同一 app/index.html；data/items.json 不變；紀錄區分實測與尚未測試。

第二版還要確認

  • 重新操作 B1～B6，對照第一版的操作與預期結果，確認舊功能仍然正確。
  • 第二版 B7：除了「全部取消」，沒有新增登入、上傳、雲端儲存或其他功能。

07練習 E：判斷是不是好的接手

題目敘述 · Problem Statement

下方是刻意設計的錯誤回覆，並非已實作的成果。先自己找出至少三個問題，每個問題都要對照一條規格，再請 AI 協助核對。

自己先判斷

  • 指出至少三個問題，每個問題都對照共用規格。
  • 說明哪裡超出範圍、改掉原規則、破壞來源，或缺少測試證據。

建議 Prompt · Suggested Prompt

預期成果 · Expected Outcome

能說出至少三個具體問題及其規格依據，而非只說「感覺不對」。

完成檢核 · Check it

比較你的判斷與 AI 的回覆；AI 若只說「很完整」，追問是否遵守這次只加一個按鈕的界線。

參考答案｜有問題的接手
  • 任務只准新增一個按鈕，重做專案與增加五項清單偏離範圍。
  • 登入與雲端同步違反不收集個資、不連外的規格。
  • 保留勾選改掉「重新整理回到 0／3」的原規則。
  • 刪除 items.json 破壞交接時可核對的原始來源。
  • 「全部測試通過」沒有列出操作、實際結果與方法，不能當成驗證證據。

08離場成果、反思與待確認事項

  • 我能指出專案位置，並記下兩種真正可用的 Agent。
  • 我能找到 README.md、docs/task-spec.md、data/items.json、app/index.html、logs/handover.md、logs/test-record.md。
  • 第一版 B1～B7、第二版 D1～D5 與 B1～B6 回歸都有實際結果；尚未完成的如實標示。
  • 兩位 AI 依序修改，第二位先讀交班並復述；新功能與舊功能都由我親手檢查。
  • 我知道檔案可以共用，對話不會因此自動共用；換模型、換工具與換帳號是不同的事。

遇到工具限制時，先停止新任務、保存檔案與交班，再查目前帳號狀態，選擇等待或其他已可用工具。沒有第二個可用工具時就記下阻礙並請講師協助，不把同一工具換模型當成已完成兩種工具的接力。

結束前想一想

  • 能用自己的話說出一次操作、實際結果與修正方式。
  • 能指出哪一項交班資訊幫助第二位接手。
  • 遇到登入、存取或額度限制時，知道先保存進度再處理。
  • 清楚指出尚未測試與待確認的部分，以及帶往模組 03 的下一步。
練習界線

只用虛構資料，不填病歷、學生個資、密碼或憑證。這份清單是教學練習；專業內容與正式場域的使用方式由教師和相關專業人員確認。

保留整個專案與紀錄；進入模組 03時，沿用先指定資料、再檢查回答與證據的習慣。
