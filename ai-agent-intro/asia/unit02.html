第一天 · 模組 02

模組 02｜讓 AI 進入專案：VS Code 與工作空間

在模組 01，我們練習把「幫我做一個工具」說成清楚的需求，並用自己的操作結果判斷 AI 是否完成。這一模組把需求放進一個真的資料夾：你會在 VS Code 開啟專案，讓 AI 讀取指定材料、做出第一版，再把進度寫下來，交給另一個 Agent 接著做。

這裡主要用 Codex 示範，也認識 Claude Code、GitHub Copilot 與 Google Antigravity。簡單任務用一個工具就可以完成；長期做教材與專題時，知道怎麼換工具、留下紀錄，會讓工作比較容易延續。你不必一次訂閱好幾種服務，也不用先學會寫程式。你的工作是說清楚需求、確認資料夾、核對修改與實際操作；AI 負責協助實作。

  • 講師：楊榮林教授／吳樺姍
  • 對象：護理教師與長照場域夥伴
  • 階段成果：一個可接手的本機專案與一份交接紀錄

01學習目標與階段成果

這一模組完成什麼

完成一個「虛構工作坊準備清單」本機專案：第一個 Agent 建立三項清單與完成數，第二個可用的 Agent 閱讀交接紀錄，加入「全部取消」按鈕，再確認原有的勾選與計數仍然正確。最後留下一份能讓別人接著工作的交接紀錄與實際檢查結果。

今天的工作順序

  • ① 確認環境開啟 VS Code 與自己的練習資料夾。
  • ② 確認工具分別登入，確認至少兩個 Agent 真正可用。
  • ③ 做出第一版用共用規格建立清單，親自試操作。
  • ④ 保存與交接把目標、檔案、進度、待辦與檢查結果存成文字。
  • ⑤ 換工具接著做讓第二個 Agent 先讀紀錄，只做一項改進。
  • ⑥ 重新驗收既有功能與新增功能都要再試一次。

離開本模組前，我能做到

  • 說出專案資料夾、VS Code 工作空間與 AI 對話各保存什麼。
  • 依官方來源找到四種工具的設定路徑，知道自己哪些已登入且可用。
  • 使用至少兩個可用 Agent，依序處理同一個專案。
  • 在檔案總管找到原始資料、成果與交接紀錄。
  • 說出第二個 Agent 讀了哪些檔案、改了什麼、哪些舊功能還正常。
  • 遇到登入或額度問題時，先保存成果與進度，再決定等待、改用其他可用工具或請講師協助。

02專案、工作空間與對話，哪裡不一樣

把 VS Code 當作工作桌

你可以把 VS Code 想成一張工作桌，專案資料夾是桌上的工作夾，Agent 是你請來協助的夥伴。工作夾裡有你提供的材料、任務說明、AI 做出的成果與後續紀錄。換一位夥伴時，工作夾還在，但新夥伴不一定知道前面談過什麼，所以需要讀取留下來的資料。

這次只用一個資料夾當作工作空間，不需要先學多資料夾設定，也不要求建立 GitHub 儲存庫。VS Code 是開啟、閱讀與管理檔案的地方；它本身不是某個 AI 帳號。安裝 Agent 擴充功能後，還要完成該服務的登入與存取確認。

什麼會留下來

名稱保存什麼換工具時怎麼處理
專案資料夾原始材料、任務規格、成果檔案與文字紀錄用第二個 Agent 開啟同一個資料夾，明確指定要讀的檔案
VS Code 工作空間目前開啟的資料夾與編輯環境確認左側顯示正確的專案名稱；不要開到另一份複本
Agent 對話這個工具或工作階段裡的問答與上下文不假設其他工具看得到；把重要決定寫進專案紀錄
帳號與額度服務的登入身分、權限與使用限制各自確認；安裝擴充功能不代表已有可用權限
交接紀錄目標、已做、未做、檔案、檢查與界線新夥伴先讀、先復述，再開始修改
換模型、換工具、換帳號，三件不同的事

在同一工具內換模型，不一定換了服務或帳號；從 Codex 換到 Claude Code、Copilot 或 Antigravity，是換工具與其工作環境；在 Codex 登出再登入另一個 ChatGPT 帳號，是換登入身分。三者都不等於「自動把前面的對話交給新的 Agent」。本模組用專案內的交接檔案延續工作。

03安裝 VS Code，開啟一個練習專案

練習 A 的環境準備

  1. 從 VS Code 官方下載頁選擇自己的作業系統。若已安裝，先確認能正常開啟，並使用與擴充功能相容的版本。
  2. Windows 通常可使用 User setup 安裝程式；依機構電腦的管理規定操作。macOS 開啟下載的安裝映像，將 Visual Studio Code.app 拖到 Applications，再開啟程式。Linux 請依官方頁面的發行版套件說明安裝。來源核對：2026-10-11，Windows 安裝、macOS 安裝、Linux 安裝。Linux 的個別安裝流程需依講師課前確認的設備補充，不在課堂臨時猜指令。
  3. 用電腦的檔案總管建立一個新資料夾，名稱是 workshop-prep-checklist。放在自己找得到、可以寫入的位置，記下位置。不放真實病歷、學生個資、密碼或服務憑證。
  4. 在 VS Code 選擇 File → Open Folder（檔案 → 開啟資料夾），選剛才的 workshop-prep-checklist。確認左側 Explorer（檔案總管）頂端就是這個名稱。若詢問工作空間信任，確認這是自己建立的練習資料夾，再依畫面與機構規定選擇；不確定的來源先問講師。
  5. 找到三個位置：Explorer 用來看檔案，Extensions 用來管理擴充功能，Agent 面板用來交辦。這次不需要你手動修改程式；程式出問題時，用一般文字描述操作與結果，請 AI 修正。

安裝成功，還不等於能用

擴充功能的搜尋名稱可能很相近。從官方文件的安裝連結進入，再核對產品與發行者。登入後，用「只讀取、不要修改」的小任務確認它能回應並取得這個專案的上下文。若只看到圖示，還沒有登入或不能回應，就記成「已安裝，尚未可用」。

05一份共用說明，讓不同 AI 接力做同一件事

像交班一樣：靠紀錄接手，不靠記憶

護理與照護現場的交班，不是要下一班記得上一班說過的每句話，而是看交班紀錄：目前狀況、已完成什麼、還要注意什麼。讓兩個 AI 接力做同一個專案，道理一樣。不同的 AI 看不到彼此的對話，能共同看到的，只有放在同一個資料夾裡的文件。

所以這一節先準備一份共用說明：要做什麼、長什麼樣子、怎樣算完成、哪些事不能做。之後不論交給哪一個 AI，都先請它讀這份說明。這樣你比較的不是哪個工具比較厲害，而是它們能不能照同一份說明，把同一件事做好。

這次要做的小工具

一張虛構的「工作坊準備清單」網頁，只用來練習，不記錄真實人員，也不用在正式照護工作。分兩次完成：

  • 第一版（第一個 AI）三個可以勾選的項目，下方顯示完成了幾項。
  • 第二版（第二個 AI）只多一個「全部取消」按鈕，其他都不改。

第二版刻意只改一件事。這樣你一眼就能看出接手的 AI 改了什麼，也能確認原本的勾選有沒有被改壞。

共用說明（兩個 AI 都要先讀）

項目說明
這是什麼虛構的工作坊準備清單，練習用
誰使用你自己，在自己的筆電上

表格中加上引號的文字，就是畫面上應該出現的字，檢查時逐字對照。

清單裡的三個項目

順序項目提醒自己的用途
1讀懂題目先說出使用者與預期成果
2整理資料只使用這份虛構練習資料

這就是全部的練習資料，沒有姓名、病歷或真實服務對象。「提醒自己的用途」只是說明，不是要勾選的第四項。第 06 節的提示會把這三項交給 AI，AI 會另外存成一份資料檔，讓下一個 AI 能核對內容有沒有被改動。

想看 AI 保存的資料檔長什麼樣子（不必看懂）

這是 AI 讀的格式，你不需要看懂或修改。第 06 節的提示已經包含這段內容，直接複製提示即可。

資料夾裡會有哪些文件

你不必自己建立這些檔案。第 06 節交辦時，AI 會照共用說明建立；你只要在 VS Code 左側的檔案總管找到它們。名稱以 .md 結尾的是一般文字檔，在 VS Code 點開就能閱讀。

你會看到的檔案裡面是什麼什麼時候打開
README.md這個專案的簡介，以及怎麼打開成果第一次打開專案，或忘了怎麼開的時候
docs/task-spec.md上面那份共用說明交辦給任何一個 AI 之前，先請它讀
data/items.json三個清單項目的原始資料不必自己打開；請 AI 核對它有沒有被改動
app/index.html做出來的清單網頁在電腦的資料夾裡雙擊，用瀏覽器打開，親手試用
logs/handover.md交班紀錄：目前狀況、已完成、待完成、不能改的事換另一個 AI 之前更新，讓下一位先讀

這些都是看得懂的一般文件，不依賴任何工具的特殊設定。換工具時，只要告訴新的 AI「先讀這幾份文件」，它就能接手。

用一般話交辦就好

你不需要知道網頁怎麼做出來，只要說清楚你想看到什麼、按了之後應該發生什麼。例如：「我按下全部取消後，三項都要變成沒勾，數字回到 0／3。」比起要求某種做法，這樣的描述更容易檢查，也更不容易被 AI 誤解。結果不對時，同樣用「我做了什麼、預期看到什麼、實際看到什麼」告訴它，請它修正。

隨時可以用的幾句話：讓 AI 跟著說明走

和 AI 一起做專案，最常見的不是它做不到，而是它做得太多、說得太難，或換了一個 AI 之後忘了前面的約定。下面幾句話照平常說話的方式寫，遇到對應的情況就複製貼上；［ ］裡的文字換成你自己的情況。不用一次全部用上，也可以用自己的話改寫，只要守住三個原則：先讀說明再動手、一次只做一件事、我親手試過才算完成。

這些句子不需要技術用語。AI 回答得太長或太難時，直接說「請用三句話、一般用語再說一次」就好；不確定要不要同意 AI 的做法時，先問它「這樣做會改到哪些地方？」再決定。

先講清楚範圍，再同意 AI 動手

請 AI 只在這個練習資料夾裡建立和修改檔案。如果它要求讀取其他資料夾、安裝新軟體、上傳或公開分享，先停下來想想是否真的需要；一份三項清單用不到整台電腦。即使網頁只放在你的電腦裡，AI 讀到的內容仍可能傳給提供服務的公司處理，所以這次只用虛構資料。

練習 B：請 AI 做出一張可以打開的清單

過程中如果 AI 做太多、說得太難，或停下來問你看不懂的問題，用第 05 節那幾句話把它拉回來就好。

07寫好交班紀錄，交給下一個 AI

只說「接著做」，下一位不知道從哪裡開始

如果你只對新的 AI 說「接著剛才做」，它不會知道「剛才」是什麼，因為它看不到上一個 AI 的對話。就像第 05 節說的交班：把重要的事寫下來，下一位先讀紀錄再接手。要寫的是：這個專案要做什麼、目前做到哪裡、有哪些文件、還差什麼，以及哪些地方不能改。

交班前，先確認第一個 AI 已經停下來、沒有還在改東西。它的對話可以留著給自己參考，但下一個 AI 只會看資料夾裡的文件。不要同時讓兩個 AI 改同一個網頁；這堂課練的是一位做完、存好，再換下一位。

09講師示範：帳號、工作階段與可用額度

先保存進度，再處理工具限制

講師平常混用 Codex、Claude Code、GitHub Copilot 與 Antigravity，會依任務、慣用的溝通方式與當時可用資源選擇工具。這不代表每件事都要換工具；簡單工作用一個就好。持續做專案時，能保存需求與進度，才有條件讓其他可用工具接手。

如果服務顯示達到限制，先停止新的工作要求，保存目前成果與交接紀錄，查看該帳號的使用狀態與畫面上的恢復時間，再選擇等待或使用另一個本來就有合法存取權的工具。這次不安排學員輪流消耗多個帳號，也不要求每個人都有兩個付費帳號。

講師專用示範與學員實作分開

講師有兩個自己的 ChatGPT 帳號，本段示範「確認身分 → 登出 → 登入另一個本人帳號 → 重讀保存的專案紀錄」。使用各帳號時仍按該服務規則與帳號限制操作。切換登入身分不會重置原帳號額度，也不能推定額度或對話已轉到新帳號。學員需要學的是辨認身分與保存專案，不必擁有多個付費帳號。

講師帳號切換示範（官方登入步驟核對：2026-10-11）

  1. 讓 Agent 完成本輪或停止修改，保存目前檔案，更新交接紀錄。將觀察者可看的專案與登入畫面分開；輸入密碼與驗證碼時由本人操作並遮蔽投影。
  2. 在 Codex IDE 擴充功能的 profile menu 查看目前帳號與登入方式，確認是預期的帳號 A。把「身分 A」當作示範代號，不把完整登入資料寫入專案。
  3. 查看目前使用狀態。官方 IDE 命令有 /status 可顯示工作階段與限制；若現場版本的選單不同，依當前狀態介面確認。只展示當時實際看到的資訊，不假設所有方案的額度一樣。IDE 命令
  4. 在 profile menu 選 Log out。確認回到未登入的畫面。
  5. 選 Sign in with ChatGPT，在瀏覽器完成帳號 B 的登入。若瀏覽器仍選到 A，先在登入流程中核對並選擇正確身分，不把「網頁已登入」誤當「擴充功能已切換」。
  6. 返回擴充功能，再查看 profile menu，確認目前身分是 B。檢查此帳號的可用性；若不能使用，就如實記錄並停止這段續作，不宣稱切換保證解決限制。
  7. 保持同一個本機專案，開新的對話，貼下方的只讀提示。讓新工作階段從檔案復述目標與待辦，核對後才授權繼續小任務。

登入與登出依據：OpenAI Authentication。官方亦說明 CLI 與 IDE 擴充功能共用登入快取；登出可能影響下一次 CLI／擴充功能登入，所以示範前先保存與停止相關工作。不要複製或展示驗證憑證檔。這段沒有在講師帳號上實際執行，課前需確認現場版本與選單位置。
