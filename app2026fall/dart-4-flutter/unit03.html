Unit 3：條件判斷、迴圈、函式與集合

2. 條件判斷：讓程式做決定

生活中充滿「如果……就……，不然就……」：如果下雨就帶傘，不然就戴帽子。程式裡用 if 和 else 來表達。

看懂 if 的寫法

  • if (條件) { ... }：小括號裡放一個會得到 true／false 的條件，成立就執行大括號裡的程式。
  • else if (另一個條件)：前面的條件不成立時，再檢查這個條件。可以接很多個。
  • else { ... }：上面的條件全都不成立時，才執行這裡。
  • 條件 ? 值1 : 值2：條件成立就用值1，否則用值2，適合「二選一」。

常見錯誤：判斷的順序寫反

電腦會從上往下檢查，第一個成立的條件執行完就結束，後面的都不看了。如果先寫 score >= 60 再寫 score >= 90，那 95 分會先符合「>= 60」，永遠拿不到 A。範圍判斷要從最嚴格的寫起（高分往低分）。

switch：情況很多的時候更清楚

當同一個值有很多種可能（例如星期幾、等第），用 switch 會比一長串 if 好讀。

  • case 後面寫「符合哪種情況」；每個 case 做完就自動結束，不用寫 break。
  • 兩個 case 疊在一起（像 '六' 和 '日'），代表共用同一段程式。
  • default 表示「其他所有情況」。
  • 下面的 switch 寫法可以直接「算出一個值」：>= 90 => 'A' 讀作「大於等於 90 的話，結果是 A」；_ 代表「其他所有情況」。

拆解 for (var i = 1; i <= 5; i++)

起點：var i = 1→檢查：i <= 5 嗎？→是：執行 { } 裡的程式→每做完一次：i++（i 加 1）→回到「檢查」

當 i 變成 6，i <= 5 不成立，迴圈就結束。

常見錯誤：停不下來的迴圈

編號從 0 開始！

第 1 個是 scores[0]，第 2 個是 scores[1]。5 個分數的編號是 0～4，所以最後一個是 scores[scores.length - 1]。這是剛開始最容易搞錯的地方。

5. 函式：把程式包起來重複使用

函式（function）就像一份食譜：給它材料（參數），它照步驟做，最後交給你成品（回傳值）。寫好一次，之後隨時叫名字就能用。其實你早就用過函式了，print() 就是一個。

看懂函式的寫法

以 double bmi(double heightCm, double weightKg) { ... } 為例：

回傳什麼型別：double函式名稱：bmi需要的材料：(double heightCm, double weightKg)步驟：{ ... return 結果; }
  • return：把結果交回去，函式到這裡就結束。
  • void：這個函式只負責「做事」（例如印東西），不交回結果。
  • =>（箭頭）：函式只有一行算式時的簡寫。bool isPassed(int score) => score >= 60; 等於寫 { return score >= 60; }。
  • 具名參數 {required String name, String sugar = '半糖'}：呼叫時要寫出名字，例如 orderDrink(name: '奶茶', sugar: '無糖')，不容易搞錯順序。required 代表一定要給，= '半糖' 是沒給時的預設值。之後學 Flutter 會大量用到這種寫法。

什麼是「函式化」？

  1. 找出程式裡重複出現，或是完成一件小事的片段。
  2. 想清楚：它需要什麼材料（參數）？會做出什麼結果（回傳值）？
  3. 包成函式、取個一看就懂的名字，原本的地方改成呼叫它。

四個處理清單的好幫手

方法做什麼本例用途
where((x) => 條件)篩選：只留下符合條件的及格名單、去掉 -999、高溫警示

怎麼讀 scores.where((s) => s >= 60)？

把清單裡的每個分數一個一個拿出來，暫時叫它 s，問：「s >= 60 嗎？」答案是 true 的就留下來。最後加上 .toList()，把留下來的變成一個新的清單。

實作題（三選一）

(a) 成績判斷：給一組分數，印出每人的等第、平均、最高分、不及格人數。

(b) 資料篩選：給一個商品 Map（品名 → 價格），列出 100 元以下的商品，以及這些商品的平均價格。

7. 測試入門：讓電腦幫你檢查答案

每次改完程式都用眼睛看輸出，很累又容易漏看。測試（test）就是先寫好「給這個輸入，應該得到這個結果」，讓電腦自動幫你一題一題對答案。作業的自動批閱，做的也是同樣的事。

這一段要在自己的電腦上執行

測試需要一個 Dart 專案（一個有固定結構的資料夾），DartPad 沒辦法做。

步驟 1：建立專案

在終端機輸入下面的指令，會建立一個叫 data_lab 的專案資料夾。第一次執行需要網路下載工具，請稍等一下。

dart create data_lab
cd data_lab

專案裡有幾個重要的資料夾：

位置放什麼
bin/data_lab.dart主程式（有 main 的地方）
lib/函式庫：把 data_tools.dart 放這裡
test/測試檔：把 data_tools_test.dart 放這裡

步驟 2：放入函式庫和主程式

  1. 在 lib/ 資料夾裡新增 data_tools.dart，貼上第 6 段的函式庫程式。
  2. 把 bin/data_lab.dart 的內容換成第 6 段的主程式（第一行是 import 'package:data_lab/data_tools.dart';，data_lab 就是專案名稱）。
  3. 執行看看：
dart run

步驟 3：寫測試

在 test/ 資料夾裡新增 data_tools_test.dart：

  • test('說明', () { ... })：一個測試，說明用中文寫也可以。
  • expect(實際算出來的, 應該要是的)：對答案。例如 expect(letterGrade(90), 'A') 的意思是「90 分應該要是 A」。
  • group('名稱', () { ... })：把同一類的測試放在一起。

要測「邊界值」

最容易出錯的是「剛好」的情況：剛好 90 分、剛好 60 分、空的清單、剛好等於門檻的溫度。上面的測試特別檢查了 90 和 89、60 和 59。

步驟 4：執行測試

dart test
全部通過時
00:00 +7: All tests passed!

測試抓到錯誤時長什麼樣子？

假設不小心把 letterGrade 裡的 >= 90 打成 > 90，90 分就會被判成 B。執行 dart test 會看到（節錄）：

測試失敗時（實際執行結果節錄）
00:00 +0 -1: letterGrade 邊界值 [E]
  Expected: 'A'
    Actual: 'B'
...
00:00 +6 -1: Some tests failed.

Failing tests:
  test/data_tools_test.dart: letterGrade 邊界值

Expected 是「應該要是」，Actual 是「實際算出來」。測試直接告訴你：「邊界值」這個測試裡，應該要是 A，結果卻是 B。這樣就知道要回去檢查 >= 90 那一行。

8. 本週重點整理

  • if／else if／else：由上往下檢查，第一個成立的就執行；範圍判斷從嚴格的寫起。
  • switch：情況很多時更清楚；_ 或 default 代表其他情況。
  • for 知道次數、for-in 走訪清單、while 條件成立就繼續；break 結束、continue 跳過。
  • List 用 [ ]，編號從 0 開始；Map 用 {鍵: 值}，查不到會得到 null。
  • 函式 = 參數（材料）＋步驟＋回傳值（成品）；具名參數在 Flutter 很常見。
  • where 篩選、map 轉換、any 至少一個、every 全部。
  • 測試用 expect(實際, 預期) 自動對答案，記得測邊界值；執行指令是 dart test。

10. 本週作業：函式化與測試

  1. 從第 6 段的實作題選一題，把程式整理成至少 2 個有寫出型別的函式，放在 lib/ 裡。
  2. 在 test/ 裡為每個函式寫至少 2 個 test，其中至少 1 個要測邊界值或特殊情況（例如空清單、剛好等於門檻、無效值 -999）。
  3. 執行 dart test，看到 All tests passed! 後截圖，連同程式一起繳交。

繳交前自我檢查

  • 函式名稱看得懂嗎？（average 比 f1 好懂很多）
  • 故意把函式改錯一個地方，測試會失敗嗎？會的話，代表你的測試真的有在檢查。檢查完記得改回來！
