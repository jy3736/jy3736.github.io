Unit 6：非同步、套件與 JSON 資料

APP 的資料多半不在自己手上：要向伺服器要、向感測器要，而這些都需要等。這個單元要學會用 Future 和 await 處理「等一下才會有的資料」，把拿回來的 JSON 文字轉成看得懂的資料類別，並為轉換過程寫測試。這是之後 APP 串接 Web API、MQTT 與雲端資料的共同基礎。

這個單元你會學到（學會了就打勾，會自動記在這台電腦的瀏覽器裡）

1. 暖身：為什麼需要「等」？

前面的程式都是算完就有答案。但「向伺服器要一份資料」不一樣：送出請求之後，可能要等 0.3 秒、也可能等 3 秒。如果程式停在那裡什麼都不做，APP 的畫面就會凍住，使用者會以為當掉了。

① 送出請求→② 等待（畫面仍可操作）→③ 拿到資料→④ 解析並顯示

Dart 用 Future<T> 表示「現在還沒有、等一下才會有的 T」。本單元用 Future.delayed 模擬等待，流程和真正連網路完全相同，之後把模擬的那一行換成 http 套件的請求就可以了。

2. Future 與 await：等到有結果再往下

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
① 開始讀取
② A1 = 27.5
③ A2 = 31.8
④ 沒有 await 時拿到：Instance of 'Future<double>'
⑤ 等它完成：27.5
  • Future<double>：「等一下會拿到一個 double」。
  • 函式要用 await，自己就必須標上 async，main 也一樣。
  • await 某個 Future：等它完成，並把結果拿出來。
  • 沒有 await 的話，拿到的是 Instance of 'Future<double>'，不是數字。

常見錯誤：忘了寫 await

錯誤訊息（實際執行結果）
e12_missing_await.dart:7:20: Error: A value of type 'Future<double>' can't be assigned to a variable of type 'double'.
 - 'Future' is from 'dart:async'.
  double celsius = readSensor();
                   ^

分析器會說不能把 Future<double> 指派給 double。這是最常見的非同步錯誤，而且在寫程式時就被抓到。看到型別是 Future 開頭，就要想到 await。

一筆一筆等，還是一起等？

先猜猜看會印出什麼，再點我看執行結果
執行結果
依序讀取：26.5, 28.0, 31.5
花了大約 600 毫秒
同時讀取：[26.5, 28.0, 31.5]
花了大約 200 毫秒
做法總時間什麼時候用
連續 await每一筆相加（約 600 毫秒）後一筆需要前一筆的結果
Future.wait([...])接近最慢的那一筆（約 200 毫秒）幾筆資料彼此無關，可以同時要

三間教室的資料就該一起要

它們互不相關。用 Future.wait 同時發出請求，使用者等待的時間可以從 3 倍變成 1 倍。

3. JSON：網路資料的共同語言

伺服器回給我們的其實是一整串文字，格式長得很像 Dart 的 Map 和 List。這種格式叫 JSON，幾乎所有 Web API 都用它。

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
電子 301
共 3 筆
A1：27.5（有效：true）
A2：31.8（有效：true）
A3：0.0（有效：false）
{"sensorId":"A1","celsius":27.5}
  • import 'dart:convert';：JSON 功能在這個內建函式庫裡，不必安裝套件。
  • jsonDecode(文字)：把文字變成 Map／List。回來的型別是 dynamic，所以要用 as 說明它是什麼。
  • (row['celsius'] as num).toDouble()：JSON 的數字可能是整數也可能是小數，先當 num 再轉 double 最安全。
  • jsonEncode(Map)：反過來把資料變成文字，準備送出去。

常見錯誤：到處寫 json['celsius']

整支程式都用 json['欄位名'] 取值，打錯字不會被抓到，欄位改名要全部找一遍。解法是下一段：先轉成資料類別。

4. 資料類別：把 JSON 變成看得懂的物件

把 Unit 4 的類別和 JSON 合起來：用工廠建構式 fromJson 負責「從一包 JSON 生出一個物件」，其他程式就只跟物件打交道。

延伸練習

先猜猜看會印出什麼，再點我看執行結果
執行結果
教室：電子 301
全部 3 筆，有效 2 筆
 - A1 27.5°C（有效：true）
 - A2 31.8°C（有效：true）
 - A3 0.0°C（有效：false）
平均：29.6°C
{sensorId: A1, celsius: 27.5, valid: true}
  • factory Reading.fromJson(...)：工廠建構式，可以先算再決定回傳什麼物件。
  • json['sensorId'] as String? ?? '未知'：欄位可能不存在，所以先當可為 null 的型別，再用 ?? 給預設值。這是 Unit 4 空值安全的直接應用。
  • toJson：要把資料送回伺服器時使用。
  • RoomSnapshot.parse：把「解析文字」也包起來，呼叫的人一行就能拿到物件。
  • 範例的第三筆故意沒有 celsius 欄位，程式不會當掉，而是得到預設值並標成無效。

5. 完整流程：等待、解析、處理失敗

真正串接服務時，失敗是常態：網路不通、教室代號打錯、回來的內容不是預期的格式。每一個取資料的流程都要先想好「失敗時畫面顯示什麼」。

先猜猜看會印出什麼，再點我看執行結果
執行結果
讀取 電子 301 ...
  電子 301：2 筆，平均 29.6°C
讀取 電子 999 ...
  讀取失敗：Exception: 找不到教室 電子 999
全部處理完畢
  • fetchRoomJson 模擬服務：等 300 毫秒後回傳 JSON，代號不存在就丟出例外。之後改用 http 套件，這個函式的外觀完全不用變。
  • try 同時包住 await 和解析：這兩件事都可能失敗，而且處理方式一樣（告訴使用者讀取失敗）。
  • 失敗的那一間不會影響其他的，程式最後照樣印出「全部處理完畢」。

要安裝套件的時候

真正連網路需要 http 套件。指令是 dart pub add http，它會把 http 寫進 pubspec.yaml 的 dependencies，程式裡再 import 'package:http/http.dart'; 就能使用。pubspec.yaml 就是這個專案的「材料清單」。

dart pub add http
dart pub get

6. 為資料轉換寫測試

fromJson 是最值得測試的地方：欄位缺漏、整數與小數、空清單，這些情況用眼睛看很容易漏掉。測試檔和 Unit 3 一樣放在 test/。

  • 完整欄位：正常情況要對。
  • 整數也要能轉成 double：JSON 寫 28 而不是 28.0 時，程式不能壞掉。
  • 缺少欄位：給安全的預設值，而不是當掉。
  • 平均只算有效讀值、沒有有效讀值時是 null：邊界情況。

把整個單元合起來：同時讀取三間教室、各自解析成物件、失敗的那間顯示「讀取失敗」，最後用集合語法組成一份看板。

實作題（作業會用到）

  1. 寫一個模擬服務的函式，回傳一整串 JSON（至少 3 筆資料，其中 1 筆欄位不完整）。
  2. 寫一個資料類別，用 fromJson 解析，缺漏欄位要有安全的預設值。
  3. 用 Future.wait 同時取兩份以上的資料，並處理其中一份失敗的情況。

8. 本單元重點整理

  • Future<T> 是「等一下才會有的 T」；用 await 拿結果，有 await 的函式要標 async。
  • 忘了 await 會拿到 Future 而不是資料，分析器會提醒你。
  • 彼此無關的請求用 Future.wait 一起等，使用者少等很多。
  • jsonDecode 得到的是 dynamic，要用 as 說明型別；數字先當 num 再轉 double。
  • 用 fromJson 把 JSON 轉成資料類別，欄位缺漏時用 ?? 給預設值。
  • 取資料的流程一定要包 try：網路與解析都可能失敗，畫面永遠要有東西顯示。
  • pubspec.yaml 是專案的材料清單，dart pub add 會幫你寫進去。
  • fromJson 要寫測試，特別是欄位缺漏與邊界情況。

10. 本單元作業：取資料並顯示

  1. 寫一個 Future 函式模擬服務，等待後回傳 JSON 文字；另外準備一個會丟出例外的情況（代號不存在或裝置離線）。
  2. 設計兩個資料類別（一筆資料 ＋ 一組資料），一筆資料的類別要有 fromJson 與 toJson。
  3. 用 Future.wait 同時取至少 3 份資料，其中 1 份會失敗；成功與失敗都要在報表上出現。
  4. 為 fromJson 寫至少 3 個測試，其中 1 個要測欄位缺漏、1 個要測邊界情況。
  5. 執行 dart test 與 dart analyze，兩者都乾淨後截圖繳交。

繳交前自我檢查

  • 把模擬服務的等待時間改成 2 秒，程式還是會正確等到結果嗎？
  • 把 JSON 裡的某個欄位整行刪掉，程式會當掉還是顯示預設值？
  • 三份資料全部改成失敗，報表還有東西可以顯示嗎？
