第 1 週：課程導論、PEA 學習循環、AI 協作規範、Dart 開發流程

這週先看清楚整學期要去哪裡、每週怎麼學、AI 什麼時候能用，然後親手跑出第一支 Dart 程式，走一次「建立 → 執行 → 修改 → 再執行」。

本週你會學到（學會了就打勾，會自動記在這台電腦的瀏覽器裡）

1. 這門課要做出什麼？

先把終點講清楚，後面每週在學什麼才有方向。

學期終點

完成一個可以在手機上執行、能和感測器或雲端資料互動的小型 App。例如畫面顯示溫濕度、光照的即時數值，可以切換開關、瀏覽清單、查看詳細資料。

教室沒有實體硬體時，我們會先用「模擬資料」（寫死或亂數產生的數值）開發，實體感測器放在課程後段再串接。

整學期路線

Dart 基礎→Flutter 畫面→資料與互動→IoT/AIoT 專題
階段週次主題在練什麼
Dart 基礎第 2–3 週變數、型別、運算子、條件、迴圈、函式、集合在主控台程式裡把「邏輯」寫對，先不管畫面
Flutter 畫面第 4–5 週widget tree、Material Design、版面配置、導覽有畫面可以看、可以操作
資料與互動第 6 週起狀態管理、表單與輸入驗證、非同步程式設計資料從哪裡來、使用者怎麼操作、畫面怎麼更新
專題整合課程後段串接感測器或雲端資料整合成 IoT/AIoT 情境的小型專題

為什麼先學 Dart，再學 Flutter？

Flutter 是用來做 App 畫面的工具組，同一套程式碼可以做出 iOS、Android、桌面和網頁 App。而 Flutter App 用的程式語言和執行環境，就是 Dart。所以 Dart 寫得穩，Flutter 才寫得動。

Dart 的兩個特色（下週會一直遇到）

型別安全：變數裡的值一定符合它的型別，寫錯型別時，Dart 會在執行前提醒你。

null safety：除非你明確允許，否則值不能是 null（什麼都沒有），很多錯誤可以提前被擋下來。

另外，Dart 在開發時支援熱重載（hot reload）：改完程式可以很快看到結果，Flutter 開發也會用到這個能力。

2. PEA 學習循環：每週怎麼學？

「什麼時候該預習？什麼時候練習？什麼時候會被檢核？」這門課把每一週拆成三個階段：

階段你要做什麼老師／課程會做什麼
Preview 預習課前閱讀資料，可以用 AI 幫忙理解提供本週重點與官方文件連結
Engage 課中參與動手寫程式、討論、修正錯誤帶領示範、巡堂協助除錯
Assess 檢核完成前測／後測或作業，展示自己的理解出 n 選 m 前測／後測、批閱作業
Preview 讀文件＋用 AI 釐清觀念→Engage 寫程式、看結果、討論→Assess 前後測、交作業→拿回饋，進入下一週
  • Preview：課前先有基本認識，上課時間才能拿來動手做。
  • Engage：真正犯錯、修正的階段。錯誤訊息本身就是學習材料（第 6 段馬上體驗）。
  • Assess：讓你知道自己掌握了多少，也讓老師調整教學步調。

3. 生成式 AI 協作規範

AI情境例子
✅ 可以Preview 自學請 AI 用不同方式解釋一個 Dart 語法
✅ 可以專題開發除錯、重構建議、理解官方文件的英文用語
❌ 不可以列入成績的 n 選 m 前測／後測每週的前測、後測
❌ 不可以隨堂測驗、考試、標示「個人獨立完成、自動評分」的作業自動批閱作業

為什麼前測／後測不能用 AI？

前測／後測檢核的是你自己現在懂多少。當下用 AI 作答，就算答對，結果也無法反映你真正的學習狀態，老師也沒辦法依此調整教學。這和「預習、做專題時鼓勵善用工具」並不衝突，只是依情境劃出界線。

AI 提示與驗證紀錄

從這週開始，每次用 AI 協助寫程式或除錯，記下三件事：

  1. 提示內容摘要：你問了 AI 什麼。
  2. AI 給的建議：摘要重點就好，不必整段複製。
  3. 驗證方式與結果：你怎麼確認建議是對的（例如執行 dart analyze、dart run、對照官方文件），以及結果如何。

重點在第 3 項

沒有自己動手確認過，這則紀錄就不完整。第 5、6 段學到的 dart run 和 dart analyze，就是你最基本的驗證工具。這份紀錄會一路用到期末專題。

4. 開發環境：DartPad 與 Dart SDK

看不懂 for？沒關係

在自己的電腦安裝 Dart

  1. 依照官方說明安裝：Get the Dart SDK（官方建議用套件管理工具安裝）。
  2. 如果你已經裝了（或打算裝）Flutter SDK，就不用另外裝 Dart，因為 Flutter SDK 裡面已經包含完整的 Dart SDK。這門課之後要寫 Flutter，直接裝 Flutter SDK 也可以。
  3. 打開「終端機」（Mac 搜尋 Terminal；Windows 搜尋 PowerShell），輸入：
dart --version
# 看到類似下面這行就成功了（版本號可能不同）
Dart SDK version: 3.9.2 (stable) ...

如果出現 command not found，代表還沒裝好，請回到官方安裝說明檢查設定。

5. 第一個 Dart 專案：建立、執行、修改

這一段要親手走一次「建立 → 執行 → 修改 → 存檔 → 再執行」，這就是整學期的開發節奏。

1建立專案

dart create hello_dart

dart create 會建立一個資料夾和專案檔案，接著自動下載需要的套件（畫面上會看到 Running pub get...）。沒有特別指定時，它會建立一個命令列程式專案（console 範本）。產生的檔案如下：

hello_dart/
├── bin/hello_dart.dart         ← 程式的進入點，可執行的程式放這裡
├── lib/hello_dart.dart         ← 程式庫的程式碼
├── test/hello_dart_test.dart   ← 測試
├── pubspec.yaml                ← 專案名稱與套件設定
├── analysis_options.yaml       ← 程式分析的設定
├── CHANGELOG.md
└── README.md

檔案很多沒關係，這週只要記得 bin/ 和 pubspec.yaml，其他之後用到再說。

2執行

cd hello_dart
dart run
# 執行結果
Hello world: 42!

6. 先分析，再執行：dart analyze

dart analyze 會檢查程式有沒有寫錯，檢查的內容和 VS Code 這類編輯器裡看到的一樣。最棒的是：不用執行程式，就能先把錯誤找出來。

dart analyze       # 檢查目前資料夾裡所有的 Dart 檔案
dart analyze bin   # 只檢查 bin 資料夾

全部沒問題時，會看到 No issues found!。

故意打錯字看看

把 split 打成 spit，執行後會得到這樣的錯誤：

錯誤訊息（實際執行結果）
e8_method_typo.dart:3:30: Error: The method 'spit' isn't defined for the type 'String'.
Try correcting the name to the name of an existing method, or defining a method named 'spit'.
  for (final char in 'hello'.spit('')) {
                             ^^^^

如果改用 dart analyze 檢查，還沒執行就會看到同一個錯誤：

error - e8_method_typo.dart:3:30 - The method 'spit' isn't defined for the type 'String'. ... - undefined_method

1 issue found.

怎麼讀錯誤訊息

3:30 代表「第 3 行、第 30 個字元」。訊息的意思是：文字（String）沒有叫做 spit 的方法，請改成正確的名稱。把 spit 改回 split 就好了。

在 DartPad 裡打錯字，右下角也會出現警告；硬是按執行，就會看到編譯錯誤。

小練習

回到你的 hello_dart 專案，只刪掉第一行 import，但保留 hello_dart.calculate()。先猜猜會發生什麼事，再執行 dart analyze，找出錯誤的「行:字元」，然後改到出現 No issues found! 為止。

做完再看：會看到什麼錯誤？ 
error - bin/hello_dart.dart:2:25 - Undefined name 'hello_dart'. ...

import 被刪掉之後，Dart 不知道 hello_dart 是誰。可以把 import 加回來，或把 print 裡用到 hello_dart 的部分改掉。

和 AI 紀錄的關係

AI 給你修改建議後：先 dart analyze 看到 No issues found!，再 dart run 確認結果正確。把這兩步寫進紀錄的「驗證方式與結果」，就是一則完整的紀錄。

7. 情境練習：哪個階段？AI 能不能用？

和旁邊的同學討論，每個情境寫下「屬於 PEA 哪個階段」「AI 能不能用」「理由」：

  1. 上課前，先請 AI 用不同方式解釋「dart create 產生的 bin/ 和 lib/ 有什麼不同」。
  2. 隨堂的 n 選 m 前測，檢核 var／final／const 的差異。
  3. 期末專題開發時，請 AI 協助找出畫面沒有更新的原因。
  4. 課堂實作時 dart run 出現錯誤，請 AI 解讀錯誤訊息，自己修改後重新執行。
討論完再看參考答案
情境階段AI理由
1Preview可以課前自學、釐清觀念
2Assess不可以列入檢核的前測，要反映自己的理解
3Engage（專題實作）可以專題除錯是允許的情境，但要寫驗證紀錄
4Engage可以課堂練習不是檢核；重點是自己改、自己重跑

8. 本週重點整理

  • 學期終點：做出能和感測器或雲端資料互動的 App；路線是 Dart 基礎 → Flutter 畫面 → 資料與互動 → 專題。
  • PEA：Preview 預習、Engage 課中動手、Assess 檢核，每週循環一次。
  • AI 可以用在預習和專題；列入成績的前測／後測、考試、自動評分作業不可以用。
  • AI 紀錄三件事：問了什麼、AI 建議什麼、自己怎麼驗證。
  • DartPad 免安裝就能寫 Dart；Flutter SDK 內含完整的 Dart SDK。
  • dart create 建立專案、dart run 執行；程式從 bin/ 裡的 main() 開始。
  • dart analyze 不用執行就能先找錯；錯誤位置 行:字元。
