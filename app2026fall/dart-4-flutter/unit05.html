Unit 5：例外處理、enum、extension 與集合語法

真實資料一定有壞掉的那幾筆：感測器沒回應、使用者打錯字、欄位是空的。這個單元要讓程式遇到壞資料也不會整個當掉，並用 enum 把「只有幾種狀態」寫成型別、用 extension 幫現成型別加上自己要的方法，最後用集合語法一次組出畫面要顯示的清單。

這個單元你會學到（學會了就打勾，會自動記在這台電腦的瀏覽器裡）

1. 暖身：程式當掉的時候發生了什麼事？

上一個單元用 ? 處理「沒有值」。但還有另一種情況：動作本身失敗了。例如把 '三十度' 交給 double.parse，它無法給出任何合理的數字，只能丟出例外（exception）。

錯誤訊息（實際執行結果）
Unhandled exception:
FormatException: Invalid double
三十度

沒有人接住的例外會讓程式立刻停止，後面的資料再也不會被處理。在 APP 上就是「整個畫面卡住或閃退」。所以只要那一行可能失敗，就要決定：失敗的時候要做什麼？

① 可能失敗的動作→② 成功：繼續／③ 失敗：接住並處理→④ 收尾

關鍵字作用
try { ... }把「可能失敗」的那幾行放進來
on FormatException只處理這一種例外，其他的不管
catch (e)接住例外物件，可以看內容或印出來
finally { ... }不論成功或失敗都會執行，用來收尾

try 裡面只放「會失敗的那幾行」

把整個程式包在一個大 try 裡面，等於「出錯了但我不知道是哪裡」。範圍越小，錯誤訊息越有用。

常見錯誤：用 catch 把錯誤吃掉

catch (e) { } 裡面什麼都不寫，程式不會當掉，但你也永遠不知道有幾筆資料壞掉。至少要印出來或記下來，讓自己看得到。

回傳 null，還是丟出例外？

情況建議做法寫法
失敗很正常，呼叫的人會處理回傳 nulldouble.tryParse(text)
失敗代表有問題，不該繼續丟出例外double.parse(text) 或自己 throw

小練習：一整批文字轉數字

給一個 List<String>，把能轉成數字的收進一個清單、不能轉的收進另一個清單，最後兩個清單都印出來。程式不可以中途停止。

3. 自訂例外：說清楚是哪一種失敗

FormatException 只說「格式不對」。但我們常需要更具體的資訊：哪一台感測器、為什麼失敗。自己定義例外型別就能把這些資訊帶著走。

延伸練習

先猜猜看會印出什麼，再點我看執行結果
執行結果
檢查 A1
  正常：27.5 度
檢查 A2
  [記錄] SensorException(A2)：感測器沒有回應
  這一台先標記為異常（感測器沒有回應）
檢查 A3
  [記錄] SensorException(A3)：讀值 150.0 超出合理範圍
  這一台先標記為異常（讀值 150.0 超出合理範圍）
  • class SensorException implements Exception：自訂例外只要實作 Exception 就好，可以自由加欄位。
  • throw SensorException(...)：發現不合理就丟出去，讓呼叫的人決定怎麼處理。檢查資料的函式不該自己決定要不要顯示錯誤訊息。
  • rethrow：這一層先記錄（log），再把同一個例外往上丟。用 throw e 會遺失原本的呼叫堆疊，rethrow 不會。
  • on SensorException catch (e)：同時指定型別又拿到物件，可以讀 e.reason。

4. enum：把狀態變成型別

用字串表示狀態很容易出錯：'警報'、'警戒'、'danger' 混用，打錯字也不會被發現。enum 把所有可能的狀態列出來，打錯字在寫程式時就被抓到。

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
26.0 度 → 正常（不用處理）通知：false
31.5 度 → 注意（開電風扇）通知：true
37.2 度 → 警報（立刻通知管理員）通知：true
[正常, 注意, 警報]
  • 加強版 enum 可以有自己的欄位和方法：label（顯示文字）、rank（嚴重程度）、needsNotify（要不要通知）。
  • switch 搭配 enum 時，少寫一種狀態，分析器就會提醒你。這是用字串永遠得不到的保護。
  • AlertLevel.values：拿到全部狀態，之後在 APP 裡做成下拉選單很方便。

小練習：裝置狀態

定義 enum DeviceStatus，包含連線中、離線、維護中三種狀態，每個狀態帶一個 label 和一個 canControl（是否可操作）。印出每個裝置的狀態，再列出目前可以操作的裝置。

5. extension：幫現成的型別加方法

double 和 String 是 Dart 內建的型別，我們改不了它們，但可以用 extension 幫它們加上自己需要的方法，讓程式讀起來像在講人話。

延伸練習

先猜猜看會印出什麼，再點我看執行結果
執行結果
31.3°C
true
26.5 → 26.5°C
28.0 → 28.0°C
「三十度」無法轉成數字
  • extension CelsiusFormat on double：對所有 double 生效，31.267.asCelsius 就能直接用。
  • this 在 extension 裡指「被呼叫的那個值」本身。
  • toDoubleOrNull 把「轉不成就回 null」包成一個看得懂的名字，比每次都寫 double.tryParse(text.trim()) 清楚。

什麼時候用 extension？

當你發現同一段小處理（格式化、去空白再轉數字、判斷是否超標）在程式裡重複出現，就是把它變成 extension 的時機。

6. 集合語法：在建立清單時就組好內容

畫面上要顯示的清單，常常是「固定幾項 ＋ 依條件多幾項 ＋ 依資料重複幾項」。Dart 讓你在 [ ] 裡面直接寫展開、判斷和迴圈，不必先建空清單再一行行 add。

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
[溫度, 濕度, 二氧化碳, 照度]
[溫度, 濕度]
[查看資料, 匯出報表]
[全部, 感測器 1, 感測器 2, 感測器 3]
=== 教室環境 ===
A1 27.5°C
A2 31.8°C（偏熱）
寫法意思用在哪
...另一個清單把它的內容全部倒進來合併預設項目與額外項目
...?可能是 null 的清單是 null 就當作沒有這一段選填的設定
if (條件) 項目條件成立才放這一項依身分顯示不同選單
for (var x in 清單) 項目一邊走訪一邊產生項目把資料變成畫面上的一列一列

這就是之後排版畫面的寫法

Flutter 的畫面是一個「元件清單」，if 元素和 for 元素就是之後「有資料才顯示」、「每筆資料一列」的標準做法。

7. 綜合實作：不會當掉的報表

把四個主題放在同一支程式裡：解析失敗丟出自訂例外、狀態用 enum、格式化用 extension、報表用集合語法組出來。

先猜猜看會印出什麼，再點我看執行結果
執行結果
=== 環境監測報表 ===
A1 27.5°C（正常）
A2 31.8°C（注意）
--- 以下需要檢查 ---
A3：「三十度」不是數字
A4：感測器沒有回應
有效 2 筆、異常 2 筆
  • 四筆原始資料裡有兩筆是壞的，程式照樣跑完，並把壞掉的原因列在報表下半部。
  • ok 和 failed 分開收集：好資料繼續算，壞資料留紀錄。
  • 最後的 report 清單就是「畫面上要顯示的每一行」，之後換成 Flutter 只是把 print 換成顯示元件。

實作題（作業會用到）

  1. 把上一個單元的類別作業加上例外處理：資料不合理時丟出自訂例外。
  2. 把「狀態」改用 enum 表示，並用 switch 決定對應的建議動作。
  3. 報表用集合語法組成一個 List<String>，最後用一個迴圈印出來。

8. 本單元重點整理

  • try 只包會失敗的那幾行；on 指定型別、catch 拿到物件、finally 收尾。
  • 失敗很正常就回傳 null（tryParse）；失敗代表有問題就 throw。
  • 自訂例外可以帶欄位，把「哪一台、為什麼」說清楚；rethrow 保留原本的呼叫堆疊。
  • 不要用 catch (e) { } 把錯誤吃掉，至少要留下紀錄。
  • enum 把狀態變成型別，switch 少寫一種狀態會被分析器抓到。
  • extension 幫現成型別加方法，讓重複的小處理有名字。
  • 清單裡可以直接寫 ...、...?、if、for，一次組好要顯示的內容。

10. 本單元作業：讓程式承受壞資料

  1. 準備一批至少 6 筆的原始資料（文字形式），其中至少 2 筆是壞的（不是數字、空字串，或代表失敗的 -999）。
  2. 解析時遇到壞資料要 throw 自訂例外；主程式接住後，把原因收進「需要檢查」的清單，程式不可以中途停止。
  3. 用 enum 表示至少 3 種狀態，每個狀態帶 label，並用 switch 產生對應的建議動作。
  4. 用集合語法組出報表清單（含標題、每筆資料、異常區塊、統計行），印出來後截圖繳交。

繳交前自我檢查

  • 把好資料全部改成壞資料再跑一次，程式還是不會當掉嗎？報表會顯示「沒有有效資料」嗎？
  • switch 裡故意刪掉一種 enum 狀態，分析器有提醒你嗎？（確認完記得補回去）
  • 有沒有哪個 catch 裡面是空的？
