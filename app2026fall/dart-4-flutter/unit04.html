Unit 4：類別、建構式與空值安全

前面的程式把資料和處理分開放：一個 List 放分數、另一個 List 放名字，很容易對不起來。這個單元要把「一筆資料」和「對這筆資料的動作」包成一個類別，並學會用 ? 明確表示「這個值可能沒有」。這兩件事是之後寫 APP 畫面時每天都會用到的基本功。

這個單元你會學到（學會了就打勾，會自動記在這台電腦的瀏覽器裡）

1. 暖身：為什麼需要類別？

上一個單元用兩個清單存同一批人的資料：

var names = ['小明', '小美'];
var scores = [92, 54];

這種寫法有兩個麻煩的地方：順序一錯，資料就對不起來；而且「這個人及不及格」的判斷散落在程式各處。類別（class）就是把「名字、分數」和「判斷及格」放在同一個地方，從此拿到一個學生物件，就同時拿到他的資料和動作。

① 定義類別→② 建立物件→③ 讀寫欄位→④ 呼叫方法

2. 類別與物件：把資料和動作放在一起

類別是「設計圖」，物件是照著設計圖做出來的東西。一張設計圖可以做出很多個物件，每一個都有自己的資料。

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
小明：92 分（及格）
小美：54 分（不及格）
小明
小美：61 分（及格）
  • class Student { ... }：定義一個新的型別，名稱用大寫開頭。
  • 類別裡面的變數叫欄位（field）：這個物件「有什麼資料」。
  • Student(this.name, this.score); 是建構式（constructor）：建立物件時要交給它的資料。this.name 的意思是「把收到的值直接放進自己的 name 欄位」。
  • 類別裡面的函式叫方法（method）：它可以直接用自己的欄位，不用再傳一次參數。
  • bool get isPassed => score >= 60; 是 getter：用起來像欄位（a.isPassed），算出來像函式。

物件之間互不影響

a 和 b 是兩個獨立的物件，改 b.score 不會影響 a。這正是我們要的：每位學生有自己的分數。

3. 建構式：讓呼叫的人一看就懂

Student('小明', 92) 只有兩個值還好，如果有五、六個值，看程式的人根本分不出哪個是什麼。Flutter 的元件幾乎都用具名參數，所以現在就要習慣。

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
A1：27.5°C
A2：31.2°C
A3：讀取失敗
true
寫法用途例子
{required this.x}具名參數，呼叫時一定要給Reading(sensorId: 'A1', celsius: 27.5)
{this.x = 預設值}具名參數，可以不給isValid 沒寫就是 true
類別.名字()具名建構式：另一種建立方式Reading.failed('A3')
const 類別(...)值在編譯時就固定，不會再改固定的設定值、固定的畫面內容
final 欄位建立之後就不准改感測器編號、量到的溫度

常見錯誤：required 的參數忘了給

具名參數沒有順序，所以漏掉一個不會被「順序」抓出來，而是由分析器直接告訴你。

錯誤訊息（實際執行結果）
e9_missing_required.dart:9:18: Error: Required named parameter 'celsius' must be provided.
  var r = Reading(sensorId: 'A1');
                 ^
e9_missing_required.dart:5:3: Context: Found this candidate, but the arguments don't match.
  Reading({required this.sensorId, required this.celsius});
  ^^^^^^^

訊息裡的 missing_required_argument 就是「少給了一定要給的參數」。這種錯誤在還沒執行時就會被抓到，是空值安全與具名參數帶來的好處。

小練習：學生類別

寫一個 Student 類別，用具名參數 name 和 score 建立物件，並加上一個 grade getter：90 以上 A、80 以上 B、70 以上 C、60 以上 D，其餘 F。建立三個學生並印出來。

4. 空值安全：這個值到底會不會是 null？

null 代表「沒有值」。Dart 規定：型別後面沒有 ? 的變數，永遠不會是 null；會是 null 的資料，型別一定要寫成 String?、double? 這種形式。這樣一來，「忘了處理沒有資料的情況」在寫程式時就會被抓出來，而不是等 APP 在使用者手上當掉。

基本範例

先猜猜看會印出什麼，再點我看執行結果
執行結果
2 個字
null
null
（沒有綽號）
綽號有 2 個字
紅茶 20 杯、咖啡 0 杯
寫法意思什麼時候用
String name保證有值一定會有的資料，例如感測器編號
String? nickname可能是 null查不到、還沒填、讀取失敗
x?.lengthx 是 null 就整個算式是 null不確定有沒有值，又不想當掉
x ?? 預設值x 是 null 就用預設值畫面上要顯示「尚未設定」
if (x != null) { ... }檢查過就可以直接用需要連續使用同一個值

常見錯誤：直接對可能是 null 的值呼叫方法

錯誤訊息（實際執行結果）
e10_null_method_call.dart:3:18: Error: Property 'length' cannot be accessed on 'String?' because it is potentially null.
Try accessing using ?. instead.
  print(nickname.length);
                 ^^^^^^

分析器會說 The property 'length' can't be unconditionally accessed because the receiver can be 'null'，意思是「這個值可能是 null，不可以直接用」。解法就是上表的 ?.、?? 或先用 if 檢查。

回傳 null 是一種「說清楚」的設計

算不出平均（清單是空的）時，回傳 null 比回傳 0 誠實：0 會讓畫面顯示「平均 0 度」，null 則讓你有機會顯示「無有效資料」。

小練習：算不出來就回 null

寫一個 double? averageOrNull(List<double> values)：清單是空的就回傳 null，否則回傳平均。呼叫兩次，一次給資料、一次給空清單，空清單時印出「沒有資料可以計算」。

5. 抽象類別與繼承：同一種東西的不同款式

溫度感測器和濕度感測器都是「感測器」：都有編號、都可以讀值、都要產生一行報表。把共同的部分寫在父類別，不一樣的部分交給子類別，就能把不同款式放進同一個清單一起處理。

延伸練習

先猜猜看會印出什麼，再點我看執行結果
執行結果
A1 溫度：27.4
B1 濕度：62.3%
A2 溫度：31.8
  • abstract class Sensor：抽象類別不能直接建立物件，它規定「子類別一定要有什麼」。
  • extends Sensor：繼承，把父類別的欄位和方法接過來。
  • @override：告訴讀程式的人和分析器「這個方法是覆寫父類別的」。
  • super.id：把收到的值交給父類別的建構式。super.report() 則是「先用父類別寫好的版本」。
  • List<Sensor>：因為兩種感測器都是 Sensor，可以放在同一個清單裡用同一個迴圈處理。

這就是 Flutter 元件的運作方式

之後寫的每一個畫面元件，都是繼承 Flutter 提供的類別再覆寫其中一個方法。今天的 extends 和 @override 就是那時候的基本功。

6. 綜合實作：用類別整理環境監測資料

把這個單元學到的東西用在一份報表上：Reading 是一筆讀值、Room 是一間教室；平均值可能算不出來，所以型別是 double?。

先猜猜看會印出什麼，再點我看執行結果
執行結果
電子 301：平均 28.2°C，失敗 1 筆
電子 302：無有效資料，失敗 2 筆
  • Room 只負責「自己這間教室」的事：算平均、數失敗筆數。呼叫的人不必知道細節。
  • averageCelsius 回傳 double?，所以印出來之前一定要先處理 null，這正是空值安全幫我們記住的事。
  • 資料換成別的教室、別的筆數，主程式完全不用改。

實作題（作業會用到）

  1. 把上一個單元自己寫的資料處理程式，改成「一個資料類別 ＋ 一個集合類別」。
  2. 集合類別至少要有一個回傳 ? 型別的 getter（例如算不出來時回傳 null）。
  3. 建構式一律改用具名參數，欄位盡量用 final。

7. 本單元重點整理

  • 類別是設計圖、物件是成品；欄位放資料、方法放動作、getter 用起來像欄位。
  • 建構式用具名參數 ＋ required最好讀，Flutter 幾乎都是這種寫法。
  • 具名建構式（Reading.failed）讓「特殊情況」有自己的名字；const 建構式的值在編譯時就固定。
  • 欄位能用 final 就用，建立之後不再變動的資料比較不容易出錯。
  • ? 代表「可能沒有值」；用 ?.、?? 或 if (x != null) 處理，不要硬用。
  • abstract 訂規格、extends 接功能、@override 換做法，不同款式就能一起處理。

9. 本單元作業：把資料處理改寫成類別

  1. 建立一個資料類別（例如 Student 或 Reading），欄位至少 3 個、全部用 final，建構式使用具名參數與 required。
  2. 建立一個集合類別（例如 ClassRoom），持有一個 List，並提供至少 2 個 getter，其中至少 1 個回傳可為 null 的型別，用來表示「算不出來」。
  3. 主程式建立至少 3 筆資料（含 1 筆無效資料），印出一份報表，並正確顯示「無有效資料」的情況。
  4. 執行 dart analyze，確認沒有任何警告後，連同執行結果截圖一起繳交。

繳交前自我檢查

  • 建構式看得出每個值是什麼嗎？（Reading(sensorId: 'A1', celsius: 27.5) 比 Reading('A1', 27.5) 好懂）
  • 有沒有哪個欄位其實不會變，卻沒有寫 final？
  • 把無效資料那筆刪掉再跑一次，「無有效資料」的那行還會正確出現嗎？
