#### [01:05] 第一節：條件判斷：讓程式自己做決定

我們先看第一節：「條件判斷」。
什麼叫條件判斷？就像你騎車出門，看到紅燈就停下來，看到綠燈就往前騎。

在 Dart 裡面，最基本的判斷是 `if` 跟 `else`。
小括號裡面放「條件」，大括號裡面放「條件成立時要做的事」。
如果條件有很多種可能，比如成績分九十分以上是 A、八十分以上是 B、七十是 C，一路排下來，就可以用 `else if` 連環接下去。
但請記住一個重要原則：電腦是「從上往下檢查」的！只要上面有一個條件被滿足了，它衝進去執行完就會直接跳過後面所有的分支。所以檢查成績時，一定要「從分數高的往下比」，千萬不要反過來寫，不然會全部變成不及格。

那如果遇到固定選項的選擇題呢？比如冷氣模式有送風、制冷、暖氣，這時候用 `switch` 語法會比寫一大堆 `if else` 乾淨十倍！
Dart 的 switch 支援傳統的 case 寫法，也支援現代的 switch expression「表達式寫法」：用箭頭符號直接對應結果，最後用一個萬用配對底線 `_` 當作「其他所有狀況」的保底備案，簡潔又俐落！

#### [03:00] 第二節：重複做：for 與 while 迴圈

來到第二節：「重複做：迴圈」。
如果你要電腦印出三次「歡迎」，你複製三行 print 也就算了；但如果感測器每秒傳來一筆資料、或者要把全校五百個人的出缺席都算過一遍，貼五百次手會斷掉。這時候就是「迴圈」登場的時刻！

講義介紹了兩種經典的迴圈工具：
第一種叫 `for` 迴圈。當你知道「明確要做幾次」的時候用它最適合。它有三部曲：起始值是 0、結束條件是小於幾次、每次做完自動加一。比如從 0 數到 4，一行搞定。
如果是要把一串清單從頭到尾走一遍，Dart 還有更優雅的 `for-in` 走訪寫法：「對清單裡的每一個元素，都抓出來做一次處理」，連數字都不用數了！

第二種叫 `while` 迴圈。當你「不知道具體要做幾次，只知道某個條件還成立時就一直做」的時候用它。比如倒數計時器，只要秒數大於零，就一直扣一並印出警報；或者等待感測器連線成功，沒連上就一直重試。

在這裡有兩個強大的迴圈控制按鈕：
一個叫 `break`，直接強制煞車跳出整個迴圈，再也不做了，比如找到了不及格名單立刻停手；
另一個叫 `continue`，是「略過這一次，直接進入下一輪」，比如檢查到異常壞掉的感測器讀值，先不要理它，直接去算下一個。

#### [04:50] 第三節：管理很多筆資料：List 清單

第三節是程式設計最常用的資料結構之一：「List 清單」。
想像你手上有一個長型藥盒，星期一到星期天，每一格裝一顆藥。清單就是「排成一整排、有順序的資料盒子」。

在 Dart 裡面，清單用中括號包起來，比如 `[24.5, 26.0, 28.2]`。
清單有三個不可侵犯的鐵則：
第一：它的型別是乾淨統一的。裝浮點數小數的清單，寫作 `List<double>`，不能亂塞文字。
第二：**清單的編號一定是從 0 開始算！** 第一個東西的位置是 0，第二個是 1。
如果你想拿最後一個東西，不要硬猜數字，直接問清單：`scores.last` 就好。
第三：千萬不能「越界」！如果清單只有三樣東西，最大的編號只有 2。你如果硬去拿第 5 號位置，程式會立刻在執行時崩潰亮紅字：`RangeError 索引越界`！

講義裡還介紹了常用的清單操作：用 `add` 加新資料、用 `length` 算長度、用 `reversed` 反轉順序，超級直覺。

#### [06:45] 第四節：用「名字」查資料：Map 對照表

第四節是另一個神器：「Map 對照表」，也有人叫它鍵值對（Key-Value pair）。
清單是用「0, 1, 2」數字編號去查資料；但如果我想用「學生學號」查成績，或者用「感測器名稱」查目前的溫度，用數字編號就很難記。這時候就要用 Map！

Map 用大括號包起來，每一筆資料都是「鍵冒號值」，比如 `'A01': 24.5`。
左邊的 Key 是鑰匙，是唯一的標籤；右邊的 Value 是對應的內容。
你可以把它想像成手機的電話簿：你輸入名字「小明」，它就幫你找到電話號碼。

查詢時，只要把名字放進中括號裡，像 `stock['紅茶']`。
但請注意：如果你輸入了一個菜單上根本沒有的飲料名字，比如「冬瓜檸檬」，Map 不會報錯崩潰，而是會回傳一個代表什麼都沒有的 `null`。
這時候我們就可以用上一週學到的雙問號 `?? 0`，意思是：「如果查不到，就當作庫存是 0 杯」，程式就不會當機！

#### [08:35] 第五節：把好用的程式包起來：函式

到了第五節，我們要學會軟體工程師最優雅的技巧：「函式 Function」。
把一段解決特定問題的程式碼包成一個有名字的積木。之後只要喊它的名字，給它材料，它就會幫你把做好的成品交出來。

定義函式的時候，請記住三要素：
第一，前面寫「回傳值的型別」，比如這個積木算完會交出一個整數 `int`，還是什麼都不交出的 `void`；
第二，函式的名字與小括號，裡面放「傳進去的材料（參數）」；
第三，大括號裡面的實作邏輯，最後用 `return` 指令把結果送回給呼叫的人。

講義裡特別提醒大家 Dart 最好用的特色：「具名參數 Named Parameters」。
如果函式要傳入很多數值，比如基準溫度、最高上限、最低下限，如果全用傳統位置傳遞，很容易手滑把上限跟下限填反。
用大括號把參數包起來，並加上 `required` 必填標籤，呼叫時就能像寫英文句子一樣清楚：`checkTemp(current: 28.5, maxLimit: 30.0)`，既好讀又永遠不會填錯！

#### [10:05] 第六節：資料管線：where、map、any、every

第六節我們把前面學的武器全部組裝在一起。
講義介紹了一套工程師必備的良好習慣：把好用的工具函式集中放在一個叫做 `data_tools.dart` 的檔案裡，這就叫做「函式庫」！主程式只要 import 引入，就能保持乾淨清爽。

處理資料時，講義傳授了四個超強的清單工具：
第一，`where`：篩選。比如把感測器壞掉讀到的負 999 雜訊過濾掉，或者把不及格的成績挑出來；
第二，`map`：轉換。把清單裡的每一個溫度數值，批次轉換成「太熱」或「舒適」的中文字標籤；
第三，`any`：只要清單裡有「至少一個」符合就回傳 true，比如「班上有沒有人考一百分？」；
第四，`every`：必須「全部」都符合才算數，比如「大家是不是都及格了？」。
學會這四招，處理幾百筆資料只要一行程式碼就搞定！

#### [11:15] 第七節：測試入門：讓電腦幫你檢查答案

第七節是本週的重頭戲：自動化測試。
很多人寫完程式，都是眼睛盯著螢幕自己算一遍、人眼對答案，不僅累得要死，而且一不小心就看漏了。
「測試」就是我們另外寫一支專門的檢查程式，給它題目，跟它說「算出來應該要是多少」，讓電腦用千分之一秒的速度幫你一題一題自動對答案！

在終端機建立一個叫 `data_lab` 的專案，把工具放在 `lib/`，主程式放在 `bin/`，而測試程式放在 `test/` 資料夾。
測試的核心就是兩個字：`expect 測試語法`，比對「實際算出來的值」跟「預期應該要是的值」。
比如 90 分理所當然應該要是等第 A。

在寫測試時，最關鍵的訣竅在於測「邊界值」！
最容易寫出 bug 的往往不是 80 分這種中間數值，而是「剛好壓線」的臨界點：比如剛好 90 分、剛好 89 分、剛好 60 分、或是空的清單。
打上指令 `dart test`，如果螢幕亮起綠燈 `All tests passed!`，那種整支程式完全被你掌握的踏實感，真的超級過癮！萬一有錯，測試會直接把 `Expected` 跟 `Actual` 攤開在螢幕上，秒殺所有隱藏 bug！

#### [12:30] 第八節：本週重點整理

第八節幫大家打包了本週的七大重點：
第一，條件判斷用 `if else` 和 switch 表達式，分支由上往下挑第一個滿足的做；
第二，計數迴圈用 for，集合遍歷用 for-in，條件等待用 while；
第三，迴圈煞車用 break，略過換下一輪用 continue；
第四，清單 List 索引從 0 開始，越界會拋 RangeError；
第五，對照表 Map 用鍵查值，查無回傳 null，可用雙問號保底；
第六，函式獨立封裝邏輯，具名參數搭配 required 既安全又好讀；
第七，資料管線用 where 篩選、map 轉換，最後用 `dart test` 和邊界值守護程式品質。
