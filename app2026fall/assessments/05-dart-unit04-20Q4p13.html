01 把「名字、分數」和「判斷及不及格」都放進同一個類別，最主要的好處是什麼？

  1. 拿到一個物件，就同時拿到它的資料和對這筆資料的動作
  2. 程式的總行數一定會變成原本的一半
  3. 從此之後完全不需要再使用任何變數
  4. 可以讓程式不必再寫任何 print

02 關於類別裡的「欄位」和「方法」，下列哪些描述正確？

  1. 欄位是類別裡的變數，代表這個物件有什麼資料
  2. 方法可以直接使用自己物件的欄位，不必再傳一次進來
  3. 一個類別的欄位必須全部宣告成 int 型別
  4. 方法一定要交回一個結果，不可以是 void

03 下面這段程式建立了兩個物件，畫面上會出現什麼？

class Box {
  String label;
  Box(this.label);
}

void main() {
  var m = Box('甲');
  var n = Box('甲');
  n.label = '乙';
  print(m.label);
}
  1. 乙
  2. 甲
  3. 甲乙
  4. null

04 關於建構式的各種寫法，下列哪些描述正確？

  1. 具名參數必須照著宣告時的順序寫，順序調換就會出錯
  2. 寫成 {this.x = 預設值} 的具名參數，呼叫時可以不給
  3. 具名建構式讓同一個類別的另一種建立方式有自己的名字
  4. const 建構式建立出來的值，在編譯時就固定下來

05 把建構式改成具名參數，並且盡量把欄位宣告成 final，可以得到哪些好處？

  1. 讀程式的人一看就知道每個值分別代表什麼
  2. 所有欄位在執行時會自動被清成 null
  3. 建立之後就不再變動的資料比較不容易出錯
  4. 呼叫的時候可以把所有參數名稱通通省略

06 下面這段程式用具名建構式建立一筆讀值，畫面上會出現什麼？

class Reading {
  final String sensorId;
  final double celsius;
  final bool isValid;

  const Reading({
    required this.sensorId,
    required this.celsius,
    this.isValid = true,
  });

  const Reading.failed(this.sensorId) : celsius = 0, isValid = false;

  @override
  String toString() => isValid ? '$sensorId：$celsius°C' : '$sensorId：讀取失敗';
}

void main() {
  print(Reading.failed('A3'));
}
  1. A3：0.0°C
  2. A3：讀取失敗
  3. A3：true
  4. null

07 關於 Dart 的空值安全，下列哪些描述正確？

  1. 型別後面沒有加 ? 的變數，永遠不會是 null
  2. 只要型別加上 ?，這個變數就再也不能存放一般的值
  3. 忘了處理沒有資料的情況，只能等程式跑到那一行才會知道
  4. 會是 null 的資料，型別要寫成 String?、double? 這種形式

08 想安全地使用一個可能是 null 的值，下列哪些做法可行？

  1. 用 ?. 安全呼叫，是 null 時整個算式就得到 null
  2. 用 ?? 補一個預設值，左邊是 null 時就改用右邊
  3. 不必理會，直接呼叫它的方法，Dart 會自動幫忙跳過
  4. 先用 if (值 != null) 檢查過，在裡面就能當成有值使用

09 一個算平均的函式把回傳型別寫成 double?，並在清單是空的時候回傳 null。這樣設計的用意是什麼？

  1. 這樣函式執行起來會比較快
  2. Dart 規定回傳 double 的函式都要加上 ?
  3. 「算不出來」和「平均是 0」是兩件事，null 才誠實
  4. 這樣呼叫的人就不必處理空清單的情況

10 一段程式宣告了 String? nickname;，接著直接寫 nickname.length，結果無法通過分析。關於這個情況，下列哪些說法正確？

  1. 這個問題要等程式執行到那一行才會被發現
  2. 分析器會指出這個值可能是 null，不可以就這樣直接存取屬性
  3. 在還沒執行前就被抓出來，正是空值安全帶來的好處
  4. 只要把 ? 拿掉就一定能解決，而且程式的意思完全不變

11 關於 abstract、extends 與 @override，下列哪些描述正確？

  1. abstract 類別不能直接拿來建立物件
  2. extends 會把父類別的欄位和方法接過來
  3. @override 表示這裡用自己的版本取代父類別的做法
  4. 子類別一旦繼承，就不能再多加自己的欄位

12 下面這段程式讓子類別覆寫 get label，畫面上會依序出現哪兩行？

abstract class Shape {
  final String id;

  Shape(this.id);

  String get label;

  String report() => '$id 是$label';
}

class Circle extends Shape {
  Circle(super.id);

  @override
  String get label => '圓形';
}

void main() {
  var s = Circle('S1');
  print(s.label);
  print(s.report());
}
  1. label
  2. 圓形
  3. S1 是 Shape
  4. S1 是圓形

13 關於子類別裡的 super，下列哪些描述正確？

  1. 寫成 TempSensor(super.id, this.celsius); 會把收到的編號交給父類別的建構式
  2. super 只能寫在 main 函式裡面，類別裡不能用
  3. super.report() 代表先使用父類別已經寫好的那個版本
  4. 覆寫之後仍然可以先用父類別的版本，再接上自己要加的內容

14 兩種不同款式的感測器都繼承自 Sensor，為什麼可以放進同一個 List<Sensor> 用一個迴圈處理？

  1. 因為它們都是 Sensor，共用同一套介面
  2. 因為它們的欄位名稱完全相同
  3. 因為清單可以同時放進任何互不相關的型別
  4. 因為它們都沒有覆寫過任何方法

15 一個教室類別把「算平均、數失敗筆數」都放在自己裡面，而且平均值的型別是 double?。關於這樣的設計，下列哪些說法正確？

  1. 呼叫的人必須自己先把無效的讀值挑掉才能用
  2. 因為平均值是 double?，所以它永遠不能被印出來
  3. 呼叫的人不必知道細節，只要問這間教室的平均和失敗筆數
  4. 印出平均之前，一定要先處理「算不出來」的情況

16 關於下列名詞的說明，哪些是正確的？

  1. 「實例（instance）」是指存放類別原始碼的那個檔案
  2. 「物件」是照著類別做出來的東西
  3. 「建構式」是建立物件時會執行的特殊方法
  4. 「getter」用起來像欄位，實際上是算出來的值

17 感測器讀取失敗的那筆資料會把 isValid 記成 false。執行下面的程式，畫面上會依序出現哪兩個數字？

class Sample {
  final double celsius;
  final bool isValid;

  const Sample(this.celsius, {this.isValid = true});
}

void main() {
  const list = [Sample(27.5), Sample(28.9), Sample(0, isValid: false)];
  print(list.where((s) => s.isValid).length);
  print(list.where((s) => !s.isValid).length);
}
  1. 2
  2. 1
  3. 0
  4. 3

18 把資料處理改寫成類別之後，作業要求在繳交前先執行哪一個指令，確認沒有任何警告？

  1. dart create
  2. dart run
  3. dart test
  4. dart analyze

19 這個單元的作業要求繳交的成果，應該包含下列哪些內容？

  1. 一個資料類別，欄位至少 3 個而且全部用 final
  2. 所有自己寫的類別都必須宣告成 abstract
  3. 一個集合類別，提供至少 2 個 getter，其中至少 1 個回傳可為 null 的型別
  4. 主程式至少建立 3 筆資料，其中要包含 1 筆無效資料

20 某個建構式宣告成 Ticket({required this.code, required this.price})，呼叫時卻只寫了 code。關於這個情況，下列哪些說法正確？

  1. 程式照常執行，price 會自動變成 0
  2. 程式照常執行，price 會自動變成 null
  3. 還沒執行之前，分析器就會指出少給了一定要給的參數
  4. 具名參數沒有順序，漏掉一個不會被順序抓出來，而是由分析器直接指出
