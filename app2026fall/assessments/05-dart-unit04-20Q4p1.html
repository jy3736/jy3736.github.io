01 用兩個平行的清單分別存放同一批人的名字和分數，最主要的麻煩是什麼？

  1. 清單裡不能存放文字資料
  2. 只要順序一錯，兩邊的資料就會配錯
  3. 一個清單最多只能放兩筆資料
  4. 清單建立之後就完全不能修改

02 「類別」和「物件」的關係，用哪一個說法最貼切？

  1. 類別是設計圖，物件是照著設計圖做出來的成品
  2. 物件是設計圖，類別是照著物件做出來的成品
  3. 兩者完全相同，只是中文和英文的差別
  4. 類別是程式的註解，物件是程式的資料

03 在類別裡寫 bool get isPassed => score >= 60;，這種成員叫什麼？用起來有什麼特色？

  1. 建構式，只有在建立物件的時候會執行一次
  2. 抽象方法，子類別一定要自己寫出內容
  3. getter，用起來像欄位，值卻是算出來的
  4. 具名參數，呼叫時一定要寫出它的名稱

04 下面這段程式建立了兩個物件，畫面上會出現什麼？

class Counter {
  int value;
  Counter(this.value);
}

void main() {
  var p = Counter(3);
  var q = Counter(3);
  q.value = 8;
  print(p.value);
}
  1. 8
  2. 11
  3. null
  4. 3

05 建構式寫成 Student(this.name, this.score);，其中的 this.name 代表什麼意思？

  1. 呼叫時一定要寫出 name 這個名稱才行
  2. 把收到的值直接放進自己的 name 欄位
  3. 先把 name 欄位設成 null，稍後再補上
  4. 宣告一個叫 name 的區域變數，和欄位無關

06 下面這段程式用具名參數建立物件，畫面上會出現什麼？

class Reading {
  final String sensorId;
  final double celsius;

  const Reading({required this.sensorId, required this.celsius});
}

void main() {
  var r = Reading(celsius: 31.2, sensorId: 'A2');
  print('${r.sensorId} ${r.celsius}');
}
  1. A2 31.2
  2. 31.2 A2
  3. 會出錯，因為兩個具名參數的順序和宣告時不一樣
  4. null null

07 建構式宣告成 Ticket({required this.code, required this.price})，呼叫時卻只給了 code，會發生什麼事？

  1. 程式照常執行，price 會自動變成 0
  2. 程式照常執行，price 會自動變成 null
  3. 還沒執行就會被分析器指出少給了一定要給的參數
  4. 程式跑到一半才中斷，並顯示找不到檔案

08 像 Reading.failed('A3') 這種「類別名稱後面再加一個名字」的建立方式叫什麼？用途是什麼？

  1. 抽象方法，用來規定子類別一定要實作
  2. 覆寫，用來取代父類別原本的做法
  3. getter，用來算出一個值並直接傳回去
  4. 具名建構式，為特殊的建立方式取一個好懂的名字

09 已知類別 Point 有一個 const 建構式。執行下面的程式，畫面上會出現什麼？

const p1 = Point(x: 2, y: 5);
const p2 = Point(x: 2, y: 5);
print(identical(p1, p2));
  1. true
  2. false
  3. null
  4. 會出錯，const 物件不能拿來比較

10 把類別的欄位宣告成 final，代表什麼？

  1. 這個欄位一定要是數字型別
  2. 這個欄位建立之後就不准再改
  3. 這個欄位的值一定是 null
  4. 這個欄位只有子類別可以使用

11 型別寫成 String? 和寫成 String，差別在哪裡？

  1. String? 保證一定有值，String 才可能是 null
  2. 兩者完全一樣，? 只是讓程式看起來比較清楚
  3. String? 代表可能是 null，String 保證不會是 null
  4. String? 只能存數字，String 只能存文字

12 下面這段程式在 Map 裡查一個沒有的鍵，畫面上會出現什麼？

var stock = {'紅茶': 20, '奶茶': 8};
int? coffee = stock['咖啡'];
print(coffee ?? 0);
  1. 0
  2. null
  3. 20
  4. 程式會中斷並顯示錯誤訊息

13 當一個變數的值是 null 時，變數?.length 這個算式會得到什麼？

  1. 0
  2. 一個空字串
  3. 程式會當掉，什麼都不會印出來
  4. null

14 下面的程式為什麼沒辦法通過分析器？

void main() {
  String? nickname;
  print(nickname.length);
}
  1. 因為 nickname 沒有寫出型別
  2. 因為 length 只能用在數字上
  3. 因為 print 一次只能印出一個字串
  4. 因為 nickname 可能是 null，不可以就這樣直接存取它的屬性

15 先寫 if (other != null) { ... } 再在大括號裡使用 other，這樣做的好處是什麼？

  1. 檢查過之後，在這段程式裡就可以把它當成一定有值來使用
  2. 可以讓原本是 null 的值自動變成 0
  3. 可以把這個變數的型別永久改成不可為 null
  4. 可以讓程式的執行速度變快一倍

16 清單是空的、算不出平均時，讓函式回傳 null 而不是回傳 0，主要的好處是什麼？

  1. null 佔用的記憶體比數字 0 少很多
  2. 回傳 0 會讓畫面顯示「平均 0 度」，null 才能誠實表示沒有資料
  3. Dart 規定回傳 double 的函式不可以回傳 0
  4. 回傳 null 可以讓程式自動跳過所有錯誤

17 把一個類別宣告成 abstract class Sensor，代表什麼？

  1. 這個類別裡面不可以有任何欄位
  2. 這個類別不能直接建立物件，它規定子類別一定要有什麼
  3. 這個類別的方法全部都不准被覆寫
  4. 這個類別只能放在 lib 這個資料夾裡

18 在子類別的方法前面加上 @override，是在告訴讀程式的人和分析器什麼？

  1. 這個方法是建立物件時會執行的建構式
  2. 這個方法整個程式裡只能被呼叫一次
  3. 這個方法是覆寫父類別的同名方法
  4. 這個方法不會交回任何結果

19 子類別的方法裡寫 super.report()，代表什麼？

  1. 重新呼叫自己這個方法一次
  2. 另外建立一個父類別的新物件
  3. 先使用父類別已經寫好的那個版本
  4. 把父類別的那個方法從此刪掉

20 溫度感測器和濕度感測器都繼承同一個父類別 Sensor，為什麼它們可以放進同一個清單、用同一個迴圈處理？

  1. 因為它們的欄位數量剛好一樣多
  2. 因為清單本來就可以同時放進任何不相關的型別
  3. 因為它們都沒有寫自己的建構式
  4. 因為它們都是 Sensor，共用同一套介面
