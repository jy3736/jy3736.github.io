# AI Agent 實作：從 Vibe Coding 到可重現的商管應用

## 課程定位

- **對象：** 商管學院大學生，不要求具備程式背景。
- **時數：** 四堂課；每堂課三小時，共十二小時。
- **課程結構：** 每堂課包含兩個九十分鐘模組以及額外作品展示及問題討論時間。
- **主要工具：** 認識並應用 AI Agent（Codex、Claude Code、GitHub Copilot 或 Antigravity 等工具）；實作時由教師依課堂環境指定主要工具。
- **核心目標：** 讓學生從「會和 AI 對話」，進一步做到「能和 AI Agent 一起完成、驗證、重現一個小型系統」。

整體學習路徑：

> AI 基礎與工具認識 → Vibe Coding 靜態網頁 → 建立可重複使用的 Skill → 完成前後端小型系統

本系列課程希望帶領商管學院非資訊背景學生突破技術門檻，從熟悉的商管問題開始，逐步探索 AI Agent、Vibe Coding 與未來專題實作。學生不必先成為工程師，而是學習如何界定需求、整理資料、與 AI 協作、測試成果並持續改進；最後把想法轉化為可操作的網頁工具、資料蒐集流程或小型系統。這些能力將成為未來課程專題、職場問題解決與跨領域合作的重要基礎。

## 第一堂：認識 AI、AI Agent 與 Vibe Coding

### 模組一：AI 是什麼？聊天機器人和 AI Agent 有何不同？（90 分鐘）

#### 學習重點

- 認識生成式 AI、聊天機器人與 AI Agent 的基本概念。
- 了解 AI Agent 可以協助處理的工作：讀取檔案、整理資料、修改程式、操作工具，以及執行多步驟任務。
- 從商管情境思考可應用的工作，例如行銷文案、活動規劃、顧客回饋整理、簡單資料分析與網頁小工具。
- 建立負責任使用 AI 的基本觀念。

#### 負責任使用 AI 的注意事項

- 不直接提供個資、公司機密或未公開資料。
- 檢查資料來源、數字、引用與結論。
- 不把 AI 輸出直接當成正確答案。
- 了解授權範圍與檔案存取權限。

#### 學生活動與產出

學生寫出一份簡短需求說明：**我要請 AI Agent 協助完成什麼商管任務？**

### 模組二：Vibe Coding、VS Code 與 AI Agent 實作環境（90 分鐘）

#### 學習重點

- 理解 Vibe Coding：用自然語言描述目標、限制與完成標準，持續測試並修正成果。
- 認識 VS Code 的基本用途：查看檔案、修改內容與管理專案資料夾。
- 建立第一個專案資料夾。
- 使用 AI Agent 製作簡單的個人介紹或活動宣傳網頁。
- 練習基本驗收：網頁能否開啟、文字是否正確、版面是否符合需求。

#### 學生產出

- 一個可在瀏覽器開啟的簡單靜態網頁。
- 一個結構清楚的專案資料夾。

## 第二堂：用 Vibe Coding 建立商管靜態網頁應用

建議全班使用共同主題：**校園活動行銷與營運小幫手**。學生也可依興趣改成商品推廣、顧客回饋、社團活動或小型商店行銷情境。

### 模組三：從商管需求到靜態網頁原型（90 分鐘）

#### 先釐清需求

- 目標使用者是誰？
- 想解決什麼問題？
- 網頁需要呈現哪些資訊？
- 成功的標準是什麼？

#### 實作內容

- 活動或產品介紹頁。
- 目標客群與行銷訊息。
- 簡單活動預算或促銷成本試算。
- KPI 儀表板示意，例如報名人數、預算、觸及率與轉換率。

#### 學生產出

第一版靜態商管網頁應用。

### 模組四：測試、修正與完成靜態應用（90 分鐘）

#### 學習活動

- 請 AI Agent 協助改善版面、文字與操作流程。
- 檢查手機版閱讀、按鈕、表格與計算結果。
- 練習把模糊需求改寫成可執行的指令。
- 同學互相試用，根據回饋修改作品。

#### 學生產出

完成版的「校園活動行銷與營運小幫手」靜態網頁。

## 第三堂：以 Skill 建立智慧網頁資料蒐集工具

本堂課聚焦於網頁應用：學生以 AI Agent 建立一個類似「智慧爬蟲」的資料蒐集工具，將公開網頁中的商管資訊整理成可用資料。課程不處理一般靜態網頁產生 Skill，而是專注於網頁資料蒐集、驗證與調適。

### 模組五：從商管問題設計智慧網頁資料蒐集任務（90 分鐘）

#### 學習重點

- 將商管問題轉成明確的資料蒐集任務，例如蒐集公開活動資訊、商品促銷資訊、競品價格或公開職缺資訊。
- 認識智慧爬蟲與固定爬蟲的差別：固定爬蟲依賴指定頁面結構；智慧爬蟲則先理解目標欄位、資料位置與驗收條件，再選擇適合的蒐集方式。
- 設計資料規格：來源網址、資料欄位、資料格式、更新時間與缺漏資料處理方式。
- 認識 Skill 的角色：它提供可重複執行的蒐集規格、限制與驗收流程。

#### 學生產出

一份「智慧網頁資料蒐集任務規格」，包含資料來源、目標欄位、輸出格式與驗收標準。

### 模組六：建立並測試可調適的智慧爬蟲 Skill（90 分鐘）

使用安全、受控制的模擬網站資料，讓學生體驗網頁資料在改版前後的差異，並建立可調適的智慧爬蟲 Skill。

#### 實作內容

- 請 AI Agent 從網頁擷取指定欄位，例如商品名稱、價格、活動日期與促銷內容。
- 將結果整理成 Markdown、CSV 或簡單商管報表。
- 將第一版頁面改成第二種版面，再請 Agent 依據 Skill 重新定位資料並調整蒐集方式。
- 比較固定選擇器式爬蟲與以目標、欄位和驗收規格為核心的智慧爬蟲 Skill。
- 將成功流程封裝為「智慧網頁資料蒐集 Skill」，並用另一個相近網頁進行測試。

#### 重要觀念

- Skill 可以幫助 AI Agent 根據目標調整做法，但不保證永遠正確。
- 網頁資料必須確認公開性、使用規範與合理使用範圍。
- 不繞過登入、付費牆或網站限制。
- 每次蒐集結果都需要人工驗證。

#### 學生產出

- 一個可整理公開資訊的智慧網頁資料蒐集 Skill。
- 一份經驗證的資料表或簡短報表。

## 第四堂：前後端小型系統與可分享的 Skill

### 模組七：建立基本可運作的前後端網頁伺服程式（90 分鐘）

本模組的核心不是完成某一種固定系統，而是運用 AI Agent 與 Vibe Coding，從需求出發完成一個具備前端操作介面、後端服務與簡易資料庫的基本可運作網頁程式。

建議以 **公司任務派工與人力排班系統** 作為共同雛形：例如某公司當天有五項任務，每項任務分別設定工作時段、所需人數與必要專長，例如電子工程、機械工程或業務支援。系統再根據可調度人員的可上班時段與專業技能，產生一份可供主管檢視的每日派工與排班建議表。

#### 系統功能

- **任務需求：** 建立當日五項任務；每項設定時段、所需人數與必要專長。
- **人才資料：** 記錄可調度人員的模擬姓名、可上班時段、專業技能與目前指派狀態。
- **前端與伺服端：** 在網頁輸入任務與人員資料；伺服端接收請求、檢查條件並回傳派工結果。
- **簡易資料庫：** 使用 JSON 或 SQLite 儲存任務、人員、技能條件與每日派工紀錄。
- **排班建議表：** 產生「任務－指派人員－符合專長－時段」列表，並標示人力或技能不足的任務。

系統先做到「專長符合、同一時段不重複指派、任務人數足夠」三項檢查即可；不必在課程中追求最佳化演算法。學生先透過 AI Agent 建出可執行樣本，再逐步測試、修正與擴充。課程僅使用虛構或去識別化人才資料，最終結果必須由人員主管確認。

#### 學生產出

可在本機執行的前後端小型系統。

### 模組八：把完整系統做成可重現的 Skill（90 分鐘）

#### 實作內容

- 整理系統需求、資料欄位、畫面功能與驗收方式。
- 撰寫「小型商管前後端系統建置 Skill」。
- 補上 README 操作說明。
- 讓另一組同學依照 Skill 嘗試重建，或改成另一種情境。

#### 可替換的情境

- 公司任務派工與人力排班系統。
- 活動報名系統。
- 顧客預約系統。
- 商品回饋管理系統。
- 社團值班排程系統。

#### 學生產出

- 一個可運作的前後端小型系統。
- 一個可分享、可重建系統的 Skill。
- 一份簡短操作與驗收說明。

## 最終成果與展示

每組學生完成：

1. 一個商管主題的靜態網頁應用。
2. 一個可處理公開網頁資訊整理的智慧網頁資料蒐集 Skill。
3. 一個具備使用者端與管理端的前後端小型系統。
4. 一個可讓其他人重建該系統的完整 Skill。

最後以五分鐘小組展示收尾：展示系統、說明 AI Agent 如何協作、分享遇到的一個問題，以及如何驗證成果是否可用。
