AI 基礎與 AI Agent 實作：完成一個最小可行的專業數位工具

10 月 14 日（星期三）｜13:20–17:00｜主要對象：視光系、醫技系學生

課程概要與設計意圖

三個 50 分鐘單元AI 基礎 → AI Agent → 最小 MVP無程式背景可參與視光與醫檢專業情境

這不是一門教 AI 工具蹭熱度的課，而是帶學生看見 AI 的演進、理解 AI Agent 能協助什麼，並親自用 AI Agent 做出一個真正能運作的最小數位工具。第一單元建立從辨別式 AI、生成式 AI、Chatbot、推理模型到 AI Agent 的基本脈絡；第二單元聚焦 AI Agent 與 Vibe Coding 的專案操作，練習建立、管理、加入與修改專案資源；第三單元則以視光或醫檢的簡單情境，完成一個可立即操作的專業數位工具。

當程式實作能由 AI Agent 協助時，人更需要說清楚想解決的問題、需要哪些資料、規則如何運作，以及結果是否合理。課程刻意不追求複雜功能，而是讓學生在有限時間內完成一次「從專業問題到可運作成果」的完整體驗；程式實作的門檻雖可由 AI Agent 降低，但專業知識、需求定義、規則說明、結果驗證與責任判斷，正是人最重要的角色。

三個單元的設計

每個單元只做一件清楚的事；前一個單元提供後一個單元所需的理解與操作基礎。

UNIT 01 · 13:20–14:10

從機器學習到 AI Agent：建立正確的 AI 脈絡

先以早期常見的辨別式人工智慧為起點，理解它擅長依既有資料辨識或分類；再進入生成式人工智慧，認識它如何生成文字、圖像或其他內容。

  • Chatbot：以對話方式回應、協助查詢與產生內容。
  • 推理模型：較適合處理需要多步分析、規劃或檢索的問題。
  • AI Agent：可在授權範圍內結合任務、上下文與工具，分步完成工作。

學生帶走的不是術語清單，而是判斷：面對一個問題時，哪一種 AI 使用方式較合適？又有哪些專業責任仍必須由人確認？

UNIT 02 · 14:20–15:10

AI Agent 與 Vibe Coding：把想法放進可管理的專案

課堂聚焦 AI Agent 的實際操作。視學生帳號與現場環境，可使用 Codex、Antigravity 或其他可用的 AI Agent 平台示範；重點是共同的專案工作方式，而不是綁定單一工具。

  • 建立專案，知道專案資料夾放在哪裡、如何再次開啟。
  • 新增、閱讀與修改檔案，並將額外的資料或素材加入專案。
  • 用清楚需求引導 AI Agent 產生或修改程式、文件、網頁內容與素材規劃。
  • 理解 Vibe Coding：由人說清楚目標、限制與驗收方式，讓 AI Agent 協助完成底層實作，再由人檢查與調整。
UNIT 03 · 15:20–16:10

最小 MVP 實作：專業知識變成可操作的數位工具

第三單元要印證一件事：即使還不熟悉程式，只要能把專業問題講清楚，仍可以透過 AI Agent 做出一個能運作的小工具。

  • 先選定一個單一、可驗證的任務；不追求功能很多。
  • 說明輸入資料、單位、規則與預期結果。
  • 請 AI Agent 建立頁面與邏輯，立即在瀏覽器預覽。
  • 以幾組虛構資料測試、修正，完成一個可展示的 MVP。

程式不再是唯一門檻；更關鍵的是專業情境的定義、規則的清楚度與成果的檢查能力。

第三單元的兩個專業 MVP 範例

每個案例都刻意控制在一堂課可完成的範圍：一個頁面、少量輸入欄位、一段清楚規則，以及立即可見的結果。

視光系

處方轉換器

輸入虛構的視光處方資料，依課堂設定的明確轉換規則，呈現轉換結果與輸入提醒。

  • 輸入：球面度數、柱面度數、軸度等虛構教學資料。
  • 輸出：依已定義規則顯示轉換結果。
  • 驗收：空白、非數字或不合理輸入時，能提供清楚提示。
醫檢系

稀釋換算器

輸入虛構的原液濃度、目標濃度與目標體積，計算所需原液與稀釋液的體積。

  • 輸入：原液濃度、目標濃度、目標體積與單位。
  • 輸出：依課堂公式顯示原液與稀釋液量。
  • 驗收：檢查空白、非數字、負值與不合理條件。
MVP

本課程的完成指標

學生在第三單元結束時，能展示一個最小但可運作的網頁工具：輸入少量虛構資料、按下按鈕、看見依規則產生的結果，並知道如何請 AI Agent 協助修改它。

完成比複雜更重要。學生藉此建立可延伸到未來專題的觀念：先用專業知識把問題定義好，再讓 AI Agent 協助把想法做成可測試的數位成果。

課前準備與課堂原則

學生需要準備

  • 筆記型電腦、電源與穩定網路。
  • 依主辦單位確認的 AI Agent 工具帳號；可事先登入並確認可用額度。
  • 以「想解決的專業小問題」而不是「想做很大的系統」作為出發點。

授課時的重要原則

  • 以工具差異為例，但以共通的專案概念與操作流程為主。
  • AI Agent 產生的內容必須由人檢查、測試與負責。
  • 不輸入真實個資、病歷、檢驗資料或其他敏感資料。
