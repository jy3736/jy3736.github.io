1. 認識 PWM：用開關的快慢調亮度

看一看板子怎麼做出「一半亮」？

UNO 的數位腳位只能輸出 5V 或 0V，並不是真的輸出「一半的電壓」。它的做法是：用非常快的速度讓腳位開、關、開、關，快到眼睛看不出在閃。開的時間比例越長，LED 看起來就越亮。這種方法叫做 PWM（脈波寬度調變）。

就像房間的電燈，如果每秒快速開關很多次，開著的時間佔一半，房間看起來就只有一半亮。

哪些腳位可以用 PWM？

只有部分腳位能輸出 PWM。在 UNO 板子上，這些腳位的數字旁邊印有 ~ 符號：

板子PWM 腳位
UNO R3（含更早版本）3、5、6、9、10、11
UNO R4（Minima、WiFi）3、5、6、9、10、11

analogWrite() 的用法

analogWrite(腳位, 亮度);   // 亮度：0 到 255
數值開的時間比例LED 狀態
00%，一直關全滅
64約 25%微亮
127約 50%大約一半亮
191約 75%較亮
255100%，一直開全亮

兩個容易搞混的地方

① analogWrite() 不需要先用 pinMode() 設定成輸出。

② analogWrite() 和 A0 到 A5 這些類比輸入腳位沒有關係，它用的是數位腳位中有 ~ 符號的那幾個。名字裡有 analog，只是因為效果看起來像類比。

動手做先看見五種亮度

先用最簡單的方式感受 analogWrite()：每種亮度停 1 秒。接線方式請看第 2 節的圖 1。

觀察時會發現：64 和 127 看起來的差距，比 191 和 255 的差距明顯。這是因為眼睛對暗處的亮度變化比較敏感，不是程式寫錯。

2. 範例 Fading：呼吸燈

動手做接線

  1. 第 9 號腳位接 220 歐姆電阻的一端。
  2. 電阻另一端接 LED 長腳（正極）。
  3. LED 短腳（負極）接 GND。

動手做程式

先認識 for 迴圈

如果不用迴圈，要從 0 亮到 255、每次加 5，就得寫 52 次 analogWrite()。for 迴圈用來「重複做一件事很多次」，括號裡有三個部分，用分號隔開：

for (起點; 繼續的條件; 每次怎麼變) {
  // 重複執行的程式
}

以 for (int fadeValue = 0; fadeValue <= 255; fadeValue += 5) 為例：

部分程式意思
起點int fadeValue = 0建立變數，從 0 開始
繼續的條件fadeValue <= 255只要還沒超過 255，就繼續
每次怎麼變fadeValue += 5每做完一次，加 5

執行順序是：起點 → 檢查條件 → 成立就做大括號裡的程式 → 變化 → 再檢查條件……直到條件不成立，才離開迴圈往下走。

第幾次fadeValuefadeValue <= 255做什麼
10成立亮度設 0，等 30 毫秒，加 5
25成立亮度設 5，等 30 毫秒，加 5
310成立亮度設 10，等 30 毫秒，加 5
…………
52255成立亮度設 255，等 30 毫秒，加 5
結束260不成立離開迴圈，開始執行「變暗」的迴圈

所以 fadeValue 會依序變成 0、5、10、15…一直到 255，共 52 個數值。變亮一次大約花 52 × 30 = 1560 毫秒，約 1.6 秒；再加上變暗，一次完整的「呼吸」大約 3 秒。

簡寫完整寫法意思
x += 5x = x + 5x 加 5 以後，再存回 x
x -= 5x = x - 5x 減 5 以後，再存回 x

第 7 週會更深入練習 for 迴圈。

改一改

  1. 把 delay(30) 改成 delay(5) 和 delay(80)，呼吸的速度有什麼改變？
  2. 把 += 5 改成 += 50，亮度變化變得平順還是一格一格？
  3. 把 LED 改接到第 8 號腳位（沒有 ~ 符號），程式也改成 8，還能慢慢變亮嗎？
看說明

第 1 題：delay(5) 時變亮一次只要約 0.26 秒，閃得很急；delay(80) 時約 4.2 秒，變成很慢的呼吸。

第 2 題：變成一格一格跳。變亮的迴圈只有 0、50、100、150、200、250 六個數值，下一個 300 超過 255 就停了，所以最亮只到 250。如果變暗的迴圈也改成 -= 50，數值是 255、205、155、105、55、5，下一個 -45 不符合 >= 0 就停了，所以最暗只到 5，不會完全熄滅。改變間隔時，要檢查頭尾兩個數值。

第 3 題：不能。第 8 號腳位不支援 PWM，LED 只會全亮或全滅，看不到漸變。

3. 範例 Analog In, Out Serial：旋鈕調光器

看一看兩個範圍對不上

可變電阻讀到的是 0 到 1023，但 analogWrite() 需要的是 0 到 255。兩個範圍不一樣，需要換算。

map() 就是用來換算範圍的工具。就像把 100 分制的考試成績換算成 5 分制：比例一樣，只是尺的刻度不同。

map(要換算的值, 原本最小值, 原本最大值, 新的最小值, 新的最大值)
讀值map(讀值, 0, 1023, 0, 255) 的結果
00
大約一半（511）大約一半（127）
1023255

map() 只算整數

map() 用整數計算，算出來的小數會直接捨去，不會四捨五入。例如 map(100, 0, 1023, 0, 255)，照比例算是 100 × 255 ÷ 1023 = 24.9…，結果卻是 24。下面的範例把幾種換算印出來：

程式結果說明
map(0, 0, 1023, 0, 255)0原本最小值對應新的最小值
map(511, 0, 1023, 0, 255)127511 × 255 ÷ 1023 = 127.3…，捨去小數
map(1023, 0, 1023, 0, 255)255原本最大值對應新的最大值
map(100, 0, 1023, 0, 255)2424.9… 捨去小數，不是四捨五入成 25
map(1023, 0, 1023, 255, 0)0新範圍寫成 255 到 0，大小就反過來
map(300, 0, 1023, 0, 100)29300 × 100 ÷ 1023 = 29.3…，換算成百分比

動手做接線

  1. 可變電阻一側接 5V，中間腳接 A0，另一側接 GND。
  2. 第 9 號腳位經 220 歐姆電阻接 LED 長腳，LED 短腳接 GND。

動手做程式

analogRead：讀旋鈕 0 到 1023→map：換算成 0 到 255→analogWrite：設定亮度→Serial：印出兩個數值
先猜猜看：旋鈕從一端轉到另一端，監控視窗會出現什麼？
序列埠監控視窗（只列出一小段）
讀值 = 0	亮度 = 0
讀值 = 204	亮度 = 50
讀值 = 511	亮度 = 127
讀值 = 818	亮度 = 203
讀值 = 1023	亮度 = 255

亮度永遠大約是讀值的四分之一，因為 1023 到 255 剛好縮小約 4 倍。"\t" 是跳格，讓兩欄對齊。

改一改

  1. 把 map() 的最後兩個數字對調成 255, 0，旋鈕和亮度的關係變成什麼？
  2. 把新範圍改成 0, 100，LED 最亮能到多亮？
  3. 挑戰：結合第 5 週的 if，當亮度超過 200 時，讓板上第 13 號腳位的 LED 也亮起來，提醒「太亮了」。
第 1、2 題：看說明

第 1 題：關係反過來。原本轉越多越亮，現在轉越多越暗。

第 2 題：最亮只到 analogWrite(9, 100)，大約是全亮的四成。map() 的新範圍決定了輸出的上限。

看參考解答

注意解答中第 13 號腳位用的是 digitalWrite()，所以要在 setup() 用 pinMode() 設定成輸出；第 9 號腳位用 analogWrite()，就不用。

4. 加碼範例：按鈕段數調光

把第 5 週的「狀態改變偵測」和這週的 analogWrite() 結合：每按一下按鈕，亮度往上一段，共 6 段，按到最亮後再按一下就回到全滅。按鈕使用兩線接法（第 2 號腳位與 GND，內建上拉電阻），LED 接法和第 2 節相同。

按第幾下0（剛上傳）1234567
level01234501
亮度 level × 51051102153204255051
  • level = (level + 1) % 6; 讓 level 在 0 到 5 之間循環：5 加 1 等於 6，6 除以 6 的餘數是 0，就回到開頭。
  • 為什麼乘以 51？因為 255 ÷ 5 = 51，最高的第 5 段剛好是 255。
  • 使用上拉接法，所以「剛按下」是從 HIGH 變成 LOW，lastButtonState 的起始值也要設成 HIGH。

5. 綜合練習

練習 1：旋鈕控制呼吸速度

保留呼吸燈的效果，但讓可變電阻決定呼吸的快慢：旋鈕轉越多，呼吸越慢。提示：用 map() 把讀值換算成每一步要等的毫秒數（例如 2 到 50），再把 delay(30) 裡的 30 換成這個變數。

看參考解答
看說明：為什麼轉動旋鈕後，速度沒有馬上改變？

解答在每一輪呼吸開始前才讀一次旋鈕。一輪呼吸要跑完兩個 for 迴圈，這段時間內不會重新讀旋鈕，所以要等目前這一輪結束，新的速度才會生效。

練習 2：反向調光器，顯示百分比

旋鈕轉越多 LED 越暗，並在監控視窗每 0.2 秒印出一行「亮度 75 %」。提示：可以用兩次 map()。

狀況可能原因解決方式
LED 只有亮或滅，沒有漸變接在不支援 PWM 的腳位改接有 ~ 符號的腳位：3、5、6、9、10、11
LED 完全不亮LED 正負腳接反長腳接電阻那一側，短腳接 GND
亮度數值超過 255忘了用 map() 換算讀值要先換算再給 analogWrite()

7. 自我檢核與重點回顧

自我檢核

  1. UNO 上哪些腳位可以做調光？怎麼從板子上認出來？
  2. analogWrite() 的數值範圍是多少？
  3. map(512, 0, 1023, 0, 255) 大約會得到多少？
  4. for 迴圈括號裡的三個部分分別代表什麼？
  5. for (int i = 0; i <= 20; i += 5) 裡，i 會依序是哪些數字？
看參考答案
  1. 3、5、6、9、10、11，腳位數字旁邊印有 ~ 符號。
  2. 0 到 255。0 是全滅，255 是全亮。
  3. 127。512 × 255 ÷ 1023 = 127.6…，map() 捨去小數。
  4. 起點、繼續的條件、每次怎麼變。
  5. 0、5、10、15、20，共 5 次。

本週重點回顧

  • PWM 用快速開關讓 LED 呈現不同亮度，UNO 的 PWM 腳位是 3、5、6、9、10、11。
  • analogWrite(腳位, 0 到 255) 設定亮度，不需要先設定 pinMode()。
  • for 迴圈可以讓數值依序變化，做出漸亮漸暗的效果。
  • map() 把數值從一個範圍換算到另一個範圍，結果是整數，小數會被捨去。
