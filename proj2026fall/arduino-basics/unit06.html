第 6 單元：用迴圈與陣列控制多顆 LED

如果要控制 6 顆 LED，照前幾個單元的寫法，同樣的指令就得重複寫 6 次，又長又容易出錯。這個單元用 for 迴圈把重複的工作交給程式，再用陣列把一群腳位編號收在一起。最後結合可變電阻，做出一條會跟著旋鈕變長變短的 LED 長條圖。

1. 範例 For Loop Iteration：來回跑馬燈

看一看用迴圈代替重複

不用迴圈時，設定 6 個腳位要寫 6 行：

pinMode(2, OUTPUT);
pinMode(3, OUTPUT);
pinMode(4, OUTPUT);
pinMode(5, OUTPUT);
pinMode(6, OUTPUT);
pinMode(7, OUTPUT);

用 for 迴圈只要 3 行，而且 LED 數量改變時，只需要改一個數字：

for (int thisPin = 2; thisPin < 8; thisPin++) {
  pinMode(thisPin, OUTPUT);
}

這三行的意思是：「thisPin 從 2 開始，只要小於 8 就執行一次 pinMode(thisPin, OUTPUT)，每次做完加 1」。thisPin 依序是 2、3、4、5、6、7，剛好 6 次，和上面 6 行的效果完全一樣。

簡寫完整寫法意思
thisPin++thisPin = thisPin + 1加 1
thisPin--thisPin = thisPin - 1減 1

動手做不接 LED，先用監控視窗看迴圈

把迴圈變數印出來，是檢查迴圈「從哪裡開始、到哪裡結束」最快的方法。這個範例只要接上 USB 線就能執行。

先猜猜看：三行分別印出什麼？
序列埠監控視窗
往前數：2 3 4 5 6 7
往回數：7 6 5 4 3 2
每次加 5：0 5 10 15 20
  • 往前數不包含 8，因為條件是 i < 8，8 不小於 8。
  • 往回數包含 2，因為條件是 i >= 2，2 大於或等於 2。
  • Serial.println() 括號裡什麼都不放，就只是換行。

算出迴圈會做幾次

寫成 for (int i = 起點; i < 終點; i++) 時，次數 = 終點 − 起點。例如 i = 2; i < 8 是 8 − 2 = 6 次。

動手做接線

6 顆 LED 分別接到第 2 到第 7 號腳位。每一顆的接法都相同：腳位接 220 歐姆電阻，電阻接 LED 長腳，LED 短腳接 GND。可以把所有 LED 的短腳都接到麵包板的同一條 GND 電源軌。

動手做程式

追蹤：LED 亮的順序

步驟123456789101112
哪個迴圈往前往回
亮的腳位234567765432

每一步亮 100 毫秒，一整輪 12 步約 1.2 秒。仔細看會發現：第 7 號在轉彎處連續亮兩步（往前的最後一步和往回的第一步），第 2 號也一樣（往回的最後一步和下一輪往前的第一步），所以兩端的 LED 看起來會亮比較久。

改一改

  1. 把 timer 改成 30 和 300，比較跑馬燈的速度。
  2. 刪掉「往回」那一段迴圈，效果變成什麼？
  3. 把迴圈裡的 digitalWrite(thisPin, LOW); 刪掉，LED 會怎麼變化？
看說明

第 1 題：30 時一整輪只要 0.36 秒，快到像光在流動；300 時一整輪 3.6 秒，可以清楚看到每一顆輪流亮。

第 2 題：LED 只會從第 2 號跑到第 7 號，然後又從第 2 號重新開始，變成一直往同一個方向跑。

第 3 題：第一輪往前時，LED 會一顆一顆亮起，而且亮了就不熄滅，最後 6 顆全亮，之後就一直全亮。因為程式裡已經沒有任何讓 LED 熄滅的指令。

2. 範例 Arrays：自訂順序的跑馬燈

看一看陣列是一排編號的盒子

第 1 節的迴圈只能處理「連續」的腳位（2、3、4…）。如果 LED 要照 2、7、4、6、5、3 這種跳來跳去的順序亮，就需要陣列。

第 3 單元說過，變數是一個貼了標籤的盒子。陣列則是一排連在一起的盒子，整排共用一個名字，每一格都有一個索引編號。要特別注意：索引從 0 開始算。

int ledPins[] = {2, 7, 4, 6, 5, 3};
[0]2
[1]7
[2]4
[3]6
[4]5
[5]3

ledPins[0] 是 2，ledPins[1] 是 7，最後一格是 ledPins[5]，值是 3。6 格的陣列，索引是 0 到 5。

寫法意思
int ledPins[] = {2, 7, 4};建立陣列：型態是 int，名字是 ledPins，大括號裡是每一格的值，用逗號隔開
ledPins[1]取出索引 1（第二格）的值
ledPins[1] = 9;把第二格的值換成 9

動手做把陣列印出來

for 迴圈的變數 i 從 0 數到 5，剛好可以當作索引，一格一格取出陣列的值。

先猜猜看：監控視窗會印出什麼？
序列埠監控視窗
ledPins[0] = 2
ledPins[1] = 7
ledPins[2] = 4
ledPins[3] = 6
ledPins[4] = 5
ledPins[5] = 3

動手做自訂順序的跑馬燈

接線和第 1 節相同，不用改。

注意迴圈變數 i 現在代表的是索引，真正的腳位要用 ledPins[i] 取出來：

i（索引）012345
ledPins[i]（亮的腳位）274653

往回的迴圈寫成 for (int i = pinCount - 1; i >= 0; i--)：起點是 6 − 1 = 5（最後一格的索引），一直減到 0。

改一改

  1. 把陣列改成 {2, 3, 4, 5, 6, 7}，效果是不是和第 1 節一樣？
  2. 自己排一個順序，例如「從兩側往中間亮」：{2, 7, 3, 6, 4, 5}。
  3. 想想看：如果把 i < pinCount 寫成 i <= pinCount，會多讀到哪一格？為什麼這樣會出問題？
看說明

第 1 題：一樣。陣列照 2 到 7 的順序排，就等於連續的腳位。

第 3 題：i 會多跑到 6，讀取 ledPins[6]。可是陣列只有索引 0 到 5，第 6 格根本不存在，讀到的是記憶體裡其他用途的資料，是一個不可預期的數字。程式會拿這個奇怪的數字當腳位去 digitalWrite()，可能影響到其他腳位。更麻煩的是，編譯器不會幫你檢查索引有沒有超過範圍，上傳時不會出現錯誤訊息。

3. 範例 LED Bar Graph：旋鈕長條圖

看一看用 map 決定亮幾顆

長條圖的想法是：旋鈕轉越多，亮起來的 LED 越多。

  1. 用 analogRead() 讀取旋鈕，得到 0 到 1023。
  2. 用 map() 換算成 0 到 10，代表「要亮幾顆」，存在 ledLevel。
  3. 用 for 迴圈檢查每一顆 LED：索引比 ledLevel 小的就亮，其餘的滅。

動手做接線

  1. 10 顆 LED 分別接到第 2 到第 11 號腳位，每顆都串聯 220 歐姆電阻，LED 短腳接 GND。
  2. 可變電阻兩側接 5V 與 GND，中間腳接 A0。

動手做程式

追蹤：ledLevel 是 4 的時候

i0123456789
ledPins[i]234567891011
i < 4成立成立成立成立不成立不成立不成立不成立不成立不成立
LED亮亮亮亮滅滅滅滅滅滅

索引 0 到 3 共 4 顆亮起，剛好等於 ledLevel。

讀值和亮幾顆的關係

讀值map(讀值, 0, 1023, 0, 10)亮幾顆
0 到 1020全滅
5114（4.99… 捨去小數）4 顆
51255 顆
92199 顆
10231010 顆全亮

為什麼很難讓 10 顆全亮？

因為 map() 捨去小數，讀值要剛好是 1023，ledLevel 才會是 10。讀值 1022 算出來是 9.99…，捨去後還是 9。所以旋鈕要轉到底，第 10 顆才會亮。

改一改

  1. 把陣列的順序反過來寫，長條圖會從哪一端開始亮？
  2. 加入 Serial.println(ledLevel);（別忘了在 setup() 加 Serial.begin(9600);），確認旋鈕轉到底時 ledLevel 是多少。
  3. 挑戰：改成只亮「最高的那一顆」，做成一個會移動的光點。（提示：把 i < ledLevel 改成比較是否相等。）
第 1、2 題：看說明

第 1 題：陣列寫成 {11, 10, 9, 8, 7, 6, 5, 4, 3, 2} 後，索引 0 變成第 11 號腳位，長條圖會從第 11 號那一端開始亮。接線完全不用改，只改陣列就能改變方向，這就是陣列好用的地方。

第 2 題：轉到底是 10，轉到另一端是 0。

第 3 題的想法：長條圖亮到索引 ledLevel - 1 為止，所以「最高的那一顆」就是 i == ledLevel - 1 那一顆。ledLevel 是 0 時，ledLevel - 1 是 -1，沒有任何 i 會等於 -1，所以全滅，和長條圖一樣。

4. 加碼範例：進度條燈號

LED 一顆一顆亮起、亮了就不關，全亮後停一下，再從最後一顆開始一顆一顆熄滅，像電腦的進度條。接線和第 2 節相同。

和跑馬燈比較：跑馬燈在同一輪迴圈裡「亮了又關」；進度條則是用第一個迴圈只負責開、第二個迴圈只負責關。

5. 綜合練習

練習 1：旋鈕控制跑馬燈速度

6 顆 LED 接第 2 到第 7 號腳位，可變電阻中間腳接 A0。讓跑馬燈往前跑，旋鈕轉越多跑得越慢，每一顆亮 30 到 300 毫秒。提示：把 delay() 的數值換成 map() 算出來的變數。

看參考解答

練習 2：全部閃 3 次，再跑一趟

讓 6 顆 LED 一起亮 0.3 秒、滅 0.3 秒，重複 3 次；接著跑馬燈跑一趟；然後一直重複。提示：「一起亮」也要用迴圈把每一顆都打開；「重複 3 次」可以在外面再包一層 for 迴圈。

看參考解答
看說明：迴圈裡面再放迴圈

解答裡外層迴圈的變數叫 times，負責數「第幾次閃」；內層迴圈的變數叫 i，負責「一顆一顆開或關」。外層每跑 1 次，內層就完整跑完 6 次。兩層迴圈的變數要用不同的名字，才不會互相干擾。

6. 常見錯誤

狀況可能原因解決方式
最後一顆 LED 不亮迴圈條件少算一格，例如 thisPin < 7檢查起點與結束條件
出現奇怪的腳位行為陣列索引超過範圍，例如讀了 ledPins[6]6 格的陣列，索引只到 5
其中一顆 LED 永遠不亮那顆 LED 正負腳接反，或電阻沒插好單獨測試那一顆的接線
往回數的迴圈沒有執行往回數時用了 ++ 或 <往回數要用 -- 與 >=
加了 LED 卻沒反應陣列多寫了腳位，但 pinCount 沒有跟著改陣列的格數和 pinCount 要一致
第 0、1 號腳位的 LED 怪怪的，上傳也失敗第 0、1 號腳位是 USB 序列通訊使用的腳位LED 從第 2 號腳位開始接

7. 自我檢核與重點回顧

自我檢核

  1. for (int i = 0; i < 6; i++) 會重複幾次？i 依序是哪些數字？
  2. 陣列 {2, 7, 4} 中，ledPins[1] 是多少？
  3. 為什麼陣列的最後一格索引是「數量減 1」？
  4. 長條圖程式中，map() 的最後一個參數為什麼是 ledCount？
  5. for (int i = 5; i >= 0; i--) 的 i 依序是哪些數字？
看參考答案
  1. 6 次，i 依序是 0、1、2、3、4、5。
  2. 7。索引 0 是 2，索引 1 是 7。
  3. 因為索引從 0 開始算。6 格的陣列，索引是 0 到 5。
  4. map() 要把讀值換算成「亮幾顆」，最多就是 LED 的總數 ledCount。
  5. 5、4、3、2、1、0。

本單元重點回顧

  • for 迴圈讓重複的工作只需寫一次，++ 加 1，-- 減 1。
  • 陣列把一群資料排在一起，用索引存取，索引從 0 開始；編譯器不會檢查索引是否超過範圍。
  • 陣列可以存放不連續的腳位，自由決定點亮順序。
  • analogRead()、map()、for 與 if 組合起來，就能做出長條圖。
