1. 認識 if 判斷

生活中充滿「如果……就……，不然就……」：如果下雨就帶傘，不然就戴帽子。程式用 if 和 else 來表達這種想法。

看一看三種寫法

寫法一：只有 if，條件成立才做，不成立就跳過。

if (條件) {
  // 條件成立時要做的事
}

寫法二：if ... else，二選一，一定會做其中一段。

if (條件) {
  // 條件成立時要做的事
} else {
  // 條件不成立時要做的事
}

寫法三：if ... else if ... else，多選一，由上往下檢查，遇到第一個成立的就做那一段，其他的都跳過。

if (條件一) {
  // 條件一成立
} else if (條件二) {
  // 條件一不成立，但條件二成立
} else {
  // 上面的條件都不成立
}

看一看比較運算子

條件通常是「比大小」或「比是否相等」。比較的結果只有兩種：成立或不成立。

寫法意思例子（假設 x 是 500）結果
x > 400大於500 大於 400成立
x < 400小於500 小於 400不成立
x >= 500大於或等於500 大於或等於 500成立
x <= 499小於或等於500 小於或等於 499不成立
x == 500等於500 等於 500成立
x != 500不等於500 不等於 500不成立

怎麼記 >= 和 <=

照著唸的順序寫：「大於或等於」就是 > 在前、= 在後。寫成 => 會出錯。符號中間也不能有空格。

最容易犯的錯：= 與 ==

寫法意思
x = 5把 5 放進 x 裡面
x == 5檢查 x 是不是等於 5

在 if 的括號裡，比較是否相等一定要寫兩個等號 ==。如果寫成一個等號，程式還是能上傳，但意思完全變了：

if (buttonState = HIGH) {   // 錯：把 HIGH 放進 buttonState
  digitalWrite(13, HIGH);   // 結果：不管按鈕有沒有按，這裡永遠會執行
}

這種錯誤不會出現紅字，只會讓程式行為怪怪的，所以更要小心。

2. 範例 If Statement：旋鈕超過門檻就亮燈

看一看什麼是門檻值

門檻值就是一條分界線。例如設定門檻為 400：讀值超過 400 時 LED 亮，沒超過時 LED 滅。生活中「室溫超過 28 度就開冷氣」就是同樣的想法。門檻值把連續變化的讀值，分成「超過」與「沒超過」兩種情況。

動手做接線

和第 3 單元相同。可變電阻兩側接 5V 與 GND，中間腳接 A0。LED 使用板上第 13 號腳位的內建 LED。

動手做程式

  1. 上傳程式，打開序列埠監控視窗。
  2. 慢慢轉動旋鈕，找出 LED 剛好亮起時的讀值，是不是在 400 附近？

用幾個讀值追蹤判斷結果

判斷時最要注意的是「剛好等於門檻」的情況：

讀值 analogValueanalogValue > 400執行哪一段LED
250不成立else滅
400不成立（400 沒有大於 400）else滅
401成立if亮
900成立if亮

如果希望 400 也要亮，就把條件改成 analogValue >= 400。

為什麼門檻值要放在變數 threshold 裡？

門檻值常常需要反覆調整。放在程式最上面的變數裡，想改的時候一眼就找得到，不用在程式中間到處找數字。

改一改

  1. 把 threshold 改成 800，要轉到哪裡 LED 才會亮？
  2. 把 > 改成 <，LED 的反應有什麼不同？
  3. 挑戰：用 if ... else if ... else 做出三段反應。讀值小於 300 時 LED 熄滅；介於 300 到 700 之間時 LED 慢慢閃爍；大於 700 時 LED 恆亮。
第 1、2 題：看說明

第 1 題：要轉得更多，讀值超過 800（大約轉到八成的位置）LED 才會亮。

第 2 題：反應完全相反，讀值小於 400 時亮，轉超過 400 反而熄滅。

第 3 題的想法：由上往下檢查。第一個條件處理「小於 300」；能走到 else if，代表讀值一定不小於 300，所以第二個條件只要再檢查「是否不超過 700」；剩下的就是大於 700。

常見錯誤：判斷的順序寫反

電腦會從上往下檢查，第一個成立的條件執行完就結束，後面的都不看。如果寫成 if (value > 300) 在前、else if (value > 700) 在後，讀值 900 會先符合「大於 300」，永遠走不到「大於 700」那一段。範圍判斷要依大小順序排，從最大（或最小）的範圍寫起。

3. 範例 State Change Detection：數一數按了幾次

看一看「按住」和「剛按下」不一樣

loop() 每秒會重複執行非常多次。如果只檢查「按鈕是不是 HIGH」，按住按鈕一秒鐘，程式可能會把它算成好幾百次。

要正確計算次數，應該抓「狀態改變的那一刻」：上一次讀到 LOW、這一次讀到 HIGH，才代表「剛按下」。做法是用一個變數記住上一次的狀態，每次都拿來和現在比較。

上一次狀態這一次狀態代表什麼
LOWHIGH剛按下，次數加 1
HIGHHIGH按住不放，不計次
HIGHLOW剛放開，不計次
LOWLOW沒有按，不計次

和第 2 單元第 2 節相同。第 2 號腳位接按鈕，同一隻腳經 10k 歐姆電阻接 GND，按鈕另一隻腳接 5V。

符號意思例子

buttonPushCounter % 4 == 0 的意思是「次數除以 4 沒有餘數」，也就是次數是 0、4、8、12…的時候。

次數012345678

注意第一格：次數是 0 時，0 % 4 也是 0，所以一上傳完、還沒按，LED 就是亮的。按第 1 下熄滅，按到第 4 下再亮起來。

一輪一輪追蹤

下表是「按一下、按住、放開、再按一下」時，每一輪 loop() 裡變數的變化：

第幾輪buttonState（這一次）lastButtonState（上一次）狀態改變了嗎？變成 HIGH 嗎？buttonPushCounter

每一輪最後的 lastButtonState = buttonState;，會把「這一次」存成下一輪的「上一次」。這一行是整個範例的關鍵。

先猜猜看：按 5 下，監控視窗會出現什麼？
序列埠監控視窗
按下次數：1
按下次數：2
按下次數：3
按下次數：4
按下次數：5

每按一下只印一行，按住不放不會多印。LED 在第 4 下時亮起，第 5 下又熄滅。

計數變數為什麼寫在 loop() 外面？

寫在 loop() 外面的變數，整個程式執行期間都存在，數值會一直保留。如果把 int buttonPushCounter = 0; 寫在 loop() 裡面，每一輪 loop() 開始時都會重新建立並歸零，次數永遠加不上去。

什麼是按鈕抖動？

按鈕內部是金屬片接觸。按下的一瞬間，金屬片會快速彈跳幾次，讀值在極短時間內「HIGH、LOW、HIGH」來回跳，程式可能把一次按下算成好幾次。狀態改變後 delay(50) 等 50 毫秒，就能跳過這段彈跳時間。

改一改

  1. 改成每按滿 3 次 LED 才亮。
  2. 把 delay(50) 刪掉，快速按按鈕，次數會不會多算？
  3. 挑戰：做一個「按一下亮、再按一下滅」的開關。（提示：次數是奇數時亮，偶數時滅，可以用 % 2 判斷。）
第 1、2 題：看說明

第 1 題：把 buttonPushCounter % 4 == 0 改成 buttonPushCounter % 3 == 0。

第 2 題：有可能。按一下時監控視窗偶爾會一次跳好幾個數字，這就是按鈕抖動造成的。抖動的情況每顆按鈕不一樣，有些按鈕比較不明顯。

4. 加碼範例：旋鈕等級顯示

判斷的結果不一定要控制 LED，也可以決定要印出什麼文字。這個範例把讀值分成三級，在監控視窗印出「低」「中」「高」。接線和第 2 節相同。

先猜猜看：讀值分別是 150、300、301、700、701 時，會印出什麼？
序列埠監控視窗
150 → 低
300 → 低
301 → 中
700 → 中
701 → 高

300 不大於 300，所以是「低」；700 不大於 700，所以是「中」。剛好等於門檻的數字，最容易判斷錯，寫完程式要特別拿來檢查。

5. 綜合練習

練習 1：按滿 5 次就完成

以 State Change Detection 為基礎：每按一下印出次數；按到第 5 次時，額外印出一行「完成！」；按滿 5 次之後，LED 一直亮著。提示：「印出完成」要用 ==，「LED 一直亮」要用 >=，想想看為什麼。

看參考解答
看說明：為什麼一個用 ==、一個用 >=？

「完成！」只想印一次，所以只在次數剛好等於 5 的那一下印；如果用 >=，第 6、7 下也會再印。LED 則是 5 次以後都要亮，所以用大於或等於。

練習 2：按鈕加旋鈕，兩個條件都要成立

同時接上按鈕（第 2 號腳位，下拉電阻接法）與可變電阻（A0）。只有「按住按鈕」而且「旋鈕讀值大於 500」時，LED 才亮。提示：可以在一個 if 裡面再放一個 if。

看參考解答

6. 常見錯誤

狀況可能原因解決方式
條件好像永遠成立在 if 裡寫成 =，而不是 ==比較相等要寫 ==
按一次卻算好幾次沒有做狀態改變偵測，或按鈕抖動比較上一次狀態，並加入短暫延遲
else 出現錯誤else 前面的 } 少了或多了檢查大括號是否成對
次數沒有累加把 int buttonPushCounter = 0; 寫在 loop() 裡面計數變數要寫在 loop() 外面，才不會每輪歸零
某一段 else if 永遠不會執行條件的順序排錯，前面的條件把範圍先吃掉了依大小順序重新排列條件
if 後面加了分號，條件沒作用寫成 if (x > 400);if (...) 後面直接接 {，不要加分號

保持縮排，大括號才不會對錯

大括號裡的程式往右縮兩格。在 Arduino IDE 按 Ctrl + T（Mac 用 Cmd + T）可以自動整理縮排。整理完如果縮排怪怪的，通常就是大括號少了或多了。

7. 自我檢核與重點回顧

自我檢核

  1. if ... else 和只有 if 的差別是什麼？
  2. x = 5 和 x == 5 有什麼不同？
  3. 為什麼計算按鈕次數時，要記住「上一次的狀態」？
  4. 10 % 4 的結果是多少？
  5. 門檻是 400、條件寫 value > 400 時，讀值剛好 400 會不會亮？
看參考答案
  1. 只有 if 時，條件不成立就什麼都不做；if ... else 一定會做其中一段。
  2. x = 5 是把 5 放進 x；x == 5 是檢查 x 是否等於 5。
  3. loop() 重複得非常快，按住按鈕會連續讀到很多次 HIGH。只有和上一次比較，才能抓到「從 LOW 變 HIGH」那一刻，一次按下只算一次。
  4. 2（10 除以 4 等於 2 餘 2）。
  5. 不會。400 沒有大於 400，要寫 value >= 400 才會亮。

本單元重點回顧

  • if 讓程式在條件成立時才執行某段程式；else 處理條件不成立的情況；else if 做多選一。
  • 比較運算子有 >、<、>=、<=、==、!=。
  • 門檻值可以把連續的讀值分成「超過」與「沒超過」兩種情況；要注意剛好等於門檻的情況。
  • 偵測狀態改變，才能正確計算按鈕按下的次數。% 取餘數，可以判斷倍數與奇偶。
