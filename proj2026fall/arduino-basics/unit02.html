第 2 單元：按鈕與序列埠監控視窗

上一單元板子負責「輸出」，這個單元換成「輸入」：讓板子讀取按鈕有沒有被按下。為了看見板子讀到了什麼，我們會使用 Arduino IDE 的序列埠監控視窗，把板子內部的數值顯示在電腦螢幕上。以後不論程式出了什麼問題，這個視窗都是你最好用的檢查工具。

1. 暖身：輸出與輸入

上一單元學到的 digitalWrite() 是「板子把訊號送出去」。這個單元的 digitalRead() 方向相反，是「板子把外面的訊號讀進來」。

方向訊號怎麼走腳位設定指令例子
輸出板子 → 元件pinMode(腳位, OUTPUT)digitalWrite()點亮 LED
輸入元件 → 板子pinMode(腳位, INPUT)digitalRead()讀取按鈕

數位腳位讀到的結果只有兩種：

讀值監控視窗顯示代表
HIGH1腳位上有電壓（接近 5V）
LOW0腳位上沒有電壓（接近 GND）

2. 範例 Digital Read Serial：看見按鈕的狀態

看一看按鈕的構造

按鈕按下時，會把兩隻腳接通；放開時，兩隻腳斷開。常見的按鈕有四隻腳，其實是兩兩一組、本來就相通，按下按鈕才讓兩組接在一起。所以按鈕要跨在麵包板中間的溝槽上插，而且方向要對：如果按了沒反應，把按鈕轉 90 度再插一次。

看一看什麼是「浮接」？為什麼要加電阻？

如果輸入腳位什麼都沒接，它就像一根懸空的天線，手靠近、旁邊的電線都會影響它，讀到的值會亂跳，一下 HIGH 一下 LOW。這種狀態叫做浮接。

為了讓讀值穩定，我們在腳位和 GND 之間接一顆 10k 歐姆電阻，稱為下拉電阻：

  • 按鈕沒按：腳位透過電阻被「拉」到 GND，穩定讀到 LOW。
  • 按鈕按下：腳位直接接通 5V，讀到 HIGH。電阻的阻值很大，只有一點點電流會經過它流到 GND，不會短路。

動手做接線

  1. 用紅線把 UNO 的 5V 接到麵包板側邊的一排，用黑線把 GND 接到另一排。
  2. 第 2 號數位腳位接到按鈕的一隻腳。
  3. 按鈕的同一隻腳，再經過 10k 歐姆電阻接到 GND。
  4. 按鈕的另一隻腳接到 5V。

動手做程式

  1. 上傳程式。
  2. 點選 Arduino IDE 右上角的放大鏡圖示，打開序列埠監控視窗。
  3. 確認視窗右下角的速度設定為 9600。
  4. 按住按鈕、再放開，觀察畫面上的數字變化。
先猜猜看：按住按鈕再放開，監控視窗會出現什麼？
序列埠監控視窗（每 10 毫秒新增一行，這裡只列出一小段）

沒按時一直印 0（LOW），按住的那段時間印 1（HIGH），放開後又回到 0。因為每 10 毫秒就印一行，畫面會快速往上捲。

逐行說明

指令作用
int buttonPin = 2;建立一個叫 buttonPin 的整數變數，存放腳位編號 2
Serial.begin(9600)開始和電腦通訊，速度要和監控視窗的設定一致
pinMode(腳位, INPUT)把腳位設定成輸入
digitalRead(腳位)讀取腳位的狀態，結果是 HIGH（顯示 1）或 LOW（顯示 0）
Serial.println(值)把值以文字送到電腦，並且換到下一行

為什麼要寫 int buttonPin = 2;，不直接寫 2？

用一個有意義的名字代表腳位，程式讀起來就像句子：digitalRead(buttonPin) 一看就知道在讀按鈕。而且如果按鈕改接到第 4 號腳位，只要改最上面那一行，下面所有用到 buttonPin 的地方都會跟著改。變數下一單元會再詳細說明。

int buttonState = digitalRead(buttonPin); 由右往左讀

先執行等號右邊的 digitalRead(buttonPin)，得到 0 或 1；再把這個結果放進等號左邊的 buttonState。之後要用讀值，就直接用 buttonState。

改一改動手修改，觀察變化

  1. 把 Serial.println(buttonState); 改成 Serial.print(buttonState);，畫面有什麼不同？
  2. 暫時拔掉接在第 2 號腳位的線，觀察讀值會不會亂跳。這就是「浮接」。
  3. 把監控視窗的速度改成 115200，畫面出現什麼？再改回 9600。
看說明

第 1 題：print 印完不換行，所有數字會擠在同一行，變成一長串：

序列埠監控視窗
000000011111110000000011111...

第 2 題：讀值會亂跳，甚至手靠近腳位時數字也會改變。這證明輸入腳位不能什麼都不接。

第 3 題：畫面出現看不懂的亂碼。板子用 9600 的速度送資料，電腦卻用 115200 的速度收，雙方對不上。程式裡 Serial.begin() 的數字，和監控視窗右下角的設定必須一樣。

3. 範例 Button：用按鈕控制 LED

看一看把輸入和輸出接起來

第 2 節是「讀到就印出來」。這一節改成「讀到就決定 LED 亮或滅」，接線和第 2 節相同，只是改用板上第 13 號腳位的 LED 顯示結果。

讀取按鈕→判斷：是 HIGH 嗎？→是：LED 亮／否：LED 滅→回到開頭再讀一次

動手做

這裡先偷看一下 if ... else：它的意思是「如果條件成立就做第一段，否則做第二段」。兩段一定只會做其中一段。第 4 單元會仔細學它。

寫法意思
if (buttonState == HIGH)如果 buttonState 等於 HIGH（按鈕被按下）
==兩個等號是「比較是否相等」，和一個等號「把值放進變數」不一樣
else否則（條件不成立的時候）

因為 loop() 一秒鐘會重複非常多次，板子隨時都在重新讀按鈕，所以你一按下，LED 幾乎立刻就亮。

改一改反過來

改成「按住時 LED 滅，放開時 LED 亮」。只需要改哪兩個字？

4. 範例 Input Pullup Serial：少一顆電阻的接法

看一看內建上拉電阻

UNO 的腳位內部有一顆上拉電阻。用 pinMode(腳位, INPUT_PULLUP) 就能啟用它，這樣就不必再外接 10k 歐姆電阻。

上拉電阻和下拉電阻剛好相反：它把沒按時的腳位「拉」到 5V。按鈕的另一隻腳接 GND，按下時腳位就被接到 GND。所以讀值會和第 2 節相反：

按鈕狀態腳位連到哪裡讀值
沒按經內建上拉電阻連到 5VHIGH（1）
按下直接連到 GNDLOW（0）

動手做接線：只要兩條線

  1. 第 2 號腳位接到按鈕的一隻腳。
  2. 按鈕的另一隻腳接到 GND。

動手做程式

注意 if 裡面的邏輯也反過來了：讀到 HIGH 代表沒按，所以讓 LED 滅；讀到 LOW 代表按下，讓 LED 亮。

改一改

按下按鈕時，監控視窗顯示 0 還是 1？和第 2 節比較看看。

看說明

顯示 0。第 2 節用下拉電阻，按下是 1；這一節用內建上拉電阻，按下是 0。按鈕按下讀到什麼，要看電阻接在哪一邊，不是固定的。

兩種接法比一比

比較項目下拉電阻（第 2 節）內建上拉電阻（第 4 節）
腳位設定INPUTINPUT_PULLUP
需要外接電阻要，10k 歐姆接 GND不用
按鈕另一隻腳接5VGND
按下時讀值HIGH（1）LOW（0）
沒按時讀值LOW（0）HIGH（1）

5. 加碼範例

範例 A：用文字顯示按鈕狀態

監控視窗只印 0 和 1，有時候不容易看懂。Serial.print() 除了印數字，也可以印雙引號包起來的文字。把 print（不換行）和 println（換行）搭配起來，就能在同一行組合出一句話。這個範例使用第 4 節的兩線接法。

先猜猜看：按住按鈕約 1 秒再放開，監控視窗會出現什麼？
序列埠監控視窗
讀值 = 1，按鈕放開
讀值 = 1，按鈕放開
讀值 = 0，按鈕按下
讀值 = 0，按鈕按下
讀值 = 0，按鈕按下
讀值 = 1，按鈕放開

每一行都由四次輸出組成：print("讀值 = ")、print(state)、print("，按鈕")，最後由 println("按下") 或 println("放開") 補上結尾並換行。

文字要用雙引號

Serial.print("讀值") 印出的是文字「讀值」；Serial.print(state) 沒有引號，印出的是變數 state 裡面的數字。引號有沒有加，意思完全不同。

範例 B：按住快閃，放開慢閃

把第 1 單元的閃爍和這個單元的按鈕結合。重點是用一個變數 waitTime 決定等待時間：先預設為 500，如果按鈕按下，就改成 100。後面的閃爍程式不用分成兩份。

  • if 可以只寫前半段、不寫 else：條件成立才改 waitTime，不成立就維持 500。
  • if (digitalRead(buttonPin) == LOW) 直接把讀取寫在條件裡，省下一個變數。
  • 想一想：LED 正在 delay(500) 的時候按下按鈕，會馬上變快嗎？（答案：不會。要等這一輪閃完、回到 loop() 開頭重新讀按鈕，才會變快。）

8. 自我檢核與重點回顧

自我檢核

  1. 我能說出為什麼輸入腳位不能「什麼都不接」嗎？
  2. Serial.begin(9600) 裡的 9600 要和哪裡的設定一致？
  3. 使用 INPUT_PULLUP 時，按下按鈕讀到的是 HIGH 還是 LOW？為什麼？
  4. Serial.print() 和 Serial.println() 差在哪裡？
  5. 我能用序列埠監控視窗確認按鈕有沒有接好嗎？
看參考答案
  1. 什麼都不接的腳位會浮接，讀值受環境影響亂跳，程式就無法正確判斷。
  2. 和序列埠監控視窗右下角的速度設定一致。
  3. LOW。沒按時內建上拉電阻把腳位拉到 5V；按下時按鈕把腳位直接接到 GND。
  4. print 印完不換行，println 印完會換到下一行。
  5. 上傳 Digital Read Serial，按下和放開時數字會在 0 和 1 之間切換，就代表接好了。

本單元重點回顧

  • digitalRead() 讀取數位腳位，結果只有 HIGH 或 LOW。
  • 輸入腳位需要上拉或下拉電阻，避免浮接造成讀值亂跳。
  • Serial.begin() 開始通訊，Serial.print() 與 Serial.println() 把值印到電腦螢幕上。
  • INPUT_PULLUP 啟用內建上拉電阻，接線更簡單，但讀值是「按下為 LOW」。
