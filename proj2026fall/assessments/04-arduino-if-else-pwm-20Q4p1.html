01 「只寫 if 的判斷」和「if ... else 的判斷」最主要的差別是什麼？

  1. 只寫 if 時，條件不成立就直接跳過；if ... else 一定會執行兩段之中的一段
  2. 兩種寫法的執行結果完全相同，只是排版不一樣
  3. 只寫 if 的判斷不能放在 loop() 裡面
  4. if ... else 在條件成立時會把兩段都執行一次

02 一段 if ... else if ... else 的判斷中，有多個條件同時成立時，程式會怎麼執行？

  1. 把所有成立的區段都各執行一次
  2. 由上往下檢查，執行第一個成立的區段之後就結束整串判斷
  3. 由下往上檢查，執行最後一個成立的區段
  4. 先執行 else 的區段，再回頭檢查其他條件

03 變數 count 目前的值是 7。下列哪一個條件成立？

  1. count == 8
  2. count > 10
  3. count != 7
  4. count >= 7

04 要在判斷的括號裡檢查變數 n 是不是等於 5，應該怎麼寫？

  1. 寫 n = 5，因為括號裡只能出現一個等號
  2. 寫 n == 5，兩個等號才是「檢查是不是相等」
  3. 寫 n =< 5，這樣程式才會做比較
  4. 兩種寫法都可以，程式會自動判斷要做哪一件事

05 在讀取旋鈕的程式中，「門檻值」指的是什麼？

  1. 程式最多可以重複執行的次數
  2. 類比腳位能夠承受的最大電壓
  3. 一條分界線，把讀值分成「超過」與「沒超過」兩種情況
  4. LED 全亮時所需要的電流大小

06 下列程式中的腳位變數與輸出入模式皆已正確設定完成。當可變電阻的讀值是 350 時，LED 會如何？

int threshold = 400;

void loop() {
  int analogValue = analogRead(analogPin);

  if (analogValue > threshold) {
    digitalWrite(ledPin, HIGH);
  } else {
    digitalWrite(ledPin, LOW);
  }
}
  1. 亮起
  2. 以一半的亮度亮起
  3. 快速閃爍
  4. 熄滅

07 有人用「只要按鈕讀到 HIGH 就把次數加 1」的寫法計數，結果按一下卻被算成好幾百次。最主要的原因是什麼？

  1. loop() 每秒會重複執行非常多次，按住的那段時間內會一直累加
  2. 按鈕的電壓不足，訊號會被自動放大
  3. 序列埠監控視窗會自己重複列印同一行文字
  4. digitalRead() 一次就會回傳好幾個數值

08 程式用一個變數記住按鈕上一次的狀態。若上一次讀到 LOW、這一次讀到 HIGH，代表什麼？

  1. 按鈕剛被放開
  2. 按鈕被按住不放
  3. 按鈕剛被按下
  4. 按鈕從頭到尾都沒有被碰到

09 取餘數運算子 % 會算出相除之後剩下的數。10 % 4 的結果是多少？

  1. 2
  2. 0
  3. 1
  4. 40

10 一個按鈕計次的程式，每按一次都列印「按下次數：1」，數字始終不會累加。最可能的原因是什麼？

  1. 序列埠的通訊速度設得太低，數字來不及更新
  2. 計數變數宣告在 loop() 裡面，每一輪都被重設為 0
  3. 按鈕接在號碼太小的腳位上
  4. 沒有在 setup() 裡面設定 LED 的腳位

11 編譯時，錯誤訊息指向程式裡 else 的那一行。最應該先檢查什麼？

  1. 序列埠的通訊速度有沒有設定
  2. 有沒有在程式最前面宣告腳位變數
  3. LED 有沒有串接限流電阻
  4. else 之前的那個大括號是不是少了或多了

12 UNO 用 PWM 讓 LED 呈現不同亮度，實際上是怎麼做到的？

  1. 用非常快的速度讓腳位反覆開與關，開著的時間比例越長就看起來越亮
  2. 直接從腳位輸出 2.5 V 這種一半的電壓
  3. 自動把 LED 的限流電阻值調低
  4. 把 LED 的正負腳快速對調

13 在 UNO R3 上，哪一組腳位可以用來做 LED 調光？

  1. 0、1、2、4、7、8
  2. A0 到 A5
  3. 3、5、6、9、10、11
  4. 只有第 13 號腳位

14 想用 analogWrite() 控制 LED 亮度，關於事前的腳位設定，下列敘述何者正確？

  1. 一定要先把該腳位設定成 INPUT
  2. 不需要先設定 pinMode()，直接呼叫就可以
  3. 必須先呼叫 Serial.begin(9600) 才能使用
  4. 必須先把該腳位設定成類比輸入

15 一段迴圈寫成 for (int i = 0; i <= 100; i += 10)，i 會依序變成哪些數值？

  1. 0、1、2 一直到 100
  2. 10、20、30 一直到 100
  3. 0、10、20 一直到 100
  4. 100、90、80 一直到 0

16 LED 經 220 歐姆電阻接在可調光的腳位上，程式也送出了不同的亮度數值，但 LED 從頭到尾都不亮。最可能的原因是什麼？

  1. 亮度的數值設得太大
  2. 電阻的阻值太小
  3. 程式裡面少了註解
  4. LED 的長腳與短腳接反了

17 可變電阻讀到的數值是 0 到 1023，而設定 LED 亮度需要的是 0 到 255。要把讀值換算成亮度，應該使用哪一個函式？

  1. map()
  2. delay()
  3. pinMode()
  4. digitalWrite()

18 執行 map(511, 0, 1023, 0, 255) 之後，得到的結果大約是多少？

  1. 約 255
  2. 約 127
  3. 約 511
  4. 約 1023

19 程式在同一行印出兩個數值，序列埠監控視窗上的數字全部擠在一起。最簡單的解決方式是什麼？

  1. 把序列埠的通訊速度提高到 115200
  2. 改用 digitalWrite() 輸出這兩個數值
  3. 在兩個數值之間印出跳格字元 "\t" 或空格
  4. 把 delay() 的等待時間拉長到 1000

20 旋鈕調光器程式把換算範圍的最後兩個數字由 0, 255 對調成 255, 0，旋鈕與亮度的關係會變成什麼？

  1. 完全沒有改變
  2. 旋鈕轉到底時 LED 會燒壞
  3. LED 會開始自己一亮一滅地閃爍
  4. 旋鈕轉到底時 LED 最暗，轉回原點時最亮
