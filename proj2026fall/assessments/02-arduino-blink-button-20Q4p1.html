應用實務專題（一）02-arduino-blink-button-20Q4p1

課前前測：Arduino 程式、LED 與按鈕

01 在 Arduino 程式中，setup() 區塊裡的程式會在什麼時候執行？

  1. 板子通電或按下重置後，只執行一次
  2. 每一輪重複執行的區塊結束後，再執行一次
  3. 每隔固定時間自動執行一次
  4. 只有在序列埠監控視窗開啟時才執行

02 某同學寫的 Arduino 程式只有 void setup() { }，完全沒有寫 loop() 區塊。按下「驗證」後，會發生什麼事？

  1. 可以編譯，setup() 會自動一直重複執行
  2. 可以編譯，但板子通電後什麼事都不做
  3. 無法編譯，因為每個 Arduino 程式都至少要有 setup() 與 loop() 兩個區塊
  4. 可以編譯，Arduino IDE 會自動補上缺少的區塊

03 Arduino 程式中，寫在 // 後面的文字稱為什麼？板子會怎麼處理它？

  1. 稱為指令，板子會照著執行
  2. 稱為註解，是寫給人看的說明，板子會直接忽略
  3. 稱為錯誤訊息，會讓程式上傳失敗
  4. 稱為腳位名稱，板子會依它設定腳位用途

04 Arduino UNO 板上有一顆內建 LED，程式中可以用 LED_BUILTIN 代表它的腳位。這顆 LED 接在第幾號數位腳位？

  1. 第 2 號
  2. 第 12 號
  3. 第 0 號
  4. 第 13 號

05 在 setup() 中寫下 pinMode(LED_BUILTIN, OUTPUT);，它的作用是什麼？

  1. 讓 LED 立刻亮起並保持亮著
  2. 告訴板子：這個腳位要用來「送出」訊號
  3. 讓程式暫停一段時間再繼續
  4. 讀取這個腳位目前是高電位還是低電位

06 已在 setup() 把板上 LED 的腳位設為輸出，loop() 內容如下。LED 每一次亮與滅，各大約持續多久？

void loop() {
  digitalWrite(LED_BUILTIN, HIGH);
  delay(100);
  digitalWrite(LED_BUILTIN, LOW);
  delay(1000);
}
  1. 亮約 0.1 秒，滅約 1 秒
  2. 亮約 1 秒，滅約 0.1 秒
  3. 亮約 100 秒，滅約 1000 秒
  4. 亮與滅都約 1.1 秒

07 按下「驗證」後出現紅字，指出某個函式名稱無法辨識。檢查後發現該名稱的字母順序完全正確，每行結尾的分號與大括號也都成對。最可能的原因是什麼？

  1. 程式中的等待時間設得太短
  2. 「工具」選單中的開發板沒選對
  3. 外接 LED 沒有串聯電阻
  4. Arduino 程式區分大小寫，函式名稱的大小寫打錯了

08 程式按下「驗證」沒有任何錯誤，但按下「上傳」時顯示上傳失敗。最應該先檢查哪一件事？

  1. 把程式中的等待時間改短
  2. 在每一行後面加上說明文字
  3. 「工具」選單中的開發板與連接埠是否選對
  4. 把外接 LED 的兩隻腳對調

09 把一顆 LED 外接到 Arduino UNO 時，一定要串聯一顆電阻。主要原因是什麼？

  1. 限制流過 LED 的電流，保護 LED 與板子不被損壞
  2. 讓 LED 閃爍的速度變快
  3. 讓板子能讀取 LED 目前是亮還是滅
  4. 取代 GND 的接線，可以少接一條線

10 外接 LED 時，數位腳位先經過電阻接到 LED 的一隻腳，LED 的另一隻腳接到 UNO 的 GND。應該接到 GND 的是 LED 的哪一隻腳？

  1. 長腳，因為長腳是負極
  2. 短腳，因為短腳是負極
  3. 長腳，因為電阻已經接在短腳
  4. 哪一隻都可以，因為 LED 不分正負腳

11 把某個數位腳位設為輸入，但這個腳位什麼都沒接，再用 digitalRead() 反覆讀取。會觀察到什麼現象？這種狀態叫做什麼？

  1. 一直穩定讀到 HIGH，稱為上拉
  2. 一直穩定讀到 LOW，稱為下拉
  3. 讀到 0 到 1023 之間的各種數值，稱為可變電阻
  4. 讀值亂跳，一下 HIGH 一下 LOW，稱為浮接

12 按鈕一隻腳接 5V，另一隻腳接第 2 號腳位；第 2 號腳位同時經過一顆 10k 歐姆電阻接到 GND，腳位設為 INPUT。按鈕「沒按」時，第 2 號腳位讀到什麼？

  1. HIGH，因為這顆電阻把腳位接到 5V
  2. 一下 HIGH 一下 LOW，無法確定
  3. LOW，因為這顆下拉電阻讓腳位穩定讀到 LOW
  4. 0 到 1023 之間的某個數值

13 程式在 setup() 中寫了 Serial.begin(9600);，但打開序列埠監控視窗後，畫面出現一堆亂碼。最可能的原因是什麼？

  1. 監控視窗右下角的速度設定和程式中的 9600 不一致
  2. 按鈕插在麵包板上的方向不對
  3. 按鈕腳位沒有用 pinMode 設定用途
  4. 外接 LED 的長短腳接反了

14 某個輸入腳位以 digitalRead() 讀到 HIGH，再把這個讀值用 Serial.println() 印出。序列埠監控視窗會顯示什麼？

  1. 0
  2. 1
  3. 5
  4. 1023

15 把印出讀值的指令由 Serial.println() 改成 Serial.print()，兩者最主要的差別是什麼？

  1. 前者把值送到電腦，後者把值送到 LED
  2. 前者只能在 setup() 中使用
  3. 後者送出的速度較快，容易出現亂碼
  4. 前者送出值後會換到下一行，後者不換行

16 以 pinMode(2, INPUT_PULLUP); 設定第 2 號腳位來讀取按鈕。按下按鈕時，digitalRead(2) 讀到什麼？

  1. HIGH，因為按下時腳位經內建電阻連到 5V
  2. 讀值亂跳，因為腳位沒有外接電阻
  3. LOW，因為按下時腳位直接連到 GND
  4. HIGH，因為內建電阻會讓按下時讀到高電位

17 讀取按鈕時，改用 INPUT_PULLUP 取代「INPUT 加外接電阻」的接法，主要好處是什麼？

  1. 按鈕不必再接到 GND
  2. 啟用腳位內部的上拉電阻，不必再外接 10k 歐姆電阻
  3. 腳位會同時變成輸出，可以直接點亮 LED
  4. 序列通訊的速度會自動加倍

18 按鈕電路已依接線圖接好，程式也沒有錯，但按下按鈕完全沒反應。最可能的原因與解決方式是什麼？

  1. 監控視窗速度不一致，改成 115200
  2. 程式裡缺少說明文字，補上註解即可
  3. 外接 LED 的長短腳接反，對調即可
  4. 按鈕插的方向不對，兩隻腳本來就相通，把按鈕轉 90 度再插

19 下列程式中，腳位已完成輸入與輸出設定。目前 buttonState 為 HIGH 時 LED 亮、為 LOW 時 LED 滅。若要改成「HIGH 時 LED 滅、LOW 時 LED 亮」，下列哪一種改法正確？

int buttonState = digitalRead(buttonPin);

if (buttonState == HIGH) {
  digitalWrite(LED_BUILTIN, HIGH);
} else {
  digitalWrite(LED_BUILTIN, LOW);
}
  1. 把兩個 digitalWrite 中的 HIGH 與 LOW 對調
  2. 把 if 條件的 HIGH 改成 LOW，並同時對調兩個 digitalWrite 中的 HIGH 與 LOW
  3. 刪除整個 else 區塊
  4. 在 if 前面加上 delay(1000)

20 程式開頭寫了 int buttonPin = 2;，這一行的意思是什麼？

  1. 讓第 2 號腳位輸出高電位
  2. 把第 2 號腳位設定成輸入
  3. 建立一個名為 buttonPin 的整數變數，存放腳位編號 2
  4. 讀取第 2 號腳位兩次
