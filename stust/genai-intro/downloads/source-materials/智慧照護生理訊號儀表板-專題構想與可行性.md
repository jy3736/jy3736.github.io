# 智慧照護生理訊號儀表板：專題構想與可行性

> 保留日期：2026-09-03  
> 用途：中華醫事科技大學 AI Agent 短期課程的備選專題構想；本文件保留討論內容，不建議作為視光系與醫學檢驗生物技術系共用課程的預設專題。

## 一句話定位

建立一個可直接在瀏覽器開啟的**智慧照護生理訊號儀表板｜教學模擬**：畫面以病房樓層與匿名床位呈現資料，利用 JavaScript 在本機自動產生數值、輪循顯示樓層，並在出現模擬異常時切換到相關床位，顯示視覺提醒與事件紀錄。

此專題讓學生練習「資料如何呈現、提醒如何設計、AI Agent 如何建立並修改專案檔案」，**不是**可用於臨床的監測系統。

## 為何值得保留

- 健康照護、遠距照護與感測器資料整合是合理的未來情境。
- 學生可以直覺看見程式每幾秒更新一次資料、切換畫面及產生提醒。
- 作品完全是靜態網頁：只要 `index.html`、`styles.css`、`script.js`，不需要伺服器、資料庫或額外展示軟體。
- 可自然帶入 AI 的責任使用、資料保護、警示疲乏與「系統提醒不等於醫療判斷」等重要觀念。

## 教學專題範圍

### 使用情境

照護人員開啟 Dashboard，查看三個樓層的整體狀態。正常時，畫面每 6 秒輪流顯示 `2F`、`3F`、`5F`；若某一床的模擬資料出現紅色提醒，畫面即自動停在該樓層，顯示床位代號與事件紀錄。

### 介面元素

| 區塊 | 內容 |
| --- | --- |
| 總覽列 | 系統狀態、目前樓層、最後更新時間、提醒數量。 |
| 樓層切換 | `2F`、`3F`、`5F` 按鈕；可手動切換，也可自動輪循。 |
| 床位卡片 | 每層四張卡片，例如 `2F-01`；只使用匿名代號。 |
| 模擬訊號 | 心率、皮膚溫度變化、最後更新時間與資料來源標示。 |
| 提醒區 | 黃色「注意」與紅色「模擬異常」視覺提示，以及最新事件紀錄。 |
| 示範控制 | 「產生一筆模擬異常」按鈕，供課堂立即展示自動跳轉。 |

### 資料來源的正確標示

| 欄位 | 課堂用標示 | 不應做的宣稱 |
| --- | --- | --- |
| 心率 | 穿戴式裝置模擬 | 不說成可直接診斷心律或病情。 |
| 皮膚溫度變化 | 穿戴式裝置模擬 | 不說成核心體溫、發燒或感染診斷。 |
| 血壓 | 床邊／袖帶裝置模擬 | 不假設所有手環都能可靠地連續量測血壓。 |
| 血糖 | CGM 閘道資料模擬 | 不宣稱一般智慧手錶或手環可自行量測血糖。 |

## 最低可行版本（MVP）

1. 建立 12 筆匿名床位資料：三個樓層、每層四床。
2. 在 `script.js` 每 3 秒生成新的**虛構**心率與皮膚溫度變化值，並更新畫面。
3. 在無提醒時每 6 秒輪循樓層；保留手動切換按鈕。
4. 以課堂自訂的「注意」門檻顯示黃、紅色提示；此門檻不可標示為臨床標準。
5. 點擊按鈕後建立一筆模擬異常，自動切到對應床位並寫入事件紀錄。
6. 顯示固定安全聲明：**所有資料均為本機自動產生的教學模擬，不可用於診斷、照護決策或緊急通知。**

## 專案資料夾

```text
campus-web-demo/
├── index.html       # Dashboard 的網頁結構
├── styles.css       # 卡片、狀態色彩與手機版面
└── script.js        # 模擬資料、樓層輪循、異常與事件紀錄
```

資料只存在瀏覽器記憶體；重新整理後重置。這是「本機即時模擬」，不是資料庫，也不會真的傳送簡訊、推播或裝置警報。

## 可直接交給 AI Agent 的提示

> 請把目前的 `campus-web-demo` 改成單一頁面的「智慧照護生理訊號儀表板｜教學模擬」。只使用 `index.html`、`styles.css`、`script.js`，不可使用外部函式庫、後端、資料庫、網路 API、真實簡訊或推播。建立 `2F`、`3F`、`5F` 三個樓層，每層四個匿名床位。用 JavaScript 每 3 秒在本機生成心率、皮膚溫度變化與最後更新時間；每 6 秒輪循樓層。加入「產生一筆模擬異常」按鈕，異常時自動顯示對應樓層、床位、紅色視覺提示和事件紀錄。請在頁面上清楚標示，所有資料僅為教學模擬，不可用於診斷、照護決策或緊急通知。

## 可行性判斷

### 合理的假設

- 一般穿戴式裝置可提供心率及部分健康趨勢資料；以此模擬資料流是合理的。
- 感測數位健康裝置可在臨床外即時擷取資料，未來與照護 Dashboard 整合的方向合理。
- 專用 CGM 可持續產生血糖資料；在介面中用「CGM 閘道」概念模擬資料來源合理。

### 必須保留的限制

- 皮膚溫度趨勢不是核心體溫；不能用來宣稱發燒或感染。
- 某些手錶有血壓功能，但可能需要袖帶校正、限定地區與裝置，且不以疾病診斷或治療為用途。
- 美國 FDA 警告，不可使用宣稱由智慧手錶或智慧戒指非侵入量測血糖的產品；一般手環不可作為血糖資料來源。
- 真實的住院、長照或重症照護系統需要核准設備、臨床流程、身分核對、資安、告警升級、紀錄保存與人員回應機制。本專題不處理這些部署問題。

## 為何不建議作為兩系共用的預設專題

本題較接近護理、長照、病房管理與健康資訊系統。視光系與醫學檢驗生物技術系學生可以理解其資料呈現與安全議題，但專題的核心不是兩系最直接的實作情境。

## 建議的共同預設專題：社區健康篩檢與檢驗品質 Dashboard（教學模擬）

這是一個更貼近兩系的共用靜態網頁：以校園或社區健康篩檢活動為情境，同時呈現**視光篩檢流程**與**醫檢檢體／品質流程**。重點放在資料完整性、流程狀態、品質提醒與專業複核，而不是對個人做診斷。

| 模組 | 視光系情境 | 醫技系情境 | 共同 AI／網頁能力 |
| --- | --- | --- | --- |
| 報到與流程 | 匿名受檢者進入視力篩檢站 | 匿名檢體進入收件流程 | 卡片、篩選、狀態切換。 |
| 資料完整性 | 篩檢項目是否完成、是否需要專業複核 | 檢體標示、收件、前處理與檢驗狀態是否完整 | 模擬資料、缺漏提示、事件紀錄。 |
| 品質提醒 | 儀器或篩檢流程的「待確認」狀態 | 品管結果、檢體不適用或待覆核狀態 | 黃紅提醒、Dashboard 摘要與圖表。 |
| 結果呈現 | 只顯示「完成／待複核／建議轉介」等流程狀態 | 只顯示「通過／待複核／不適用」等品質狀態 | 不輸入個資、不宣稱診斷。 |

### 50 分鐘內的共同 MVP

- 設計兩個分頁：`視光篩檢站` 與 `醫檢品質站`。
- 每個分頁放六筆匿名模擬資料，使用代號如 `S-101`、`L-201`。
- 使用 JavaScript 每 3 秒更新一筆流程狀態；加入「產生一筆待複核事件」按鈕。
- 顯示「完成、進行中、待複核」統計卡與簡單長條圖。
- 所有受檢資料、檢驗數字與品管門檻均為課堂虛構資料；不提供診斷或醫囑。

這個版本可讓視光系學生連結篩檢與專業複核流程，讓醫技系學生連結檢體處理、品質管理與資料完整性，也能共同練習 AI Agent、靜態網頁、資料視覺化與專業責任。
