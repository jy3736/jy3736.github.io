第一階段｜依規格產生基本排班工具

將本頁提供的規格檔與職員資料檔一併交給 AI Agent。規格已描述賣場角色、班別、人力需求、排班規則、畫面需求及驗收條件。每位學生產生的介面可以不同，但功能須符合相同的規格與驗收條件。

  1. 閱讀規格及資料找出系統目標、職員資料、排班規則與驗收條件。
  2. 產生基本版本請 AI Agent 建立可在本機瀏覽器操作的一週排班工具。
  3. 操作並檢查查看職員資格、可排班時間、重複排班及人力缺額。
  4. 描述問題並修正提供操作步驟、實際結果與預期結果，請 AI Agent 針對問題修正。
  5. 確認基本版本符合規格後，將此版本作為第二階段的既有系統基礎。

可提供給 AI Agent 的起始指令

請先閱讀「學生用規格-基本排班系統.md」與「虛構職員資料庫.json」，再依照規格在目前專案中建立可於本機瀏覽器操作的迷你賣場排班工具。請使用 JSON 檔中的虛構職員資料，不要加入真實人員。開始製作前，請先簡短整理你理解的系統目標、主要排班規則及驗收條件。完成後請說明如何開啟工具，以及如何逐項檢查驗收條件。

基本版本檢查重點

  • 工具可在本機瀏覽器開啟。
  • 使用提供的虛構職員資料。
  • 可產生一週、每天三個時段的班表。
  • 只安排合格且當時有空的人員。
  • 不重複排班，也不超過每週時段上限。
  • 明確顯示各時段的人力缺額。
  • 班表標示為待主管確認的建議草稿。

第二階段｜在原作品上追加臨時請假功能

修改原則：已確認的基本版本就是修改起點。不要重新產生整個系統或全面改寫；先理解目前作品，再只做新增功能所需的最小修改，保留既有畫面、資料、排班流程及已完成的功能。

新增功能需求

  1. 主管可選擇日期、時段及已排班人員，標記該人員臨時無法出勤；不須輸入病情或私人原因。
  2. 系統移除該員在受影響時段的指派，依可工作時間、職務、技能、撞班及每週排班上限重新計算。
  3. 最多提供三個彼此不同且符合規則的重組方案；若實際只有一至兩個，就只顯示這些方案。
  4. 每個方案說明人員與班別如何調整、調整原因，以及調整後仍未補足的人力。
  5. 主管選擇方案後才套用；若取消，原班表維持不變。未受影響的班表應保持原樣。
  6. 若沒有可行方案，清楚警示目前無法以現有人力完成重排，提醒主管考慮安排臨時人員或請總部支援。

追加修改步驟

  1. 檢視目前作品先確認現有畫面、資料、排班方式及已完成的功能。
  2. 提出最小修改計畫列出預計調整的檔案與保留原有功能的方式；先不修改檔案。
  3. 檢視並確認計畫確認修改範圍只涉及新增功能所需的部分。
  4. 追加功能並檢查確認後才修改，並重新檢查新舊功能。

可提供給 AI Agent 的追加指令

請先檢視目前專案中的排班工具，確認現有畫面、資料結構、班表產生方式及已完成的功能。這是已確認可用的基本版本，請勿重新產生整個系統、全面改寫程式或更換整體架構。先提出最小修改計畫，列出預計新增或修改的檔案，以及如何保留現有功能；先不要修改檔案，等我檢視並確認後再進行。

新增臨時無法出勤與排班重組功能：主管選擇已排班人員、日期及時段，將該人員標記為該時段無法出勤。系統須移除該員在該時段的指派，依現有排班規則提出最多三個不同且可行的重組方案。顯示每個方案的人員與班別變動及尚未補足的需求；若方案少於三個，只顯示實際可行的方案。主管選擇後才套用，取消時保留原班表。若無可行方案，顯示警示並提醒主管考慮安排臨時人員或請總部支援。不得詢問病情或私人原因。未受影響的班表與所有基本功能都須保留。

第二階段檢查重點

  • 基本版本原有功能仍可使用。
  • 請假人員不再被計入該時段人力。
  • 所有方案均符合資格、時間及排班限制。
  • 未受影響的班表沒有被更動。
  • 主管選擇前不會自動套用方案。
  • 沒有方案時會警示並提示支援選項。
  • 不詢問私人請假原因，也不要求請假人員回來工作。
