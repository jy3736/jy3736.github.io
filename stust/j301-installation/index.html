安裝前須知

適用範圍

供多門 AI Agent 課程、一般 C/C++ 課程與 Flutter App Development 課程使用。環境為 Windows 10／11 混合電腦、WSL 2 與 Ubuntu LTS；Flutter 在 Windows 執行，以 Android 與 Web 為驗收目標。課堂編輯器統一使用 VS Code。

電腦每次重開機會還原，預計僅在期中考週安裝一次，供學期後半段使用。因此安裝程式之外，也要完成學生帳號初始化、範本依賴下載、快取預載、還原基準保存與重啟後驗收。文件只涵蓋軟體、必要設定、預載與驗收。

文件與執行順序

  1. 閱讀本頁的版本與還原原則。
  2. 依 共用環境安裝指南 完成 Windows 與 WSL 共用環境。
  3. 依 Flutter 環境安裝指南 完成 Windows Flutter、Android 與 Web 環境。

版本選擇與固定原則

  • 安裝當日選官方最新 stable；Node.js 選 LTS，Ubuntu 選當日仍受支援且與 WSL 相容的 LTS。不要將本文件日期當作安裝版本。
  • 最新版若與作業系統或課程範本不相容，記錄原因與可用的相容 stable 版本；不得直接標示通過。Windows 10／11 分別確認官方支援條件及實際執行結果。
  • Python 最新 stable 若缺少相容套件，可並存另一個相容版本；不取代 Ubuntu 系統 Python。
  • 以實際課程範本驗證後，固定確切 SDK、工具、擴充套件、套件與瀏覽器版本，保留 lockfile、安裝來源及必要安裝檔。後續更新要重新驗收，不在未驗證下整批升級。
  • AI 桌面產品名稱、CLI 與編輯器整合應分別依官方下載與支援頁核對。不同產品不能當作同一套程式，也不能假定都有相同平台支援。
  • 固定本機版本不代表雲端 AI、登入機制、模型或 TTS 服務能永久使用。雲端功能須連線驗證，服務變更仍可能影響學期中使用。

還原基準與學生帳號

  1. 依既有還原機制保存安裝結果，確認系統功能、Windows 軟體、WSL 發行版及其資料都在有效基準內。
  2. 使用實際學生權限初始化工具；不要只在管理員帳號安裝、登入或下載快取。學生需能寫入專案、SDK 所需目錄、暫存與套件快取。
  3. 保存 VS Code 擴充套件、WSL VS Code Server、各端 Python／Node 依賴、瀏覽器、Flutter／Pub／Gradle／Android SDK／AVD 等必要內容。Windows 與 WSL 的快取分開驗證。
  4. 暫時斷網，以無雲端依賴範本從乾淨工作副本重建、啟動與測試；必須實際證明不需下載。測完恢復連線，另驗 AI 與雲端 TTS。
  5. 任意未來 AI 生成的新依賴無法事先全部預載。離線能力僅涵蓋紀錄中已通過的範本與版本。

7. 預載與封存前檢查

每個實際課程範本應準備原始碼、鎖定檔、啟動說明、無秘密的設定範例、測試資料、預期畫面，以及各平台重建需要的依賴快取。

  • Python：保留選定直譯器與套件。可為每端建立對應的 wheelhouse；若依賴只有原始碼包，需預先建 wheel 或另存並驗證建置依賴。新建環境後實測離線安裝。
  • Node：預載 npm cache 或 pnpm store；依固定 lockfile，從不含 node_modules 的副本重建。npm 範本可用 npm ci --offline；pnpm 範本可用 pnpm install --offline --frozen-lockfile。缺少任何依賴即補齊後重測。
  • 工具：預載 VS Code Server／擴充、Playwright 瀏覽器、Mermaid 使用的瀏覽器、字型及選用模型。記錄實際快取位置與學生讀寫權限。
  • 首次啟動：以學生帳號各開啟一次桌面程式、各類範本、文件轉換與瀏覽器自動化，排除上課時才觸發下載。
  • 完成還原基準保存後，重開、還原、暫斷網重建，再恢復網路測 AI／TTS。各端結果填入驗收表。

Flutter 課程環境安裝指南

狀態：待教室實測。主環境為 Windows，目標為 Android 與 Web。先完成共用指南中的 Git、VS Code 與網路設定。

1. Flutter SDK 與編輯器

  1. 從官方取得安裝當日最新 Flutter stable SDK，解壓至學生可寫、沒有空白或特殊字元的路徑，例如 C:\dev\flutter。確認學生可更新快取；避免放在需要管理員權限才能寫入的位置。
  2. 將 C:\dev\flutter\bin 加入 PATH，重新開啟 PowerShell 與 VS Code。
  3. Flutter SDK 已包含 Dart；不另裝另一套 Dart SDK。確認 flutter 與 dart 都來自同一套 SDK。
  4. 在 Windows VS Code 安裝 Flutter／Dart 擴充套件並開啟一次專案，完成初始化。

依據：Flutter 手動安裝、Dart SDK 說明。

2. Android Studio 與 SDK

安裝 Android Studio stable，主要用於 SDK 與 Emulator 管理；課堂程式編輯維持 VS Code。

在 SDK Manager 安裝並記錄以下元件的精確版本：

  • Android SDK Platforms：課程範本所需 API level。
  • Android SDK Build-Tools、Command-line Tools、Platform-Tools（含 ADB）、Android Emulator。
  • CMake、NDK side-by-side：依 Flutter 與課程外掛要求選相容版本。
  • 手機 AVD 所需系統 image：記錄 API、架構、image 類型與 AVD 名稱。

使用 Android Studio 隨附 Java，確認其版本與範本 Gradle wrapper、Android Gradle Plugin 相容；以實際建置結果判斷。預下載 wrapper 對應的 Gradle distribution 與 Android 建置依賴，不任意將所有元件升到不同的最新版。

依據：Flutter Android 設定。

3. Emulator、實機與 Web

Emulator

啟用韌體硬體虛擬化與 Windows Hypervisor Platform，依官方要求設定並重啟。建立手機 AVD、啟動至主畫面，確認在 WSL 2 同時可用的情況下能正常啟動、執行 App 與 hot reload。

Android Studio 官方最低記憶體條件區分 Studio 8 GB、Studio 加 Emulator 16 GB；安裝當日再核對完整條件。不符合模擬器條件時，採 Web 或 Android 實機驗收，模擬器欄保留待驗收並說明限制，未測不能寫通過。

依據：Android Studio 安裝條件、Emulator 硬體加速。

Android 實機

依手機廠牌安裝必要 Windows USB 驅動，使用可傳資料的 USB 線；在手機啟用開發人員選項與 USB debugging，閱讀並確認此電腦的偵錯授權。檢查 ADB 識別、安裝與執行 App。未提供手機時明確填「待驗收：未有手機」，不可用模擬器結果代替。

狀態須為 device，若為 unauthorized 或 offline，先排除授權／連線問題。

Web

安裝 Chrome 與 Edge stable；Chrome 作為下列命令的主要測試瀏覽器，Edge 另測啟動與頁面功能。依 Flutter Web 設定 核對支援方式。

5. 實際課程範本驗收

空白專案通過後，仍須逐一開啟教材使用的範本，以各自 pubspec.yaml、pubspec.lock、Gradle wrapper 與 Android 設定完成 resolve、analyze、test、build、run：

範本 Android／Web 必驗功能
基礎 App UI 互動、狀態更新、hot reload
多頁導覽 go_router 切換頁面、返回與參數傳遞
本地偏好 shared_preferences 寫入、讀取，重啟 App 後讀回
HTTP JSON API 連到無秘密的測試 API、解析 JSON、顯示成功與錯誤狀態

套件來源：go_router、shared_preferences。版本依實測固定，不在本文件預填未測版本。

HTTP 範本可搭配共用環境的本地 API，分別設定 Web 與 Android 可達的位址。Android 的 localhost 指向裝置自身；依模擬器網路或實機連線方式設定主機位址／ADB 轉送。Web 若有跨來源限制需設定測試 API 的 CORS。確認 Android 網路權限及教材使用協定的設定，不把連線失敗誤判成 SDK 缺漏。

camera、audio、資料庫等其他外掛僅依教材需要加入；先核對 Android／Web 支援與權限，再個別測試。不保證任意新生成的外掛已可離線使用。

6. 預載、還原與斷網重建

  1. 以學生帳號完成 Flutter cache、Pub cache、Gradle distribution／依賴、Android SDK、system image、AVD 與 VS Code 擴充初始化。
  2. 留存每個實際範本的精確鎖定檔、SDK 版本、Java／Gradle／Android Gradle Plugin／NDK 組合與快取位置。
  3. 將上述資料納入還原基準，確認學生有必要讀寫權限，無個人憑證。
  4. 正常重開並還原後，先確認 SDK／AVD／範本與快取仍在，再暫時斷網。
  5. 從不含 build、.dart_tool 的新範本副本執行 flutter pub get --offline、analyze、test、Android／Web build 與本地功能測試。Gradle 亦須不需下載；在範本 android 目錄以 Windows PowerShell 執行 .\gradlew.bat --offline assembleDebug 驗證 Gradle 快取。記錄所有缺漏後補載重測。
  6. API 範例斷網驗收使用可達的本地服務；需要外部雲端者另在恢復網路後測試。保存驗收日誌與產物路徑。

離線通過只適用於實測的範本、目標與版本；安裝後仍需線上服務的功能另行記錄。
