0. 一張圖看懂指標

指標只有三個動作要記：

  1. &x：問 x「你的門牌號碼是多少？」得到一個位址。
  2. p = &x：把這個門牌號碼存進指標 p，圖上就多了一支從 p 指向 x 的箭頭。
  3. *p：沿著箭頭走過去，打開那一格。讀 *p 就是讀 x，寫 *p 就是寫 x。

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
*p = 42
x = 99

Beej 用「編了號的格子」來比喻記憶體，每個位元組都有一個依序遞增的編號，這個編號就是位址（Beej §5.1）；指標就是存放位址的變數（Beej §5.2），而 * 讓你透過指標使用它所指的資料（Beej §5.3）。後面每一節都是把這張圖再放大來看。

1. 位址與取址運算子 &

問題定義

  • 問題：變數放在記憶體的哪裡？兩個變數的值相同，它們是同一個東西嗎？
  • 輸入：幾個不同型別的變數。
  • 輸出：每個變數的值、大小（位元組數）與位址。
  • 限制：位址由系統決定，每次執行都可能不同，程式不能假設它是某個固定數字。

計算思維：抽象化

記憶體裡其實是一長串位元組。我們把它抽象化成「一排有門牌號碼的格子」：每個變數租下一個或幾個相連的格子（Beej §5.1：多位元組型別的位元組一定相鄰），用第一個位元組的編號當作整個變數的位址。之後所有指標問題都可以畫成這樣的格子圖來想。

演算法

1. 宣告變數 → 系統配置格子，並決定位址
2. 用 sizeof 問「佔幾個位元組」
3. 用 &變數 問「門牌號碼是多少」
4. 用 %p 印出位址

基本範例：印出值、大小與位址

執行結果的樣子（位址每台電腦、每次執行都可能不同）：

先猜猜看會印出什麼，再點我看執行結果
執行結果
grade：值 A，佔 1 位元組，位址 0x16ce9dfeb
age：值 19，佔 4 位元組，位址 0x16ce9dfe4
height：值 172.5，佔 8 位元組，位址 0x16ce9dfd8
  • &grade 產生 grade 的位址（GNU C 手冊 §14.1）。
  • %p 用來印位址，通常以 0x 開頭的十六進位顯示；位址前面加 (void *) 是為了符合 %p 要求的型別。
  • 真實位址不一定照宣告順序排列，所以動畫裡的 1000、1016 只是方便說明的假設值。

延伸練習：值一樣，不代表是同一格

執行結果

兩者位址相同嗎？不同

輸入格式錯誤

scanf 要把讀到的數字「放進」你的變數，所以它需要的是門牌號碼 &heightCm，而不是變數現在的值。這和第 5 節「函式透過指標寫回呼叫端」是同一件事；scanf 的回傳值告訴你成功讀到幾個項目，所以先檢查是不是 2。

手動追蹤（輸入 170 65）

步驟 heightCm（位址 1000） weightKg（位址 1008） 說明

常見錯誤

  • scanf("%lf", heightCm); 忘了 &：scanf 會把一個無意義的值當成位址去寫，結果無法預期。開啟 -Wall 時編譯器通常會警告。
  • 用 %d 印位址：位址不是 int，請用 %p。

自我檢查

  1. 宣告 int a = 5, b = 5; 之後，&a == &b 成立嗎？
  2. 為什麼 printf("%d", age) 不需要 &，scanf("%d", &age) 卻需要？
看答案

1. 不成立。a、b 是兩個不同的格子，值相同但位址不同。2. printf 只需要讀出值；scanf 要把資料寫進變數，必須知道它的位址。

2. 指標變數與解參照 *

問題定義

  • 問題：能不能不寫變數的名字，也讀寫到那個變數？
  • 輸入：一個變數 stock 與指向它的指標 p。
  • 輸出：透過 *p 修改後，stock 的值。
  • 限制：p 必須先指向一個真的變數，才能用 *p。

計算思維：模式辨識

觀察動畫會發現一個固定模式：只要 p 指向 stock，*p 出現的地方都可以換成 stock（Beej §5.3：解參照後的指標可以完全當成原變數使用）。兩個名字、同一個格子，所以兩邊永遠一致。

寫在哪裡 例子 意思
宣告中 int *p; p 是「指向 int 的指標」
運算式中 *p = 5; 把 5 存進 p 所指的格子
運算式中 &stock 取得 stock 的位址

宣告時的 * 和解參照的 * 是同一個符號，但意思不同（Beej §5.3）；而且 * 跟著變數走，int *p, q; 只有 p 是指標（Beej §5.6）。

演算法

1. stock ← 10
2. p ← stock 的位址          （畫出 p → stock 的箭頭）
3. 沿著箭頭讀出值，減 3，再沿著箭頭寫回
4. 直接用 stock 的名字加 20
5. 沿著箭頭讀出值並印出

基本範例：透過指標修改變數

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
賣出 3 件後：stock = 7，*p = 7
進貨 20 件後：stock = 27，*p = 27

延伸練習：指標自己也是一格

指標也是變數，所以它也有自己的位址與大小。

執行結果的樣子（位址每次不同；在 64 位元電腦上指標通常佔 8 位元組）：

對照動畫：紫色格子「p」裡的 1000 是 p 的值（stock 的位址），格子下方的 1016 才是 p 自己的位址。

常見錯誤

  • int *p; *p = 5;：p 還沒指向任何變數就解參照。指標沒有設定時裡面是無意義的值（Beej §5.5），寫進去的結果無法預期。
  • int *p, q; 以為 q 也是指標。建議一行只宣告一個指標。
  • 把 p = &stock; 寫成 *p = &stock;：前者是「讓 p 指向 stock」，後者是「把位址寫進 p 所指的 int」，型別不合，編譯器會警告。

自我檢查

  1. 動畫執行 *p = *p - 3; 之後，p 存的值是多少？stock 是多少？
  2. int *p = &stock; 和 int *p; p = &stock; 意思一樣嗎？
看答案

1. p 仍是 1000，stock 變成 7。2. 一樣。第一種寫法是在宣告時直接初始化，* 屬於宣告的一部分，不是解參照。

3. 改變指向：一個指標，輪流指向不同變數

問題定義

  • 問題：三個整數中找出最大值，而且要知道「是哪一個變數」。
  • 輸入：a = 7、b = 12、c = 9。
  • 輸出：最大值 12，以及它是 b。
  • 限制：比較時不搬動任何資料，只改變指標的指向。

計算思維：演算法設計

把「目前最大的是誰」交給一個指標記住，這個指標就像冠軍的獎盃：一開始先頒給 a，之後每來一個候選值就和 *p（目前冠軍的值）比，比較大就把獎盃交給它（p = &候選值）。每一步的動作都一樣，這是重複的模式；候選值一多，就可以把它們放進 Unit 7 的陣列，用迴圈重複同一個比較（Unit 10 會把陣列和指標接起來）。

動畫：箭頭怎麼移動

看下方 track_max.c 的動畫：被改的是 p 存的位址，a、b、c 的值完全沒動。p = &b（改指向）和 *p = ...（改內容）是完全不同的動作。

基本範例：同一個 p，依序指向三個變數

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
早上：18 度
中午：27 度
晚上：21 度
三個變數仍然是：18 27 21

三次 printf("...%d...", *p) 寫法一模一樣，印出的內容卻不同，因為箭頭指的格子換了。

延伸練習：用指標記住最大值

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
最大值是 12
它是變數 b

最後一行比較 p == &a、p == &b：比較的是位址，回答的是「p 指向誰」；*p == 12 比較的才是值。

問題：輸入三種文具的庫存，替庫存最少的那一種補 20 件。

執行範例：

執行結果

執行到的敘述 lowest 指向 *lowest 說明

常見錯誤

  • 寫成 *p = b; 想「換冠軍」：這會把 b 的值抄進 a（因為 p 指向 a），a 被改掉了，冠軍卻沒換。換冠軍要寫 p = &b;。
  • 用 <= 還是 < 要想清楚：兩個值相同時，< 保留先出現的那一個，<= 會換成後面那一個。

自我檢查

  1. 在 track_max.c 輸入改成 a = 9、b = 9、c = 3，p 最後指向誰？
  2. 把 restock_lowest.c 改成「替庫存最多的商品打 9 折出清」，要改哪兩個地方？
看答案

1. 指向 a，因為 b > *p 是 9 > 9，不成立。2. 兩個比較都改成 >，最後一行改成打折的算式（例如 *lowest = *lowest * 9 / 10;），變數名稱也建議改成 highest。

4. NULL 指標：「目前沒有指向任何地方」

問題定義

  • 問題：成績可能還沒出來。函式拿到一個指標時，怎麼知道能不能解參照？
  • 輸入：一個可能指向成績、也可能「什麼都沒指」的指標。
  • 輸出：有成績就印出成績，沒有就印出「尚無成績」。
  • 限制：絕對不能對 NULL 解參照（GNU C 手冊 §14.7：在大多數平台上程式會被終止）。

計算思維：演算法設計

任何型別的指標都可以存特別的值 NULL，代表「沒有指向任何東西」（Beej §5.5）；NULL 定義在 stddef.h，可以用 ==、!= 和指標比較（GNU C 手冊 §14.6）。所以演算法加一道守門的判斷：先問「有沒有箭頭？」，有才沿著箭頭走。

基本範例：先設成 NULL，用之前先檢查

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
p 目前沒有指向任何變數
p 指向的座位號碼：12

宣告指標時如果還不知道要指向誰，就先設成 NULL，不要讓它保持無意義的值。

問題：三位會員各有編號與點數。輸入會員編號，找到就加 10 點；找不到要說明。

found 一開始是 NULL，意思是「還沒找到」。搜尋過程只負責讓它指向找到的點數；搜尋結束後，一個 NULL 檢查就能分辨兩種結果，加點數的那一行也不必知道是哪一位會員。

手動追蹤

常見錯誤

  • 判斷寫反：if (p == NULL) printf("%d", *p); 正好在最危險的時候解參照。
  • 以為 NULL 檢查能擋住所有錯誤：它只擋得住「設成 NULL」的指標。宣告後完全沒設定的指標裡是無意義的值，不等於 NULL，檢查也擋不住。所以宣告時就要初始化。

自我檢查

  1. 在 null_check.c 的 showScore 中拿掉 return;，傳入 NULL 時會發生什麼事？
  2. 為什麼 member_points.c 的 found 要一開始就設成 NULL？
看答案

1. 印出「尚無成績」後會繼續執行 *score，對 NULL 解參照，程式很可能被終止。2. 如果三個條件都不成立，found 不會被設定；先設成 NULL，之後的檢查才有意義。

5. 指標參數：讓函式改到呼叫端的變數

問題定義

  • 問題：寫一個 swap 函式交換兩個變數的值。
  • 輸入：main 的 x = 3、y = 8。
  • 輸出：呼叫後 x = 8、y = 3。
  • 限制：函式拿到的引數一定是複本（Beej §5.4），所以要想辦法讓複本也能找回原本的變數。

計算思維：分解

把函式的參數分成兩類：

參數的用途 參數型別 呼叫時傳
只需要讀 int bonus 值，例如 5
需要寫回呼叫端 int *score 位址，例如 &amy

swap 的兩個參數都要寫回，所以兩個都要是指標。傳過去的仍然是複本，但那是「門牌號碼的複本」，照著門牌號碼找過去，開的還是同一個格子（Beej §5.4）。

動畫：傳值 vs 傳位址

對照下方 swap_wrong.c 和 swap.c 的動畫：傳值版交換複本，指標版沿著箭頭修改 main 的格子。

演算法

swap(a, b)：a、b 是兩個位址
1. t ← a 所指的值
2. a 所指的格子 ← b 所指的值
3. b 所指的格子 ← t

基本範例：替學生加分

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
Amy：83，Ben：100

bonus 只需要讀，所以是一般的 int；score 要寫回，所以是 int *。Ben 的 95 + 8 = 103 超過上限，被修正成 100。

延伸練習：傳值版與傳位址版的 swap

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
3 8

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
8 3

兩個程式只差在參數的 *、函式內的 *，以及呼叫時的 &。對照兩個 swap 動畫進入函式的那一步：傳值版的 a、b 裝的是 3 和 8，傳位址版裝的是 1000 和 1016，而且多了兩支箭頭。

應用情境：三個數由小到大排好

問題：輸入三個整數，用 swap 把它們排成由小到大，結果要留在原本的三個變數裡。

執行範例：

先猜猜看會印出什麼，再點我看執行結果
執行結果
請輸入三個整數：9 2 5
由小到大：2 5 9

執行範例（有相同的數）：

先猜猜看會印出什麼，再點我看執行結果
執行結果
請輸入三個整數：4 4 1
由小到大：1 4 4

sortThree 拿到的 first、second、third 已經是指標，所以呼叫 swap 時直接傳 first，不用再加 &。

手動追蹤（輸入 9 2 5）

步驟 p q r 說明
開始 9 2 5
第 1 個比較 2 9 5 9 > 2，交換 p、q
第 2 個比較 2 5 9 9 > 5，交換 q、r，最大值到位
第 3 個比較 2 5 9 2 > 5 不成立，不交換

常見錯誤：函式裡忘了 *

預期輸出：

先猜猜看會印出什麼，再點我看執行結果
執行結果
x = 5

n = NULL; 改的是參數 n 這個指標複本，箭頭消失了，x 完全沒被碰到；函式結束後這個複本就消失。想改指向的資料，要寫 *n = *n + 10;。不能用 n = n + 10; 來示範固定輸出：它超出單一 int 物件允許的指標運算範圍，行為未定義。

另一個常見錯誤是呼叫時忘了 &，例如 swap(x, y) 去呼叫指標版的 swap：函式期待位址卻拿到整數，編譯器會提示要用 & 取得位址（詳見 Unit 9 的常見錯誤 1）。

自我檢查

  1. 在 swap.c 的動畫中，swap 結束後 a、b 的格子消失了，為什麼 x、y 的改變還在？
  2. 寫出 void minMax(int a, int b, int *smaller, int *larger) 的呼叫方式：main 裡有 int lo, hi;。
看答案

1. 因為 swap 是沿著箭頭直接寫進 main 的格子，收回的只是 a、b、t 這些複本。2. minMax(x, y, &lo, &hi);，前兩個只讀，傳值；後兩個要寫回，傳位址。

6. 綜合程式：零用錢帳本

問題定義

  • 輸入：一開始的零用錢，接著一連串指令：d 金額 存入、w 金額 支出、q 結束。
  • 輸出：每筆指令後的餘額；支出超過餘額時取消並提示。
  • 限制：金額必須是正整數；輸入格式錯誤時停止讀取。

分解

函式 參數 為什麼這樣設計
deposit int *balance, int amount 要改餘額，所以餘額傳位址；金額只讀
withdraw int *balance, int amount 同上；回傳 1／0 表示成功與否
showBalance int *balance 只讀，但先檢查 NULL 示範守門

演算法

1. 讀入起始金額，失敗或小於 0 → 結束
2. 重複：
   a. 讀指令字元；讀不到或是 q → 跳出
   b. 讀金額；不是正整數 → 跳出
   c. d → deposit(&wallet, 金額)
      w → withdraw(&wallet, 金額)，失敗就提示
   d. 印出餘額
3. 印出最後餘額

執行範例：

先猜猜看會印出什麼，再點我看執行結果
執行結果
請輸入一開始的零用錢：100
指令：d 金額＝存入，w 金額＝支出，q＝結束
指令：d 50
目前餘額：150 元
指令：w 80
目前餘額：70 元
指令：w 200
餘額不足，這筆支出取消
目前餘額：70 元
指令：q
結束。目前餘額：70 元

測試

測試項目 輸入 預期結果
一般存提 100、d 50、w 80、q 餘額 150 → 70
邊界：剛好領完 100、w 100、q 餘額 0，不提示不足
餘額不足 100、w 200、q 提示取消，餘額仍 100
起始金額錯誤 -5 金額必須是 0 以上的整數
看不懂的指令 100、x 5、q 看不懂的指令：x，餘額不變

  • withdraw 為什麼要先檢查、再修改 *balance？如果順序反過來，餘額不足時會發生什麼事？
  • 加一個 int transfer(int *from, int *to, int amount)，把錢從錢包轉到存錢筒。它需要幾個指標參數？可以直接呼叫 withdraw 和 deposit 嗎？

本講義未涵蓋的內容

  • 真實位址的排列方式：教材只保證同一個變數的多個位元組相鄰（Beej §5.1），不保證不同變數照宣告順序排列；動畫中的連續位址只是為了說明。
  • 「信箱與門牌號碼」「獎盃」的比喻：Beej §5.1 用的是「編了號的格子」與「住家地址」的比喻，本講義的比喻是延伸的說明方式。
  • %p 搭配 (void *) 的原因：本講義在引用的教材中沒有找到完整說明，這裡依照 -Wpedantic 的要求加上。
