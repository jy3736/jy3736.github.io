1. 開檔、關檔與錯誤檢查

用白話說

到目前為止，程式的資料都來自鍵盤，結果都印在螢幕上；程式一結束，資料就不見了。檔案讓資料可以保存下來，下次執行時再讀回來。

使用檔案的流程就像去圖書館借書：

  1. 開檔（fopen）：辦理借閱，拿到一張借閱證（FILE *）。
  2. 讀或寫：拿著借閱證讀取或寫入內容。
  3. 關檔（fclose）：歸還，讓系統收回資源。

還有一件事一定要做：開檔可能失敗（例如檔案不存在），所以每次開檔都要先檢查。

教材怎麼說

  • C 的輸入輸出都透過 FILE * 型別的資料進行，它記錄了「開啟的是哪個檔案、目前讀寫到哪裡」等資訊。出處：Beej §9.1 The FILE* Data Type。
  • 程式一開始就有三個已經開好的串流：stdin（標準輸入，通常是鍵盤）、stdout（標準輸出，通常是螢幕）、stderr（標準錯誤，通常也是螢幕）。printf(...) 其實就等於 fprintf(stdout, ...)。出處同上。
  • fopen(檔名, 模式) 開啟檔案並回傳 FILE *；發生錯誤（例如找不到檔案）時回傳 NULL，所以應該檢查。出處：Beej §9.2 Reading Text Files。
  • 常用的模式如下。出處：Beej 函式庫參考 §23.7 fopen()；Beej §9.5 Writing Text Files。
模式 用途 檔案不存在時 檔案已存在時
"r" 只讀 開檔失敗 從頭讀起
"w" 只寫 建立新檔 立刻清空，從頭寫起
"a" 附加 建立新檔 保留原內容，寫在最後面
  • fclose 關閉檔案並釋放系統資源。寫入的資料有可能要等到關檔時才真正寫進磁碟，所以用完一定要關檔。出處：Beej 函式庫參考 §23.5 fclose()。

對照練習

練習「單元 1」的基本範例開檔寫入一行文字並檢查是否成功；延伸練習用 "r" 模式開啟不存在的檔案，觀察如何在失敗時正常結束。下面的補充範例寫入多行資料，並把「開檔失敗」的處理包成函式。

補充範例 1-1：把購物清單寫進檔案

檔名 write_list.c：

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("shopping.txt", "w");
    if (fp == NULL) {
        printf("無法建立 shopping.txt\n");
        return 1;
    }

    fprintf(fp, "milk 2\n");
    fprintf(fp, "bread 1\n");
    fprintf(fp, "egg 12\n");
    fclose(fp);

    printf("已寫入 3 筆資料\n");
    return 0;
}

螢幕上的輸出：

已寫入 3 筆資料

執行後，shopping.txt 的內容：

milk 2
bread 1
egg 12

一步一步看

  1. fopen("shopping.txt", "w")：以寫入模式開檔。檔案不存在就建立；已經存在就先清空（Beej §9.5）。
  2. 立刻檢查 fp == NULL。失敗時印出訊息並 return 1;，不會對 NULL 繼續操作。
  3. fprintf(fp, ...) 的用法和 printf 幾乎一樣，只是多了第一個參數，指定要寫到哪個檔案。
  4. fclose(fp); 關檔。之後就不能再用這個 fp。
  5. 把這支程式執行兩次，shopping.txt 仍然只有 3 行，因為 "w" 每次都會先清空。

補充範例 1-2：檔案不存在時

檔名 open_check.c：

#include <stdio.h>

int showFirstChar(const char *filename);

int main(void)
{
    if (!showFirstChar("no_such_file.txt")) {
        printf("請確認檔案名稱與存放位置\n");
    }
    printf("程式正常結束\n");
    return 0;
}

int showFirstChar(const char *filename)
{
    FILE *fp = fopen(filename, "r");
    if (fp == NULL) {
        printf("無法開啟 %s\n", filename);
        return 0;
    }

    int c = fgetc(fp);
    printf("第一個字元是 %c\n", c);
    fclose(fp);
    return 1;
}

預期輸出（資料夾中沒有 no_such_file.txt 時）：

無法開啟 no_such_file.txt
請確認檔案名稱與存放位置
程式正常結束

一步一步看

  1. "r" 模式遇到不存在的檔案會開檔失敗，fopen 回傳 NULL。
  2. 函式印出錯誤訊息後 return 0;，下面的 fgetc 和 fclose 都不會執行。
  3. main 根據回傳值給出提示，程式照樣正常結束，不會當掉。
  4. 檔名參數寫成 const char *filename，因為函式只需要讀這個字串（第 12 週）。

2. 讀取文字檔

用白話說

讀檔有三種常見的方式，就像讀一本書時可以「一個字一個字讀」、「一行一行讀」或「一欄一欄填表」：

方式 函式 適合的情況
一次讀一個字元 fgetc 計算字元數、找特定符號
一次讀一行 fgets 逐行處理、需要整行檢查
依格式讀取 fscanf 每行都是固定格式的資料

教材怎麼說

  • fgetc 從檔案讀一個字元。讀到檔案結尾之後再讀，會回傳特別的值 EOF。因為 EOF 不是一般字元，所以 fgetc 的回傳型別是 int，而不是 char。出處：Beej §9.3 End of File: EOF。
  • fgets(陣列, 大小, fp) 從檔案讀一行，會自動在結尾補上空字元；讀到檔案結尾或發生錯誤時回傳 NULL。出處：Beej §9.3.1 Reading a Line at a Time。它和第 9 週從鍵盤讀取時一樣，會把行尾的換行也存進字串。
  • fscanf 用法類似 scanf，但從檔案讀取；它會略過前面的空白，並在檔案結尾或發生錯誤時回傳 EOF。出處：Beej §9.4 Formatted Input。
  • Beej 提醒，用 fgets 讀一行、再用 sscanf 從那一行取出資料，面對格式錯誤的檔案時比較穩健。出處：Beej §9.4；Beej 函式庫參考 §23.11.0.2。

對照練習

練習「單元 2」的基本範例逐行讀回單元 1 寫入的檔案，延伸練習一邊讀一邊計算行數並移除換行。下面的補充範例依序示範三種讀法。

補充範例 2-1：一次讀一個字元

準備資料檔 motto.txt：

Practice makes
progress.

檔名 count_chars.c：

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("motto.txt", "r");
    if (fp == NULL) {
        printf("無法開啟 motto.txt\n");
        return 1;
    }

    int c;
    int chars = 0;
    int lines = 0;

    while ((c = fgetc(fp)) != EOF) {
        chars++;
        if (c == '\n') {
            lines++;
        }
    }
    fclose(fp);

    printf("共 %d 個字元（含換行），%d 行\n", chars, lines);
    return 0;
}

預期輸出：

共 25 個字元（含換行），2 行

一步一步看

  1. (c = fgetc(fp)) != EOF：先把讀到的字元存進 c，再拿 c 和 EOF 比較。Beej 說明這是 C 很常見的寫法，看不懂時由最內層的括號開始拆解（Beej §9.3）。
  2. 第一行 Practice makes 有 14 個字元，加上換行是 15；第二行 progress. 有 9 個字元，加上換行是 10，總共 25。
  3. 每遇到一個 '\n' 就算一行。
  4. c 宣告成 int 而不是 char，因為要能存放 EOF（Beej §9.3）。

補充範例 2-2：一次讀一行，略過空白行

準備資料檔 todo.txt（第 3 行是空白行）：

buy printer ink

return library book
email the TA

檔名 read_lines.c：

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("todo.txt", "r");
    if (fp == NULL) {
        printf("無法開啟 todo.txt\n");
        return 1;
    }

    char line[100];
    int number = 0;

    while (fgets(line, sizeof line, fp) != NULL) {
        if (line[0] == '\n') {
            continue;                  /* 空白行：只有一個換行字元 */
        }
        number++;
        printf("%d. %s", number, line);
    }
    fclose(fp);

    printf("共 %d 項待辦事項\n", number);
    return 0;
}

預期輸出：

1. buy printer ink
2. return library book
3. email the TA
共 3 項待辦事項

一步一步看

  1. 每次 fgets 讀一整行。讀到檔案結尾時回傳 NULL，迴圈結束（Beej §9.3.1）。
  2. 空白行讀進來只有一個換行字元，所以 line[0] == '\n'，用 continue 跳過（第 6 週）。
  3. printf("%d. %s", ...) 的格式字串結尾沒有 \n，因為 line 自己已經帶著換行了。

補充範例 2-3：依格式讀取每一筆資料

準備資料檔 books.txt（每行是「書名代號 頁數」）：

C-Primer 480
Algorithms 320
Networking 256

檔名 read_records.c：

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("books.txt", "r");
    if (fp == NULL) {
        printf("無法開啟 books.txt\n");
        return 1;
    }

    char title[50];
    int pages;
    int count = 0;
    int total = 0;

    while (fscanf(fp, "%49s %d", title, &pages) == 2) {
        printf("%-12s %4d 頁\n", title, pages);
        count++;
        total = total + pages;
    }
    fclose(fp);

    printf("共 %d 本，%d 頁\n", count, total);
    return 0;
}

預期輸出：

C-Primer      480 頁
Algorithms    320 頁
Networking    256 頁
共 3 本，1056 頁

一步一步看

  1. 格式 "%49s %d"：讀一個不含空白的字串，再讀一個整數。%49s 限制最多讀 49 個字元，留一格給結尾的 \0。Beej 提醒，%s 不指定寬度可能讓讀入的資料超出陣列（Beej §9.4）。
  2. title 前面不加 &，因為陣列名稱本身就是位址（第 12 週）；pages 是一般變數，要加 &。
  3. 迴圈條件寫 == 2，表示「兩個欄位都讀成功」才處理。和第 4 週 scanf 一樣，fscanf 回傳成功存入的項目數；遇到格式不符的資料時回傳值會小於 2，迴圈也會停止，不會把錯誤的資料算進去。

動手改改看

  • 在 todo.txt 中多加兩個連續的空白行，補充範例 2-2 的輸出會改變嗎？
  • 在 books.txt 最後加上一行 Database abc，執行補充範例 2-3。迴圈在哪裡停止？總頁數有沒有被影響？

3. 寫入檔案與資料驗證

用白話說

檔案裡的資料可能有錯：數字打錯、欄位少了、數值超出合理範圍。處理檔案資料時，要養成「先驗證，再使用」的習慣：合格的資料照常處理，不合格的資料要記錄下來、給出提示，而不是讓整個程式出錯。

教材怎麼說

  • 寫入文字檔可以使用 fputc（寫一個字元）、fputs（寫一個字串）、fprintf（依格式寫入）。出處：Beej §9.5 Writing Text Files。
  • 用 "a" 模式開檔時，寫入位置在檔案最後面，新資料會接在原本的內容之後；檔案不存在時會自動建立。出處：Beej 函式庫參考 §23.7 fopen()。
  • 對於不可信任的輸入，Beej 建議先整行讀進來，再從字串中取出資料，這比直接用 fscanf 讀取更能應付毀損的檔案。出處：Beej §9.4；Beej 函式庫參考 §23.11.0.2。

對照練習

練習「單元 3」的基本範例把一批溫度寫入檔案，延伸練習讀回來並驗證每筆溫度是否在合理範圍；綜合練習則對濕度記錄做寫入、讀取、驗證與平均。下面的補充範例示範另一種常見的處理流程：讀入原始資料，把合格的資料寫到新檔案，不合格的逐行回報原因。

補充範例 3-1：篩選合格的訂單

準備資料檔 orders.txt（每行是「訂單編號 數量」，數量必須是 1 到 20）：

1001 3
1002 25
1003 abc
1004 7
1005 0

檔名 filter_orders.c：

#include <stdio.h>

int main(void)
{
    FILE *in = fopen("orders.txt", "r");
    if (in == NULL) {
        printf("無法開啟 orders.txt\n");
        return 1;
    }

    FILE *out = fopen("valid_orders.txt", "w");
    if (out == NULL) {
        printf("無法建立 valid_orders.txt\n");
        fclose(in);
        return 1;
    }

    char line[100];
    int lineNo = 0;
    int validCount = 0;

    while (fgets(line, sizeof line, in) != NULL) {
        int id;
        int qty;
        lineNo++;

        if (sscanf(line, "%d %d", &id, &qty) != 2) {
            printf("第 %d 行：格式錯誤，略過\n", lineNo);
            continue;
        }
        if (qty < 1 || qty > 20) {
            printf("第 %d 行：訂單 %d 的數量 %d 超出範圍，略過\n", lineNo, id, qty);
            continue;
        }

        fprintf(out, "%d %d\n", id, qty);
        validCount++;
    }

    fclose(in);
    fclose(out);
    printf("共讀取 %d 行，%d 筆合格\n", lineNo, validCount);
    return 0;
}

螢幕上的輸出：

第 2 行：訂單 1002 的數量 25 超出範圍，略過
第 3 行：格式錯誤，略過
第 5 行：訂單 1005 的數量 0 超出範圍，略過
共讀取 5 行，2 筆合格

執行後，valid_orders.txt 的內容：

1001 3
1004 7

一步一步看

行號 讀到的內容 sscanf 回傳 驗證結果
1 1001 3 2 合格，寫入新檔
2 1002 25 2 數量超過 20
3 1003 abc 1 格式錯誤
4 1004 7 2 合格，寫入新檔
5 1005 0 2 數量小於 1
  1. 同時開了兩個檔案：in 用來讀，out 用來寫。如果 out 開檔失敗，要先把已經開啟的 in 關掉再結束。
  2. sscanf(line, "%d %d", &id, &qty) 的用法和 scanf 一樣，只是資料來源換成字串 line。第 3 行的 abc 讀不成整數，所以只成功存入 1 項。
  3. 因為是先用 fgets 讀整行，就算某一行格式錯誤，下一次 fgets 仍然會從下一行開始，不會卡住。這就是 Beej 建議「先讀整行」的原因。
  4. 兩道驗證都通過，才用 fprintf 寫入新檔。

補充範例 3-2：用附加模式累積紀錄

問題：每次呼叫函式都在記錄檔最後面加一行，不覆蓋舊資料。

檔名 append_log.c：

#include <stdio.h>

int appendLog(const char *filename, const char *message);

int main(void)
{
    FILE *fp = fopen("activity.txt", "w");   /* 先建立一個空的記錄檔 */
    if (fp == NULL) {
        return 1;
    }
    fclose(fp);

    appendLog("activity.txt", "login");
    appendLog("activity.txt", "upload hw13");
    appendLog("activity.txt", "logout");
    printf("記錄完成\n");
    return 0;
}

int appendLog(const char *filename, const char *message)
{
    FILE *fp = fopen(filename, "a");
    if (fp == NULL) {
        printf("無法開啟 %s\n", filename);
        return 0;
    }
    fprintf(fp, "%s\n", message);
    fclose(fp);
    return 1;
}

螢幕上的輸出：

記錄完成

執行後，activity.txt 的內容：

login
upload hw13
logout

一步一步看

  1. main 先用 "w" 開一次再關掉，得到一個空檔案，讓範例每次執行的結果都相同。
  2. appendLog 每次都用 "a" 開檔，寫入位置在檔案最後面，所以三次呼叫的內容依序累積（Beej 函式庫參考 §23.7）。
  3. 如果把 appendLog 裡的 "a" 改成 "w"，每次開檔都會清空，最後檔案裡只剩 logout。

動手改改看

  • 在 orders.txt 加上一行只有 1006 的資料，補充範例 3-1 會如何回報？
  • 修改補充範例 3-1，把不合格的行也寫到另一個檔案 rejected_orders.txt。

本講義未涵蓋的內容

  • Windows 與其他系統在換行字元上的差異：Beej §9.2 提到文字串流可能轉換換行的表示方式，但沒有詳細說明，本講義不展開。
  • 程式執行時的「目前資料夾」如何決定：引用的教材中沒有說明。如果程式找不到資料檔，請確認資料檔和執行程式時所在的資料夾相同，或向授課教師詢問。
  • 二進位檔案（binary file）的讀寫：Beej §9.6 有介紹，本課程不使用。
