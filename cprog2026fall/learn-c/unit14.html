題目：每日飲水紀錄小工具

課程講義用「生活記帳小工具」、練習用「讀書時數記錄小工具」示範。本講義換成另一個題目，讓你看到同樣的流程可以套用在不同的需求上：

使用者每天輸入當天喝了多少毫升的水，最多記錄 14 天。輸入 -1 表示結束。程式要拒絕不合理的數值，最後印出記錄天數、總量、平均，以及有幾天達到每日 2000 毫升的目標。

1. 問題定義與 IPO 分析

用白話說

動手寫程式之前，先回答三個問題：

  • I（Input，輸入）：程式需要哪些資料？從哪裡來？
  • P（Process，處理）：拿到資料後要做什麼計算或判斷？
  • O（Output，輸出）：最後要給使用者看什麼？

另外還要寫下限制：資料的範圍、數量上限、什麼情況算錯誤。限制寫得越清楚，後面的測試計畫就越好寫。

IPO 分析

項目 內容
輸入 每天的飲水量（整數，毫升），從鍵盤輸入；輸入 -1 結束
處理 驗證數值是否合理、存進陣列、計算總量與平均、計算達標天數
輸出 每筆輸入的回饋訊息；結束時的摘要報表
限制 1 每天的飲水量必須在 0 到 5000 毫升之間
限制 2 最多記錄 14 天，記滿後自動結束輸入
限制 3 一筆資料都沒有時，平均要顯示為 0，不能除以 0

對照練習

練習「單元 1」的基本範例把「讀書時數記錄」的構想寫成問題陳述，列出輸入、輸出和限制。上面的表格是同樣的格式套用在飲水紀錄上。

2. 從需求到函式清單

用白話說

把 IPO 表中「處理」的每一件事，拆成一個函式只做一件事。每個函式先寫出原型，決定三件事：叫什麼名字、需要什麼資料、交回什麼結果。

設計時用到的 C 語言規則（有資料依據）

設計決定 依據的規則 出處
先列出所有原型，函式定義放在 main 後面 原型出現在呼叫之前，定義就可以寫在後面 GNU C 手冊 §22.2；Beej §4.2
陣列參數一定搭配一個「筆數」參數 函式拿到的是指標，算不出陣列長度 Beej §6.2、§6.6.2
只讀取陣列的函式，參數加 const const int * 不能透過它修改資料 Beej §16.1.1
需要同時修改陣列與筆數時，筆數用指標參數 指標參數讓函式修改呼叫端變數 Beej §5.4（第 11 週）
「成功與否」用回傳值表示 和 scanf 回傳成功筆數的設計相同 Beej 函式庫參考 §23.11（第 4 週）

函式清單

函式原型 負責的事 參數為什麼這樣設計
int isValidAmount(int ml); 判斷一筆數值是否在 0 到 5000 之間 只需要讀一個數，回傳 1 或 0
int addRecord(int amounts[], int *count, int capacity, int ml); 驗證並加入一筆資料 要修改陣列和筆數，所以陣列不加 const、筆數用指標；回傳 1 表示成功
int totalOf(const int amounts[], int count); 計算總量 只讀取，加 const
double averageOf(const int amounts[], int count); 計算平均，沒有資料時回傳 0 只讀取；回傳 double 保留小數
int daysReachedGoal(const int amounts[], int count, int goal); 計算達標天數 目標值當參數傳入，不寫死在函式裡
void printReport(const int amounts[], int count, int goal); 印出摘要報表 只負責輸出，不回傳
void runSelfTests(void); 用 assert 自動檢查上面的計算函式 見第 3 節

對照練習

練習「單元 2」的基本範例把一個「做太多事」的函式拆開，延伸練習示範新增需求時優先組合既有函式。例如之後想加上「最多的一天喝了多少」，只要新增一個 int maxOf(const int amounts[], int count);，其他函式都不必修改。

3. 撰寫測試計畫

用白話說

測試計畫就是事先寫好：「給這個輸入，應該得到什麼結果」。寫的時候要涵蓋三種情況：

  • 一般情況：最常見的正常資料。
  • 邊界情況：剛好在限制邊緣的資料，例如 0、5000、剛好 14 筆。
  • 錯誤情況：不合理的資料，例如 -5、6000。

測試計畫

編號 測試對象 輸入 預期結果 類型
T1 isValidAmount 1800 1（合格） 一般
T2 isValidAmount 0 1（合格） 邊界
T3 isValidAmount 5000 1（合格） 邊界
T4 isValidAmount 5001 0（不合格） 錯誤
T5 isValidAmount -5 0（不合格） 錯誤
T6 totalOf {1800, 2600, 900} 5300 一般
T7 averageOf 沒有資料（筆數 0） 0.0，不會除以 0 邊界
T8 daysReachedGoal {1800, 2000, 2600}，目標 2000 2（剛好 2000 也算達標） 邊界
T9 addRecord 陣列已滿時再加一筆 回傳 0，筆數不變 邊界

讓測試自動執行：assert

教材怎麼說：assert(條件) 表示「我假設這個條件成立」，條件不成立時程式會以 assertion 失敗立刻結束，並指出是哪一個條件。它通常用在除錯期間，確保沒有發生預料之外的狀況。出處：Beej 函式庫參考 §3.2 assert()。

把測試計畫的每一列寫成一行 assert，每次執行程式時就會自動檢查一遍（第 15 週補充範例 3-3 介紹過 assert）。只要有一項不符合，程式就會立刻停下來，並告訴你是哪一行。

對照練習

練習「單元 3」的基本範例從一個函式的 IPO 直接寫出測試表，延伸練習示範限制改變時測試計畫也要跟著補。上面的 T8 就是一個容易漏掉的邊界：「剛好等於目標」算不算達標，必須在 IPO 的限制中先講清楚。

4. 雛型程式

對照練習

練習「單元 4」提供讀書時數記錄小工具的完整設計文件與雛型骨架。下面是飲水紀錄小工具的對應版本，程式開頭先執行自我測試，通過之後才開始接受輸入。

檔名 water_log.c：

#include <stdio.h>
#include <assert.h>

int isValidAmount(int ml);
int addRecord(int amounts[], int *count, int capacity, int ml);
int totalOf(const int amounts[], int count);
double averageOf(const int amounts[], int count);
int daysReachedGoal(const int amounts[], int count, int goal);
void printReport(const int amounts[], int count, int goal);
void runSelfTests(void);

int main(void)
{
    const int GOAL = 2000;
    int amounts[14];
    int capacity = sizeof amounts / sizeof amounts[0];
    int count = 0;
    int ml;

    runSelfTests();

    while (count < capacity) {
        printf("第 %d 天喝了多少毫升（-1 結束）：", count + 1);
        if (scanf("%d", &ml) != 1) {
            printf("讀取失敗，結束輸入\n");
            break;
        }
        if (ml == -1) {
            break;
        }
        if (addRecord(amounts, &count, capacity, ml)) {
            printf("  已記錄\n");
        } else {
            printf("  %d 不在 0 到 5000 之間，請重新輸入\n", ml);
        }
    }

    printReport(amounts, count, GOAL);
    return 0;
}

int isValidAmount(int ml)
{
    return ml >= 0 && ml <= 5000;
}

int addRecord(int amounts[], int *count, int capacity, int ml)
{
    if (*count >= capacity || !isValidAmount(ml)) {
        return 0;
    }
    amounts[*count] = ml;
    *count = *count + 1;
    return 1;
}

int totalOf(const int amounts[], int count)
{
    int total = 0;
    for (int i = 0; i < count; i++) {
        total = total + amounts[i];
    }
    return total;
}

double averageOf(const int amounts[], int count)
{
    if (count == 0) {
        return 0.0;
    }
    return (double)totalOf(amounts, count) / count;
}

int daysReachedGoal(const int amounts[], int count, int goal)
{
    int days = 0;
    for (int i = 0; i < count; i++) {
        if (amounts[i] >= goal) {
            days++;
        }
    }
    return days;
}

void printReport(const int amounts[], int count, int goal)
{
    printf("====== 飲水紀錄摘要 ======\n");
    printf("記錄天數：%d 天\n", count);
    printf("總飲水量：%d 毫升\n", totalOf(amounts, count));
    printf("平均每天：%.1f 毫升\n", averageOf(amounts, count));
    printf("達標天數：%d 天（目標 %d 毫升）\n", daysReachedGoal(amounts, count, goal), goal);
}

void runSelfTests(void)
{
    int sample[3] = {1800, 2600, 900};
    int border[3] = {1800, 2000, 2600};
    int full[2] = {100, 200};
    int fullCount = 2;

    assert(isValidAmount(1800) == 1);                        /* T1 */
    assert(isValidAmount(0) == 1);                           /* T2 */
    assert(isValidAmount(5000) == 1);                        /* T3 */
    assert(isValidAmount(5001) == 0);                        /* T4 */
    assert(isValidAmount(-5) == 0);                          /* T5 */
    assert(totalOf(sample, 3) == 5300);                      /* T6 */
    assert(averageOf(sample, 0) == 0.0);                     /* T7 */
    assert(daysReachedGoal(border, 3, 2000) == 2);           /* T8 */
    assert(addRecord(full, &fullCount, 2, 300) == 0);        /* T9 */
    assert(fullCount == 2);                                  /* T9 */

    printf("自我測試全部通過\n");
}

設計追蹤表（第一次執行範例）

輸入 addRecord 回傳 count 陣列內容 畫面回饋
1800 1 1 {1800} 已記錄
2600 1 2 {1800, 2600} 已記錄
6000 0 2 不變 不在範圍內
900 1 3 {1800, 2600, 900} 已記錄
2100 1 4 {1800, 2600, 900, 2100} 已記錄
-1 不呼叫 4 不變 結束輸入

最後：總量 1800 + 2600 + 900 + 2100 = 7400，平均 7400 / 4 = 1850.0，達到 2000 毫升的是 2600 和 2100 兩天。

程式碼亮點

  1. 陣列長度只寫一次：capacity = sizeof amounts / sizeof amounts[0] 在宣告陣列的 main 裡計算，再以參數傳給需要的函式（Beej §6.2，第 8 週）。
  2. addRecord 同時修改兩樣東西：陣列透過陣列參數修改（Beej §6.6.3），筆數透過指標參數 int *count 修改（Beej §5.4）。
  3. averageOf 先檢查 count == 0：對應 IPO 的限制 3，也是測試計畫 T7 驗證的內容。
  4. 輸入錯誤不會讓程式當掉：scanf 的回傳值不是 1 時，結束輸入並照常印出報表（Beej 函式庫參考 §23.11，第 4 週）。
  5. 測試跟著程式一起跑：runSelfTests 把測試計畫變成 assert，之後修改任何計算函式，只要重新執行就能立刻知道有沒有改壞。

動手改改看

  • 把 isValidAmount 的 ml <= 5000 故意改成 ml < 5000，重新編譯執行。程式在哪一行停下來？訊息指出的是測試計畫的哪一項？
  • 新增「最多的一天」功能：先在測試計畫加一列（例如 {1800, 2600, 900} 應該得到 2600），寫成 assert，再完成 int maxOf(const int amounts[], int count);。

5. 專題自我檢核清單

為自己的專題準備設計文件時，可以逐項確認：

  • IPO 表中每一項「限制」，是否都至少對應到測試計畫中的一列？
  • 每個函式是否只做一件事？能不能用一句話說出它負責什麼？
  • 只讀取資料的陣列參數，是否都加上了 const？（第 12 週）
  • 每個陣列參數旁邊，是否都有一個說明筆數的參數？（第 12 週）
  • 會用到除法的地方，是否處理了除數為 0 的情況？（第 15 週）
  • 讀取輸入或開檔的地方，是否都檢查了回傳值？（第 4、14 週）
  • 測試計畫是否包含一般、邊界、錯誤三種情況？
