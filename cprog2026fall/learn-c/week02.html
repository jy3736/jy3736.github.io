本週使用的編譯指令

使用 Windows 電腦的同學，請先依照〈在 Windows 用 WSL 寫 C 程式〉完成環境設定，再開始本週的內容。

和練習檔一致，本講義的範例都用下面這行指令編譯（把 檔名 換成你的檔案名稱）：

gcc -std=c17 -Wall -Wextra -Wpedantic 檔名.c -o 檔名

1. 編譯：把我們寫的文字變成電腦能執行的程式

用白話說

我們寫的 C 程式，一開始只是一個存在電腦裡的文字檔。電腦沒辦法直接看懂這些文字，需要一個叫做編譯器的工具，把文字翻譯成電腦能執行的檔案。翻譯完成後，才能「執行」這個程式。

教材怎麼說

  • C 是一種編譯式語言。編譯器會把 C 的程式文字翻譯成機器能理解的二進位碼，也就是可執行檔（executable）。出處：Modern C §1.2 Compiling and running（PDF 第 16 頁）。
  • 翻譯時分成兩個階段：先由前置處理器（preprocessor）處理以 # 開頭的行，再由編譯器產生可執行檔。出處：Beej's Guide §2.2 Hello, World!。
  • 產生的是 CPU 可以直接執行的機器碼，這也是 C 程式通常執行得很快的原因之一。出處：Beej §2.3 Compilation Details。
  • 用 gcc -o hello hello.c 可以把 hello.c 編譯成名為 hello 的程式，-o 的意思是「輸出到這個檔案」。出處：Beej §2.4 Building with gcc。
  • 執行程式的方式，是在終端機輸入程式的檔名當作指令，例如 ./hello。出處：GNU C 手冊 §2.4 Compiling the Example Program。

編譯指令拆開來看

片段 意思 出處
gcc 編譯器程式的名稱 GNU C 手冊 §2.4
-std=c17 指定使用 C17 標準 Modern C §1.2 用 -std=c2x 示範同類選項（PDF 第 17 頁）
-Wall 請編譯器對任何不尋常的寫法提出警告 Modern C §1.2（PDF 第 17 頁）
檔名.c 要翻譯的原始檔，.c 代表 C 語言 Modern C §1.2（PDF 第 17 頁）
-o 檔名 翻譯完的程式要存成什麼名字 Beej §2.4

-Wextra、-Wpedantic 會再多開啟一些警告。本講義在引用的教材中沒有找到這兩個選項的詳細說明，這裡依照練習檔的慣例使用。

對照練習

練習「單元二：編譯流程」要你實際跑一次「寫程式、編譯、執行」。做那個練習時，可以對照上面的表格，確認指令中每個片段的作用。

補充範例 1-1：同一個程式，換個名字

目的：觀察 -o 決定了程式的名字。

檔名 greet.c：

#include <stdio.h>

int main(void)
{
    printf("編譯成功！\n");
    return 0;
}

分別執行下面兩組指令：

gcc -std=c17 -Wall -Wextra -Wpedantic greet.c -o greet
./greet
gcc -std=c17 -Wall -Wextra -Wpedantic greet.c -o hi
./hi

預期輸出（兩次都一樣）：

編譯成功！

一步一步看

  1. 第一次編譯產生名為 greet 的程式，第二次產生名為 hi 的程式。
  2. 兩個程式都從同一個 greet.c 翻譯而來，所以執行結果相同。
  3. 如果修改了 greet.c 卻沒有重新編譯，執行的仍然是舊的程式。因為執行的是翻譯後的檔案，不是原始的文字檔。

2. hello.c 逐行解讀

教材怎麼說

以練習「單元三」的基本範例為例，把每一行對照資料：

#include <stdio.h>

int main(void)
{
    printf("計算機程式及實習\n");
    return 0;
}
程式片段 作用 出處
#include <stdio.h> 請前置處理器把 stdio.h 這個檔案的內容放進來。stdio.h 是「標準輸入輸出」的標頭檔（header file），printf 就是在這裡面宣告的 Beej §2.2
int main(void) 每個完整的程式至少要有一個 main 函式，程式從這裡開始執行。括號裡的 void 表示 main 不使用任何引數 GNU C 手冊 §22.6 The main Function
{ 和 } 大括號把屬於 main 的敘述包在一起 Beej §3.3.1（說明大括號把多行程式碼組成一個區塊）
printf(...) 把雙引號裡的文字印到螢幕上 Beej §2.2
\n 換行 Beej §2.2
return 0; 讓 main 結束，並回傳結束狀態 0 Beej §28.1.1 Returning From main()

關於 return 0;：Beej §28.1.1 說明，main 有一個特例，就算執行到結尾沒有寫 return，效果也等同回傳 0；這個特例只適用於 main。本課程的範例一律明確寫出 return 0;，讓每支程式的結束點清楚可見。

註解：寫給人看的說明

  • 夾在 /* 和 */ 之間的文字，以及一行中 // 之後的文字，都是註解，編譯器會完全忽略。註解是寫給未來的自己和其他人看的。出處：Beej §2.2。

補充範例 2-1：一次印出多行

目的：觀察 \n 決定換行的位置，而不是 printf 本身。

檔名 card.c：

#include <stdio.h>

int main(void)
{
    /* 這是註解：編譯器會忽略這一段 */
    printf("姓名：王小明\n");
    printf("系級：電機一甲\n");
    printf("興趣：");          // 這一行沒有 \n
    printf("打籃球\n");
    return 0;
}

預期輸出：

姓名：王小明
系級：電機一甲
興趣：打籃球

一步一步看

  1. 前兩個 printf 的文字結尾都有 \n，所以各自佔一行。
  2. 第三個 printf 印出「興趣：」後沒有換行，第四個 printf 的「打籃球」就緊接在同一行後面。
  3. 兩種註解（/* */ 與 //）都沒有出現在輸出中。

補充範例 2-2：一個 printf 印出多行

目的：\n 可以放在文字中間的任何位置。

檔名 lines.c：

#include <stdio.h>

int main(void)
{
    printf("第一行\n第二行\n第三行\n");
    return 0;
}

預期輸出：

第一行
第二行
第三行

動手改改看

  • 把補充範例 2-1 第四個 printf 的 \n 刪掉，重新編譯並執行。終端機的提示字元出現在哪裡？
  • 把 #include <stdio.h> 整行刪掉再編譯，閱讀編譯器輸出的訊息，找找看訊息裡有沒有提到 printf。

3. 編譯器警告：程式可以跑，不代表沒問題

教材怎麼說

  • 自己寫程式時，常常會寫出只有部分正確、或結果不可靠的程式。Modern C 示範用 -Wall 編譯一支有問題的程式，編譯器會輸出診斷訊息（diagnostic），指出可疑的地方。出處：Modern C §1.2（PDF 第 17、18 頁）。
  • GNU C 手冊也提醒：除非確定程式是正確的，否則應該預期需要除錯。出處：GNU C 手冊 §2.4。

補充範例 3-1：看懂一則警告

目的：故意少給 printf 一個資料，觀察警告訊息。

檔名 warn.c：

#include <stdio.h>

int main(void)
{
    printf("我今年 %d 歲\n");
    return 0;
}

編譯時會看到類似下面的警告（實際文字依編譯器版本不同而略有差異）：

warn.c:5:24: warning: more '%' conversions than data arguments [-Wformat-insufficient-args]

一步一步看

  1. %d 的意思是「這裡要放一個整數」，這個寫法會在第 4 週詳細介紹。
  2. 程式裡寫了 %d，卻沒有提供要放進去的整數，所以編譯器發出警告。
  3. warn.c:5:24 表示問題出現在 warn.c 的第 5 行、第 24 欄附近（中文字會佔用多個欄位）。
  4. 有警告時，編譯器仍可能產生可執行檔，但印出的數字是不可靠的。把 printf 改成 printf("我今年 %d 歲\n", 19); 後重新編譯，警告就會消失。
