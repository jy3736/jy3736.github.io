01 關於陣列的宣告與使用，下列敘述哪些正確？

  1. 宣告時在名稱後面寫 [長度]，例如 double a[5];
  2. 陣列的第 N 格寫成 a[N]，可以讀出它的值，也可以存入新的值
  3. 宣告陣列時一定要同時寫出每一格的值，否則無法編譯
  4. 每一格用起來和一般的變數完全一樣

02 關於用大括號給陣列初始值，下列敘述哪些正確？

  1. 大括號裡的個數必須和陣列長度完全相同，否則無法編譯
  2. 大括號裡的第一個值會放進索引 1 的那一格
  3. 初始值的個數少於陣列長度時，其餘的格子會自動設為 0
  4. 初始值的個數多於陣列長度時，編譯器會發出警告

03 執行下列程式片段後，下列敘述哪些正確？

int temps[5] = {24, 27, 22, 30, 26};
temps[3] = 31;
printf("%d\n", temps[0] + temps[3]);
  1. 螢幕上印出 55
  2. temps[3] 原本的 30 被換成 31
  3. 螢幕上印出 54
  4. 這段程式會把陣列的每一格都改成 31

04 在 double 佔 8 位元組的電腦上，double prices[6]; 這個陣列整體佔用多少位元組？

  1. 8
  2. 14
  3. 48
  4. 6

05 關於用 sizeof 算出陣列有幾格的作法，下列敘述哪些正確？

  1. C 會自動記錄陣列的長度，所以這個作法沒有必要
  2. 把「整個陣列的位元組數」除以「一格的位元組數」就得到格數
  3. 這個作法只能用在整數陣列
  4. 把陣列傳給函式之後，這個作法就不管用了

06 關於用 for 迴圈走訪陣列，下列敘述哪些正確？

  1. 可以把索引換成迴圈變數，例如寫成 steps[i]
  2. 迴圈變數必須從 1 開始才不會超出範圍
  3. 走訪 4 格的陣列時條件寫成小於 4，最後一次的迴圈變數是 3
  4. 讓迴圈變數從 0 跑到「長度減 1」，就能一格一格處理整個陣列

07 想把使用者輸入的整數存進 numbers 陣列的第 i 格。下列敘述哪些正確？

  1. 和一般變數一樣要加 &，寫成 scanf("%d", &numbers[i]);
  2. &numbers[i] 是第 i 格的位址
  3. 陣列的格子不需要 &，直接把格子本身交給 scanf 就可以
  4. 陣列不能用 scanf 讀入，只能在宣告時用大括號給值

08 執行下列程式片段後，下列敘述哪些正確？

int list[4] = {9, 5, 7, 2};
for (int i = 3; i >= 0; i--) {
    printf("%d ", list[i]);
}
  1. 印出的順序是 9 5 7 2
  2. 印出的順序是 2 7 5 9
  3. 迴圈一次都不會執行
  4. 迴圈依序處理的索引是 3、2、1、0

09 執行下列程式片段後，下列敘述哪些正確？

const int WEEKS = 3;
int hours[3] = {12, 9, 15};
int total = 0;
for (int i = 0; i < WEEKS; i++) {
    total = total + hours[i];
}
printf("%.1f\n", (double)total / WEEKS);
  1. total 最後是 36
  2. 螢幕上印出 12.0
  3. 把長度集中放在一個常數裡，長度要改時只需要改一個地方
  4. 螢幕上印出 12.5

10 算平均時把式子寫成 (double)total / DAYS。關於這個寫法，下列敘述哪些正確？

  1. 它會把 total 這個變數本身永久變成浮點數
  2. 它會讓陣列自動多出一格
  3. 它讓相除時以浮點數的方式計算
  4. 它可以避免整數除法把小數部分去掉

11 執行下列程式片段後，下列敘述哪些正確？

int record[5] = {5100, 9200, 7600, 10500, 8000};
int reach = 0;
for (int i = 0; i < 5; i++) {
    if (record[i] >= 8000) {
        reach++;
    }
}
  1. reach 最後是 3
  2. reach 最後是 2
  3. 值剛好等於 8000 的那一格也算符合條件
  4. 迴圈只會檢查前兩格

12 執行下列程式片段後，下列敘述哪些正確？

int checkedIn[5] = {14, 6, 29, 3, 18};
int position = -1;
for (int i = 0; i < 5; i++) {
    if (checkedIn[i] == 29) {
        position = i;
        break;
    }
}
  1. position 最後是 3
  2. position 最後是 2
  3. position 最後仍然是 -1
  4. 找到之後就離開迴圈，不再檢查後面的格子

13 在陣列中搜尋某個值之前，先把記錄位置的變數設成 -1。下列敘述哪些正確？

  1. 索引不可能是負數，所以 -1 可以用來代表「還沒找到」
  2. -1 表示要從陣列的最後一格開始往前找
  3. 整個陣列都比對失敗時，這個變數會維持 -1
  4. 設成 -1 之後，迴圈會自動跳過第 0 格

14 要記錄一週七天的步數。關於「用陣列」而不是「宣告七個各自命名的變數」，下列敘述哪些正確？

  1. 陣列的每一格可以放不同型別的資料
  2. 整排資料共用一個名字，每一格用索引區分
  3. 陣列可以用迴圈一格一格處理
  4. 用陣列之後就不必在意索引的範圍

15 關於使用超出範圍的索引，下列敘述哪些正確？

  1. 讀到的值一定是 0
  2. C 語言不會檢查索引是否在合法範圍內
  3. 程式會去存取陣列以外的記憶體
  4. 確保只使用合法的索引，是寫程式的人自己的責任

16 某支程式宣告了一個 5 格的整數陣列 scores，並在程式中直接寫出 scores[5]。下列敘述哪些正確？

  1. 這個索引已經超出陣列
  2. 索引 5 剛好是第 5 格，完全合法
  3. 陣列會自動加長一格來容納它
  4. 這個陣列的最後一格要寫成 scores[4]

17 讀取超出陣列結尾的格子屬於未定義行為。下列敘述哪些正確？

  1. 可能讀到 0，也可能讀到亂七八糟的數字
  2. 編譯器一定會發出警告
  3. 也可能讓程式當掉
  4. 索引是變數（例如迴圈變數）時，編譯器通常看不出來

18 走訪陣列時，為什麼要特別檢查迴圈條件寫的是「小於長度」而不是「小於或等於長度」？

  1. 這樣迴圈才會從 0 開始
  2. 寫成「小於或等於長度」會多存取一格，超出陣列的範圍
  3. 兩種寫法完全相同，只是習慣不同
  4. 寫成「小於或等於長度」會讓程式無法編譯

19 一個 7 格的陣列依序存放第 1 天到第 7 天的紀錄。日常說的「第幾天」和索引之間的關係是什麼？

  1. 兩者相同，「第 3 天」就是索引 3
  2. 「第幾天」要加 1 才是索引
  3. 索引和「第幾天」沒有固定的關係
  4. 「第幾天」要減 1 才是索引

20 執行下列程式片段後，下列敘述哪些正確？

int score[6] = {70, 88, 95, 60, 100, 82};
int high = 0;
for (int i = 0; i < 6; i++) {
    if (score[i] >= 90) {
        high = high + score[i];
    }
}
  1. high 最後是 195
  2. 只有索引 2 和索引 4 的值被加進 high
  3. high 最後是 283
  4. 陣列每一格的值都會被加進 high
