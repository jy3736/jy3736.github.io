01 下列關於寫 C 程式時常見名詞的敘述，哪些正確？

  1. 終端機是用「打字輸入指令」來操作電腦的視窗
  2. Ubuntu 是 Windows 內建的程式編輯器
  3. sudo 讓指令以系統管理員身分執行，執行前會要求輸入密碼
  4. WSL 是一種必須另外購買的虛擬機器軟體

02 下列關於在 Windows 上安裝 WSL 步驟的敘述，哪些正確？

  1. 安裝指令要在 Ubuntu 視窗中輸入
  2. 在開始選單的 PowerShell 上按滑鼠右鍵，選擇「以系統管理員身分執行」
  3. 安裝過程不需要網路連線
  4. 安裝完成後，需要重新啟動電腦

03 小凱輸入 wsl --install 後，畫面只出現一大段英文說明文字，沒有開始安裝。下列哪一種判斷與處理最合適？

  1. 代表電腦不支援 WSL，只能改用雙系統
  2. 代表網路中斷，應拔掉網路線後再試一次
  3. 代表電腦已經裝過 WSL 的部分功能，先用 wsl --list --online 查看可安裝的系統，再輸入 wsl --install -d Ubuntu
  4. 代表需要先在 Ubuntu 中執行更新套件的指令

04 想確認自己的 Windows 版本與組建編號，下列哪一種做法可以做到？

  1. 按 Windows 鍵 + R 開啟「執行」視窗，輸入 winver 後按 Enter
  2. 開啟 VS Code，查看視窗左下角的狀態列
  3. 打開 Windows 檔案總管，查看「本機」的磁碟容量
  4. 開啟 Ubuntu，閱讀第一次啟動時的歡迎訊息

05 小美的 Ubuntu 使用者名稱是 student，但她忘記了 Ubuntu 的密碼。下列哪些是重設密碼過程中正確的操作？

  1. 重新安裝 Windows，讓 Ubuntu 帳號恢復成預設值
  2. 在 Ubuntu 中輸入 clear 清除舊密碼
  3. 開啟 PowerShell，輸入 wsl -u root 以最高權限進入 Ubuntu
  4. 輸入 passwd student，依照提示輸入兩次新密碼

06 在 Ubuntu 中輸入 gcc --version，畫面第一行顯示 gcc (Ubuntu 12.3.0-1ubuntu1~22.04) 12.3.0。下列敘述哪些正確？

  1. 這代表 C 編譯器已經可以使用
  2. 版本數字和別人電腦上看到的不同，並不影響使用
  3. 版本必須剛好是 13.3.0，否則無法編譯 C 程式
  4. 這代表 VS Code 已經成功連線到 Ubuntu

07 使用者名稱為 student，且 /home/student/cprog/week02 資料夾已存在。在 Ubuntu 中依序輸入 cd ~、cd cprog/week02、cd ..，最後輸入 pwd。畫面會顯示哪一個位置？

  1. /home/student
  2. /home/student/cprog/week02
  3. /mnt/c/Users/student
  4. /home/student/cprog

08 程式檔存放在 WSL 的 Linux 檔案系統中。想用 Windows 檔案總管查看這些檔案，下列哪些做法可行？

  1. 直接到 Windows 的「文件」資料夾尋找
  2. 在 Ubuntu 中切換到該資料夾，輸入 explorer.exe .
  3. 在 Windows 檔案總管的網址列輸入 \\wsl$
  4. 在 Ubuntu 中輸入 cd ~，檔案總管就會自動開啟

09 下列關於安裝 VS Code 並讓它搭配 WSL 使用的敘述，哪些正確？

  1. VS Code 要安裝在 Windows 這一邊
  2. 應在 Ubuntu 中用 sudo apt install code 把 VS Code 裝在 Linux 裡
  3. 安裝時要取消勾選「加入 PATH」，以免和 Ubuntu 發生衝突
  4. 在 VS Code 的擴充功能面板搜尋並安裝由 Microsoft 發布的 WSL 擴充功能

10 VS Code 已在 WSL 模式下開啟。從選單選擇「終端機 → 新增終端機」後開啟的終端機，下列敘述何者正確？

  1. 它是 Windows 的 PowerShell，無法使用 Linux 指令
  2. 它直接在 Ubuntu 中執行，可以在裡面用 gcc 編譯程式
  3. 每次開啟都必須重新安裝 C 編譯器
  4. 它只能顯示程式的輸出，不能輸入任何指令

11 第三週上課時，小玉開啟 Ubuntu，但家目錄下的 cprog 裡還沒有 week03 資料夾。下列哪一組操作順序最合適？

  1. 先輸入 code .，再輸入 cd ~/cprog/week03，最後才建立資料夾
  2. 先輸入 cd ~/cprog/week03，出現錯誤後直接開始寫程式
  3. 先輸入 mkdir -p ~/cprog/week03，再輸入 cd ~/cprog/week03，最後輸入 code .
  4. 先在 Windows 桌面建立 week03 資料夾，再用 VS Code 直接開啟桌面

12 阿翔輸入 ./lab1 後，終端機顯示「No such file or directory」。下列哪些是可能的原因？

  1. 編譯沒有成功，所以沒有產生 lab1 這個檔案
  2. 目前所在的資料夾不是程式所在的資料夾
  3. VS Code 的佈景主題設定成深色模式
  4. Ubuntu 的密碼輸入錯誤太多次

13 下列關於寫程式時看待編譯器診斷訊息的態度，哪些正確？

  1. 只要程式能執行，就可以忽略編譯器顯示的所有訊息
  2. 自己寫的程式通常第一次就完全正確，不必預期除錯
  3. 自己寫程式時常會寫出只有部分正確的程式，診斷訊息能指出可疑的地方
  4. 除非確定程式是正確的，否則應該預期需要除錯

14 C 程式從文字檔翻譯成可執行檔時分成兩個階段。下列哪一項正確描述這兩個階段？

  1. 編譯器先產生可執行檔，前置處理器再處理以 # 開頭的行
  2. 整個翻譯只有一個階段，由前置處理器獨自完成
  3. 前置處理器負責執行程式，編譯器負責顯示輸出
  4. 前置處理器先處理以 # 開頭的行，再由編譯器產生可執行檔

15 下列關於編譯指令中各個片段的敘述，哪些正確？

  1. gcc 是要翻譯的原始檔名稱
  2. -std=c17 指定使用 C17 標準
  3. -Wall 會關閉編譯器的所有警告
  4. -Wall 請編譯器對任何不尋常的寫法提出警告

16 小華把同一個 greet.c 編譯兩次：第一次用 gcc -std=c17 -Wall -Wextra -Wpedantic greet.c -o greet，第二次用 gcc -std=c17 -Wall -Wextra -Wpedantic greet.c -o hi，兩次都成功。下列敘述哪些正確？

  1. 同一個原始檔可以編譯出名稱不同的程式
  2. hi 必須從名為 hi.c 的原始檔才能編譯出來
  3. 執行 greet 與執行 hi，輸出的結果相同
  4. 兩個程式的輸出不同，因為程式名稱不同

17 main 中有下列敘述（\n 表示換行）。執行後會在螢幕上印出幾行文字？

printf("甲\n乙\n丙\n");
  1. 三行
  2. 一行
  3. 兩行
  4. 四行

18 main 中有下列敘述。下列敘述哪些正確？

printf("一");   // 第一段
/* printf("二"); */
printf("三\n");
  1. 螢幕上會印出「一二三」
  2. 「// 第一段」這段文字會被編譯器忽略
  3. 螢幕上會印出「一三」
  4. 註解文字「第一段」也會出現在螢幕上

19 下列關於 C 程式中 main 函式與大括號的敘述，哪些正確？

  1. 程式從 main 函式開始執行
  2. 一個完整的程式可以完全沒有 main 函式
  3. 大括號用來標示註解的範圍
  4. 大括號把屬於 main 的敘述包在一起

20 main 中有下列敘述，編譯時出現警告。下列敘述哪些正確？

printf("身高 %d 公分\n");
  1. 警告是因為 printf 的文字中不能出現中文字
  2. %d 表示這裡要放一個整數，但敘述中沒有提供，所以編譯器發出警告
  3. 出現警告時，編譯器已自動補上整數 0，輸出一定是「身高 0 公分」
  4. 把敘述改成 printf("身高 %d 公分\n", 170); 後重新編譯，警告就會消失
