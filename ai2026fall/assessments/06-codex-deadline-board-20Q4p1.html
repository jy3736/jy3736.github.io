課前前測：Codex 截止日看板

20 題單選。可選「逐題檢查」，每題選好就按「檢查答案」；或選「全部一次檢查」，全部作答後按「全部檢查」一次批改。答錯可以再試，試過 2 個不同的錯誤答案後才能看答案。答對 60% 以上的題目（看答案的不算）後，可以下載含答案的 HTML 檔。作答紀錄不會保存，重新整理或離開頁面後會從頭開始。

01 某截止日清單的每一筆資料都記錄了科目、名稱、類型與截止日四個欄位，其中類型只允許三種值。下列哪一組符合這個規定？

  1. 作業、考試、報告
  2. 作業、專題、複習
  3. 作業、小考、練習
  4. 考試、報告、預習

02 某工具規定「還剩幾天」要從一個指定的日期算起。若執行指令時沒有指定這個日期，工具應該怎麼處理？

  1. 停止執行，並要求使用者補上這個日期
  2. 改用執行當天的日期
  3. 改用資料中最早的那個截止日
  4. 改用資料中最晚的那個截止日

03 某看板工具堅持讓使用者在指令上指定天數的起算日，而不是一律使用今天。這樣做最重要的好處是什麼？

  1. 可以讓工具執行得更快
  2. 可以讓頁面上顯示更多欄位
  3. 同一份資料配同一個起算日，每次都會產生一模一樣的一頁，才分得出差異的來源
  4. 可以省下讀取資料檔的步驟

04 某看板規定剩餘天數 1 到 3 天分到緊急區、4 到 7 天分到本週區、8 天以上分到之後區，邊界一律照字面計算。剩餘天數剛好 7 天的項目應該分到哪一區？

  1. 緊急
  2. 之後
  3. 已過期
  4. 本週

05 某看板上，截止日剛好等於這次天數起算日的項目，必須用一段固定的文字呈現。那段文字是什麼？

  1. 今天到期
  2. 剩 0 天
  3. 逾期 0 天
  4. 剩不到一天

06 某看板要求每一區內的項目順序固定不變。當同一區裡兩個項目的剩餘天數相同時，應該依什麼決定先後？

  1. 依項目名稱的字數多寡
  2. 依科目名稱
  3. 依項目的類型
  4. 依它們在資料檔中出現的先後

07 某看板共有已過期、緊急、本週、之後四個區塊。這四區在頁面上一律照哪一個順序出現？

  1. 緊急 → 本週 → 之後 → 已過期
  2. 之後 → 本週 → 緊急 → 已過期
  3. 已過期 → 緊急 → 本週 → 之後
  4. 已過期 → 本週 → 緊急 → 之後

08 某看板的其中一個分區剛好沒有任何項目。頁面應該怎麼處理這一區？

  1. 直接省略這一區，不顯示出來
  2. 用鄰近分區的項目補滿這一區
  3. 把這一區改成灰色，並且不寫任何文字
  4. 仍然列出這一區，並在裡面寫「沒有項目」

09 某看板頁面最上面除了標題「截止日看板」之外，還必須讓人看到哪一項資訊？

  1. 這次計算所使用的天數起算日
  2. 資料檔的完整路徑與檔案大小
  3. 製作這個工具的人的姓名
  4. 各個科目的任課教師名單

10 某看板工具用同一份資料與同一個起算日連續執行兩次。對這兩次產生的頁面應有什麼要求，以及由此衍生的限制是什麼？

  1. 允許不同，因為兩次執行的時刻不一樣
  2. 必須完全相同，所以頁面上不能放每次都會變動的內容
  3. 只要項目數量相同，排序可以不一樣
  4. 只要分區數量相同，項目內容可以不一樣

11 驗收某看板工具時，有一個步驟是先把網路連線關掉，再執行一次並打開產生的頁面。這個步驟要確認的是什麼？

  1. 資料檔沒有被其他人修改過
  2. 終端機的字型顯示正確
  3. 不必連網就能產生頁面，而且打開後版面也正常
  4. 起算日會自動更新為最新的日期

12 某看板工具每執行一次，除了產生頁面之外，還要在終端機上輸出一項訊息。那應該是什麼？

  1. 每一筆資料的完整內容
  2. 程式碼的行數統計
  3. 產生這一頁所花的毫秒數
  4. 一行摘要，說明四個分區各有幾項

13 某看板的資料共有 7 筆，在某個起算日下四個分區的項目數分別是 1、2、2、2。驗收時把四區的項目數加起來核對，最主要是為了確認什麼？

  1. 合計與資料筆數一致，沒有漏算也沒有重複計算
  2. 四個分區的門檻設定得剛好平均
  3. 這份資料的品質比其他資料更好
  4. 頁面上的字體大小設定正確

14 想測試某看板工具遇到 2026-13-45 這種不存在的日期時會怎麼反應。下列哪一種做法最恰當？

  1. 直接修改原始資料檔，測完之後再改回來
  2. 複製一份副本，只在副本裡改成這個日期並對副本執行，原始資料檔保持不動
  3. 把那一筆資料從原始資料檔刪掉之後再執行
  4. 自己先手算那一筆的天數，不必真的執行工具

15 某工具讀進來的清單中，有一筆的日期格式不正確。這時工具應該有什麼行為？

  1. 自動猜一個最接近的合理日期填進去
  2. 默默跳過那一筆，其餘照常產生結果
  3. 用看得懂的話指出是哪一筆有問題，不自己猜也不默默跳過
  4. 把整份資料改寫成正確格式之後再繼續

16 某練習的工作資料夾裡附了一份現成的實作。開始練習之前，先執行下面這行指令把它移除，並另外留下一個版本控制的存檔點。這樣安排最主要的理由是什麼？

git rm -q -r src test build.mjs
  1. 那份現成的實作含有錯誤，不刪掉就無法執行
  2. 那份現成的實作會讓工具執行的速度變慢
  3. 那份現成的實作佔用了太多磁碟空間
  4. 練習的重點是自己把需求講清楚，而原本的檔案仍留在存檔點裡，隨時取得回來

17 有人想同時把兩個不同的修改要求交辦給 AI 工具，於是改用工作副本（worktree）的方式進行。這主要是為了解決什麼問題？

  1. 兩個對話若同時修改同一個資料夾，會改到彼此的檔案，分不清哪個修改是誰做的
  2. 工作副本可以讓兩個對話共用同一份修改紀錄
  3. 工作副本可以讓工具跳過所有自動檢查
  4. 工作副本可以自動把兩個要求合併成一個

18 在編輯器中以某個分支為基礎建立工作副本（worktree）之前，必須先把手上的修改提交。原因是什麼？

  1. 建立工作副本的動作會刪除尚未提交的修改
  2. 工作副本只包含已經提交的檔案，未提交的修改不會跟過去
  3. 未提交的檔案會在工作副本中被自動改名
  4. 不先提交就無法在清單中選擇基礎分支

19 在某個工作副本上建立了一個分支之後，本機就無法再切換到同一個分支。若想在本機檢查這些修改，應該怎麼做？

  1. 先刪掉那個分支，再在本機建立一個同名的分支
  2. 在本機強制切換到那個分支
  3. 用 Hand off 把對話和程式碼移回本機
  4. 把工作副本整個資料夾複製到桌面再打開

20 有些被版本控制忽略的檔案（例如環境設定檔）不會跟著複製到新建立的工作副本。在桌面版中可以怎麼處理這個情況？

  1. 把那些檔案改名成不會被忽略的名稱
  2. 每次建立工作副本之後手動關閉忽略規則
  3. 把那些檔案的內容直接貼到對話裡
  4. 在儲存庫根目錄建立 .worktreeinclude，列出要一併複製的忽略檔
