課前前測：Codex 專案管理與 VS Code 協作

20 題單選。可選「逐題檢查」，每題選好就按「檢查答案」；或選「全部一次檢查」，全部作答後按「全部檢查」一次批改。答錯可以再試，試過 2 個不同的錯誤答案後才能看答案。

答對 60% 以上的題目（看答案的不算）後，可以下載含答案的 HTML 檔。作答紀錄不會保存，重新整理或離開頁面後會從頭開始。

01 在 Codex CLI 中，Codex 把什麼當作這次對話的專案？

  1. ChatGPT 桌面版 Projects 畫面中最近開啟的專案
  2. VS Code 目前開啟的工作區
  3. 啟動 codex 時所在的資料夾，或用 --cd 指定的資料夾
  4. 帳號中最近一次連接的 GitHub 儲存庫

02 某同學在桌面版的本機專案中加入了兩個資料夾，並把其中一個設為主要資料夾（Make primary）。下列敘述何者正確？

  1. Codex 只會在主要資料夾自動尋找規則檔、技能與設定檔
  2. 次要資料夾完全無法被 Codex 讀取或編輯
  3. 新對話會從最後加入的那個資料夾開始
  4. Git 操作預設會同時作用在所有已加入的資料夾

03 在 Codex 中「釘選」一個常用的對話，會產生什麼效果？

  1. 之後每個新對話都會自動讀取這個對話的內容
  2. 只改變它在側邊欄的顯示位置，不會增加脈絡，也不會改變 Codex 能存取的內容
  3. Codex 因此可以存取更多電腦上的資料夾
  4. 這個對話會在一週後自動被封存

04 某個截止日看板程式依「基準日」計算每個項目的剩餘天數，而且基準日一律由命令列參數指定，而不是讀取執行當天的日期。這樣設計的主要好處是什麼？

  1. 程式執行速度會明顯變快
  2. 可以省略所有單元測試
  3. 頁面會自動顯示執行當天的最新日期
  4. 不論哪一天執行，同樣的資料都能產生相同的結果，方便重現與比對

05 某個資料夾中同時有 AGENTS.override.md 與 AGENTS.md。Codex 在組合這一層的指示時，會怎麼處理？

  1. 只採用 AGENTS.override.md，因為每層依序尋找且最多採用一個檔案
  2. 兩個檔案都採用，並把內容合併
  3. 只採用內容比較長的那一個檔案
  4. 兩個檔案互相衝突，所以這一層全部略過

06 某組把所有規則都寫進專案根目錄的規則檔，內容越來越長。關於 Codex 合併這些指示的方式，下列敘述何者正確？

  1. 規則檔沒有大小上限，全部寫在同一個檔案最好
  2. 空白的規則檔會清除上一層已載入的規則
  3. 合併後的大小預設上限為 32 KiB，超過就停止加入，因此專案很大時應把規則拆到各子資料夾
  4. Codex 只讀取規則檔的第一段，其餘內容會被忽略

07 同一個設定項目同時出現在 CLI 旗標、專案的 .codex/config.toml 與使用者的 ~/.codex/config.toml 中，Codex 會以哪一個為準？

  1. 使用者設定檔
  2. CLI 旗標
  3. 專案設定檔
  4. 內建預設值

08 某同學把一個剛下載的專案標記為「不信任」。對這個專案而言，會發生什麼事？

  1. Codex 會拒絕開啟這個專案中的任何檔案
  2. 專案的設定會改為最高優先順序
  3. Codex 會自動刪除專案中的設定資料夾
  4. Codex 會略過專案的 .codex/ 設定層，包括專案設定、hooks 與 rules

09 想在 CLI 中依優先順序列出目前生效的各個設定層，應使用哪一個斜線指令？

  1. /init
  2. /compact
  3. /debug-config
  4. /fork

10 撰寫技能時，為什麼 SKILL.md 的 description 要精簡，並把關鍵用途與觸發字放在前面？

  1. Codex 一開始只看每個技能的名稱與描述，並依描述判斷是否自動選用
  2. description 會直接顯示在 VS Code 的狀態列
  3. description 越短，技能執行的速度越快
  4. Codex 只會執行 description 中寫到的指令

11 某組想建立一個只跟目前專題有關、並且要隨專案一起 commit 的技能。這個技能的資料夾最適合放在哪裡？

  1. $HOME/.agents/skills
  2. /etc/codex/skills
  3. Codex 內建的系統技能位置
  4. 儲存庫中的 .agents/skills

12 在 ChatGPT 桌面版的本機環境中設定 Setup scripts，這些腳本會在什麼時候執行？

  1. 每次在 VS Code 存檔時執行
  2. Codex 建立新的 worktree 時自動執行
  3. 只有手動點選工具列按鈕時才執行
  4. 每次關閉桌面版 App 時執行

13 Codex 擴充套件提供的 chatgpt.addToThread 指令，用途是什麼？

  1. 把選取的程式碼範圍加入目前對話
  2. 開啟一個新的 Codex 面板
  3. 把整個專案資料夾上傳到雲端
  4. 開啟 Codex 的指令選單

14 某同學正在和 Codex 進行一個長任務，想臨時問一個小問題，但不想打斷主對話。應使用哪一個斜線指令？

  1. /cloud
  2. /side
  3. /project
  4. /goal

15 以 chatgpt.* 開頭的設定（例如 chatgpt.followUpQueueMode），應該在哪裡調整？

  1. 寫進使用者的 Codex 設定檔，才能和 CLI 共用
  2. 寫進專案的規則檔，讓組員一起使用
  3. 只能透過 CLI 旗標在每次啟動時指定
  4. 在 VS Code 的設定中調整，不要寫進 Codex 的設定檔

16 桌面版與 VS Code 擴充套件開啟同一個專案時，在桌面版輸入框開啟 IDE context 會有什麼效果？

  1. VS Code 會自動關閉所有開啟的檔案
  2. 兩邊的對話會被合併成一個並刪除舊紀錄
  3. Codex 可以使用你在編輯器中開著的檔案
  4. 桌面版會改用另一個模型執行

17 在 VS Code 的 Agent Host 上使用 Codex 時，哪一種核准預設可以修改工作區外的檔案並直接連網，等於給代理完整的電腦存取權？

  1. Default Permissions
  2. Auto-Review
  3. Full Access
  4. Plan

18 關於 VS Code 工作階段中的 New Worktree，下列敘述何者正確？

  1. 它只隔離程式碼修改，不是安全邊界，不會限制指令或網路存取
  2. 它會自動帶入目前工作區所有未 commit 的修改
  3. 它可以在沒有任何 commit 的資料夾中使用
  4. 它會封鎖所有網路存取，確保指令無法連網

19 某組的成績報告專案附有規格文件、測試與「預期報告」。老師決定把等第改成 11 級制，下列哪一種處理順序最恰當？

  1. 先改預期報告，再讓程式配合輸出相同的結果
  2. 讓技能直接修改預期報告，讓比對通過
  3. 只修改程式，規格與預期報告維持不變
  4. 先改規格，再改程式與測試，最後才更新預期結果

20 某同學在 worktree 中建立了 feature/a 分支，現在想在本機平常的 VS Code 視窗中檢查這些修改。最恰當的做法是什麼？

  1. 在本機直接 checkout 同一個分支
  2. 使用 Hand off，把對話和程式碼移回 Local
  3. 刪除 worktree 後重新建立一次
  4. 執行 /status 查看目前的用量限制
