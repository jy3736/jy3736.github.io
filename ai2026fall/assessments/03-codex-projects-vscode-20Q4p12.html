課後形成性評量：Codex 專案規則與工作階段

20 題複選，每題 1 至 2 個正確選項。可選「逐題檢查」，每題選好就按「檢查答案」；或選「全部一次檢查」，全部作答後按「全部檢查」一次批改。答錯可以再試，試過 2 個不同的錯誤答案後才能看答案。答對 60% 以上的題目（看答案的不算）後，可以下載含答案的 HTML 檔。作答紀錄不會保存，重新整理或離開頁面後會從頭開始。

01 關於不同介面如何決定 Codex 的「專案」，下列哪些敘述正確？

  1. VS Code 擴充套件以目前開啟的資料夾或工作區作為專案
  2. CLI 與 IDE 擴充套件都可以看到桌面版的 Projects 畫面
  3. Codex CLI 可以用 -C 旗標指定要工作的資料夾
  4. 桌面版的專案只能連結電腦上的一個資料夾

02 某組希望未來新開的每一個 Codex 對話都讀得到一條長期有效的專案規則。這條規則最適合放在哪裡？

  1. 放在專案的規則檔，或其他納入版本控制的專案檔案中
  2. 寫在某個已釘選對話的第一則訊息
  3. 寫在對話的標題中
  4. 只在目前對話中口頭交代一次

03 下列哪些情況適合建立一個 Codex 專案，而不是直接開一個新對話？

  1. 只想問一次某個指令的用法
  2. 這項工作會持續好幾週，陸續產生多份成果
  3. 一次性的小任務，不需要共用任何檔案或資料夾
  4. 這項工作會反覆用到同一批檔案

04 下列哪些情境適合在桌面版建立一個「連結多個資料夾」的本機專案？

  1. App 的程式與它的文件分開放在兩個資料夾
  2. 兩件彼此完全無關的工作
  3. 希望對話只能碰到儲存庫中的某一部分
  4. 網站的前端與後端分開放在兩個資料夾

05 在連結多個資料夾的本機專案中，關於「次要資料夾」的敘述何者正確？

  1. 完全無法被 Codex 讀取或修改
  2. 新對話會從次要資料夾開始
  3. 仍可搜尋、讀取、編輯，但不會自動載入其中的規則檔、技能與設定檔
  4. Git 操作預設作用在次要資料夾

06 在 Codex CLI 中管理對話時，下列哪些敘述正確？

  1. 開新對話時，所有舊對話都會被刪除
  2. 用 /new 為不同的成果開新對話
  3. 用 codex resume 接續之前的舊對話
  4. 接續舊對話時，專案中的其他對話會全部封存

07 某同學想確認 Codex 這次實際讀到了哪些規則檔。最直接的做法是什麼？

  1. 打開 VS Code 的鍵盤快捷鍵設定查看
  2. 直接問 Codex：「列出你載入的指示來源。」
  3. 重新安裝 Codex 擴充套件
  4. 把所有規則檔刪除後重新建立

08 關於 Codex 如何尋找與組合規則檔，下列哪些敘述正確？

  1. 內容空白的規則檔會清除所有前面已載入的規則
  2. 合併後的指示沒有任何大小上限
  3. 全域規則從 Codex 家目錄（預設為 ~/.codex）讀取
  4. 專案層從專案根目錄往下到目前資料夾，每一層最多採用一個檔案

09 專案的 .codex/config.toml 中若寫了下列哪些設定，Codex 會忽略它們並在啟動時警告？

  1. model_provider
  2. profile
  3. approval_policy
  4. sandbox_mode

10 Codex 設定檔中的 sandbox_mode 控制的是什麼？

  1. Codex 什麼時候要暫停下來詢問你
  2. Codex 介面顯示的語言
  3. Codex 使用哪一個模型
  4. 指令執行時的檔案與網路存取程度

11 關於技能資料夾的結構，下列哪些敘述正確？

  1. 技能資料夾中必須有 SKILL.md
  2. 技能資料夾中必須包含 scripts 子資料夾
  3. SKILL.md 開頭必須寫出 name 與 description
  4. 技能只能手動建立，無法由 Codex 引導建立

12 在 CLI 或 IDE 擴充套件中，可以用下列哪些方式明確呼叫一個技能？

  1. 執行 /init 產生技能
  2. 輸入 $ 提及技能名稱
  3. 重新啟動電腦後技能才會生效
  4. 執行 /skills 從清單中選擇

13 下列哪一項是撰寫技能時建議遵守的原則？

  1. 一個技能盡量包辦專題中的所有流程
  2. 除非需要確定性的結果或外部工具，優先用文字指示
  3. 每一個步驟都盡量寫成腳本，避免使用文字
  4. 描述寫得越長越詳細，越容易被自動選用

14 桌面版的本機環境中，哪一項功能提供常用任務（例如啟動開發伺服器、執行測試）的快捷按鈕，顯示在上方工具列？

  1. Actions
  2. Setup scripts
  3. Worktree
  4. Hand off

15 關於 Codex 的斜線指令，下列哪些敘述正確？

  1. /compact 會壓縮目前對話的脈絡
  2. /cloud 會刪除本機所有的 worktree
  3. /ide-context 會開啟一個新的 VS Code 視窗
  4. /fork 會把本機對話複製成新的本機對話

16 安裝 Codex 擴充套件後，在 VS Code 中找不到 Codex 圖示。下列哪一個做法最恰當？

  1. 重新安裝 VS Code 並清除所有設定
  2. 改用瀏覽器開啟 Codex 雲端
  3. 在終端機執行 git init
  4. 開啟命令選擇區，執行 Codex: Open Codex Sidebar

17 關於編輯器設定 chatgpt.followUpQueueMode，下列哪些敘述正確？

  1. 這個設定應該寫進 Codex 的 config.toml
  2. 預設值是 queue，Codex 工作中送出的訊息會排隊
  3. 可以用 Cmd/Ctrl+Shift+Enter 單次反轉這個行為
  4. 預設值是 steer，訊息會引導目前這一輪

18 在 VS Code 的代理工作階段中，下列哪些控制項的說明正確？

  1. Language model 決定由哪一個 harness 執行工作階段
  2. Agent 決定工具在本機或雲端運作
  3. Code isolation 決定修改寫進目前資料夾，或另開 Git worktree
  4. Permissions 決定哪些動作需要你確認

19 在 VS Code 中選擇 New Worktree 開始工作階段時，下列哪些敘述正確？

  1. 需要一個至少有一個 commit 的 Git 儲存庫
  2. 被 Git 忽略的檔案（如 .env）預設不會帶過去，可用 git.worktreeIncludeFiles 指定要複製的項目
  3. 未 commit 的修改會自動帶進新的 worktree
  4. 可以在沒有 Git 的一般資料夾中使用

20 桌面版會自動清理 Codex 管理的 worktree。若某個 worktree 需要長期使用，最恰當的做法是什麼？

  1. 每天手動複製一份 worktree 資料夾備份
  2. 把 worktree 的分支名稱改成 main
  3. 從側邊欄專案的三點選單建立 permanent worktree，它不會被自動刪除
  4. 關閉桌面版的所有對話，讓清理不再執行
