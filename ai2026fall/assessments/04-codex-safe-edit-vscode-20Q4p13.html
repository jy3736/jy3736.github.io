課後形成性評量：Codex 安全修改與 VS Code 協作

20 題複選，每題 1 至 3 個正確選項。可選「逐題檢查」，每題選好就按「檢查答案」；或選「全部一次檢查」，全部作答後按「全部檢查」一次批改。答錯可以再試，試過 2 個不同的錯誤答案後才能看答案。答對 60% 以上的題目（看答案的不算）後，可以下載含答案的 HTML 檔。作答紀錄不會保存，重新整理或離開頁面後會從頭開始。

共 20 題，每題 A–D 四個選項，每題的正確選項為 1 至 3 個，請選出所有正確選項。

01 關於 Codex 在不同介面中如何決定「專案」，下列哪些敘述正確？

  1. Codex CLI 以啟動 codex 時所在的資料夾為專案，也可以用 --cd <資料夾>（簡寫 -C）指定
  2. VS Code 擴充套件以 VS Code 目前開啟的資料夾或工作區為專案
  3. CLI 與 VS Code 擴充套件看不到網頁版或桌面版的 Projects 畫面
  4. 桌面版的一個專案只能連結電腦上的一個資料夾

02 在 ChatGPT 桌面版把一個專案連結兩個資料夾，並把其中一個設為主要資料夾。主要資料夾有什麼特別的地位？

  1. 只有主要資料夾裡的檔案能被讀取，其他資料夾一律無法搜尋或編輯
  2. 主要資料夾會自動被標記為不信任，裡面的設定一律略過
  3. 主要資料夾裡的檔案不會被 Git 記錄，適合放暫存檔
  4. 新對話從它開始、Git 操作預設作用在它，而且只有它會自動載入 AGENTS.md、技能與 config.toml

03 Codex 會讀檔案、改檔案、執行指令。關於讓這些動作維持在掌控之中的機制，下列哪些敘述正確？

  1. 沙箱像一道圍籬，技術上限制 Codex 能碰哪些檔案、能不能連網
  2. 釘選專案會讓 Codex 多知道一些內容，等於擴大它能存取的範圍
  3. 核准機制只負責事後記錄 Codex 做過什麼，不會在動作前停下來問你
  4. 建議使用 Ask for approval 模式：可以在專案資料夾內自由工作，要超出範圍時先暫停問你

04 下列哪一個指令會放棄所有還沒存檔的修改、回到上一個存檔點，而且這個動作無法復原？

  1. git status
  2. git restore .
  3. git diff
  4. git add -A

05 Codex 每次開始工作時，會把找到的規則檔串成一份指示。關於這個尋找與合併的方式，下列哪些敘述正確？

  1. 所有規則合併後沒有大小上限，寫多少都會被完整加入
  2. 全域規則取自 Codex 家目錄，先找 AGENTS.override.md，沒有的話才讀 AGENTS.md
  3. 專案規則從最上層一路往下找到目前所在的資料夾，每一層最多採用一個
  4. 合併時越靠近目前資料夾的檔案越晚出現，所以會覆蓋前面的規則

06 關於專案層級的 .codex/config.toml，下列哪些敘述正確？

  1. 它只在被信任的專案中生效；專案被標記為不信任時，Codex 會略過專案裡的設定
  2. 它的優先順序高於啟動 CLI 時直接加的旗標與 --config 覆寫
  3. 它不能更改 model_provider、profile 這類設定，Codex 會忽略並在啟動時警告
  4. 它使用 JSON 格式，註解以兩條斜線開頭

07 一個 Codex 技能是一個資料夾。下列哪一項是技能一定要具備的內容？

  1. 一個 scripts/ 資料夾，裡面至少放一支可以執行的程式
  2. 一個 assets/ 資料夾，存放範本與預期結果
  3. 一份 SKILL.md，開頭兩條 --- 之間寫出 name 與 description
  4. 一份 references/ 底下的規格文件，逐項列出輸入與輸出格式

08 關於技能的呼叫方式與存放位置，下列哪些敘述正確？

  1. Codex 一開始就會讀完每個技能完整的內容，再決定要不要使用它
  2. 在 CLI 或 VS Code 擴充套件輸入 $ 接技能名稱即可明確呼叫，例如 $grade-report
  3. 要隨專案一起分享給組員的技能，應該放在整台機器共用的 /etc/codex/skills
  4. 請求符合技能的 description 時 Codex 會自動選用，所以描述要精簡並把關鍵用途放在前面

09 下面這個 Python 函式想計算一串分數的平均，但結果不正確。關於它的問題與修正方向，下列哪些敘述正確？

def average(scores):
    total = 0
    for score in scores:
        total = total + score
    return total / 3
  1. 它固定除以 3，所以輸入 100 與 60 兩個分數時會算出 53.33，而不是正確的 80
  2. 只要把最後一行改成直接回傳總和，就能得到正確的平均
  3. 應該改成除以實際的分數個數，也就是串列的長度
  4. 沒有任何分數時回答 0.0 會誤導人，比較好的做法是回傳代表「沒有值」的 None

10 一個好的 Codex 提示會把四件事說清楚。下列哪一組最符合這個結構？

  1. 想要的行為、相關的程式或重現步驟、必須保留的限制、如何驗證
  2. 使用的模型、推理強度、沙箱模式、核准政策
  3. 專案名稱、組員分工、時程表、期末簡報大綱
  4. 檔案路徑、檔案大小、副檔名、最後修改時間

11 關於 VS Code 畫面各區域的位置與用途，下列哪些敘述正確？

  1. 側邊欄位於畫面下方面板，主要用途是執行指令
  2. 活動列是最左邊一排圖示，用來切換檔案總管、搜尋、原始檔控制、擴充套件與 Codex
  3. 以選單「終端機 > 新增終端機」開啟的終端機，會自動位在目前開啟的專案資料夾
  4. 編輯區位於活動列左側，只能閱讀檔案，不能修改內容

12 關於 Codex 擴充套件在 VS Code 命令選擇區中提供的指令，下列哪些敘述正確？

  1. chatgpt.addToThread 可以把選取的程式碼範圍加入目前對話
  2. chatgpt.newChat 在 macOS 的預設快捷鍵是 Cmd+N
  3. chatgpt.addFileToThread 的用途是開啟 Codex 指令選單
  4. 可以執行 Preferences: Open Keyboard Shortcuts，搜尋指令 ID 後綁定自訂快捷鍵

13 某個專案把「啟動網站」設定成一個 Action，按鈕顯示在桌面版上方工具列。點下這個按鈕時會發生什麼事？

  1. 在雲端容器中執行，完成後把結果寄到你的信箱
  2. 先要求你確認每一個檔案變更，再逐一套用
  3. 在瀏覽器中開啟一個新分頁顯示設定畫面
  4. 直接在桌面版的內建終端機執行對應的指令

14 在 Codex 輸入框輸入 / 會列出可用的斜線指令。關於這些指令的用途，下列哪些敘述正確？

  1. /init 會為目前專案產生 AGENTS.md 草稿
  2. /side 會開一個臨時的側聊，不打斷主對話
  3. /compact 的用途是選擇模型與推理強度
  4. /fork 會把目前的本機對話搬到雲端繼續執行

15 關於 Codex 擴充套件的編輯器設定與桌面版的搭配，下列哪些敘述正確？

  1. chatgpt.commentCodeLensEnabled 預設為關閉，必須手動開啟才會在 TODO 註解上顯示小按鈕
  2. 以 chatgpt. 開頭的設定屬於 VS Code，不要寫進 config.toml
  3. 桌面版與 VS Code 擴充套件開啟同一個專案時，兩邊會共用進行中的對話與編輯器內容
  4. 在桌面版輸入框開啟 IDE context，Codex 就能使用你在 VS Code 開著的檔案；不想帶入時可以關掉

16 某位同學想調整 Codex 使用的模型、推理強度、權限與沙箱。這些選項屬於哪一層設定，應該在哪裡調整？

  1. 編輯器設定；在 VS Code 設定頁搜尋 Codex 相關項目後修改
  2. Codex 設定；只能在 ChatGPT 網頁版的帳號設定頁修改
  3. Codex 設定；從 Codex 側邊欄齒輪開啟 Codex Settings，或用 Open config.toml 直接編輯
  4. 編輯器設定；在 VS Code 的鍵盤快捷鍵頁面調整

17 編輯器設定 chatgpt.followUpQueueMode 決定 Codex 工作中送出的訊息如何處理。下列哪些敘述正確？

  1. 它的預設值是 steer，訊息會立刻引導目前這一輪
  2. 這個設定只有在 Codex 於雲端執行時才會生效
  3. 設成 queue 時，工作中送出的訊息會排隊等下一輪
  4. 按 Cmd/Ctrl+Shift+Enter 可以單次反轉它的行為

18 代理工作階段的 Code isolation 可以選擇 Folder 或 New Worktree。關於這兩種選擇，下列哪些敘述正確？

  1. Folder 適合需要用到目前檔案與尚未 commit 修改的小型互動任務，修改會立刻出現在工作區
  2. New Worktree 從已 commit 的狀態開始，完成後要自己整合結果
  3. Worktree 只隔離程式碼修改，並不是安全邊界，不會限制指令或網路存取
  4. 只要資料夾裡有檔案就能建立 New Worktree，不需要任何 commit 紀錄

19 Codex 預設不會出現在 VS Code 代理介面的選單裡。下列哪一項是讓它出現的正確做法？

  1. 安裝 OpenAI Codex 擴充套件以在 Chat view 中使用，或開啟實驗功能設定 chat.agentHost.codexAgent.enabled 讓它出現在 Agents window
  2. 把 VS Code 介面語言改成英文後重新啟動
  3. 在設定檔中加入一行 session_target = "codex"
  4. 把專案資料夾改名為 .codex 之後重新開啟 VS Code

20 在 VS Code 的代理工作階段中可以調整多個控制項。關於這些控制項各自決定什麼，下列哪些敘述正確？

  1. Language model 決定哪些動作需要你先確認
  2. Session Target 決定由哪個代理執行，以及工具在哪裡運作
  3. Permissions 決定推理方式、速度與額度消耗
  4. Agent 決定代理扮演的角色，例如直接實作或先規劃
