第 2 單元講義

建立與管理 Codex 專案，並在 VS Code 中協作

上週學會了「怎麼跟 AI 說清楚」。這週要把專案整理成 Codex 一打開就知道規則的樣子，並在 VS Code 裡和 Codex 一起完成兩個小而完整的程式，最後用「技能」讓任何人都能重現同樣的結果。

  • 課堂時間 120 分鐘
  • 需要：VS Code、Codex 擴充套件、Git、Python、Node.js
  • 選用：ChatGPT 桌面版
目標 1

說明桌面版、CLI、VS Code 各自把什麼當作 Codex 專案，並整理專案與對話。

目標 2

用 AGENTS.md、config.toml 與技能，把專案規則寫進專案裡。

目標 3

在 VS Code 中用指令、斜線指令與設定和 Codex 協作。

目標 4

完成兩個範例，用 worktree 平行作業，並用技能重現結果。

01本單元會用到的名詞

專案
一件持續進行的工作，以及它用到的檔案、規則與對話。在 Codex 裡，專案通常對應到電腦上的一個資料夾。
儲存庫（repository）
被 Git 記錄的資料夾，常簡稱 repo。執行過 git init 的資料夾就是一個儲存庫。
分支（branch）
同一個專案的「平行版本」。可以在新分支上嘗試新功能，不影響主要版本（常叫 main），確定沒問題再合併回去。
Worktree
同一個儲存庫在電腦上的另一份工作副本。兩份副本共用 Git 的紀錄，但檔案各自獨立，所以可以同時在兩邊做不同的修改。
設定檔
存放「偏好與選項」的文字檔。Codex 的設定檔叫 config.toml。
技能（skill）
一個資料夾，裡面寫好「某件事該怎麼做」的步驟與參考資料。Codex 讀了它，就能照同一套流程把事情做好。
VS Code
免費的程式編輯器，可以看檔案、改程式、開終端機，也能安裝擴充套件增加功能。
擴充套件
替 VS Code 加上新功能的外掛。Codex 擴充套件讓你在 VS Code 裡直接使用 Codex。
命令選擇區
VS Code 裡用打字找功能的搜尋框（Command Palette）。按 Cmd+Shift+P（macOS）或 Ctrl+Shift+P（Windows）開啟。
CSV
用逗號分隔欄位的表格文字檔，第一行通常是欄位名稱。可以用 Excel 開啟。
JSON
一種常見的資料格式，用 { } 包住一筆資料的各個欄位，用 [ ] 包住一串資料。
函式（function）
一段有名字、可以重複使用的程式。把資料交給它，它算出結果交回來。
測試（test）
自動檢查程式結果是否符合預期的程式。

02Codex 專案是什麼

不同介面怎麼決定「專案」

介面專案是什麼開始方式
ChatGPT 桌面版Projects 畫面中的專案，可以連結電腦上的一個或多個資料夾建立專案，或開啟一個資料夾
Codex CLI啟動 codex 時所在的資料夾在該資料夾執行 codex，或用 --cd <資料夾>（簡寫 -C）指定
VS Code 擴充套件VS Code 目前開啟的資料夾或工作區用 VS Code 開啟資料夾；同時開多個資料夾時，要為對話選擇其中一個作為根目錄

換句話說：你在哪個資料夾打開 Codex，Codex 就在那個資料夾工作。CLI 和 VS Code 擴充套件看不到網頁版或桌面版的 Projects 畫面，所以長期有效的規則要寫在資料夾裡的 AGENTS.md，未來的新對話才讀得到。

什麼時候建立專案

  • 建立專案：工作會持續一段時間、會產出不只一份成果，或會反覆用到同一批檔案。
  • 直接開新對話：一次性的工作，不需要共用檔案、指示或資料夾。
  • 每個成果一個對話：同一個專案裡，「修 bug」、「加新功能」、「寫說明文件」各開一個對話，讓每個對話保持聚焦。

桌面版：一個專案連結多個資料夾

當 Codex 需要讀取或修改電腦上的檔案時，就在桌面版建立本機專案：

  1. 開啟專案選單，選擇 Edit project。

  2. 選擇 Add folder 加入資料夾，可以加入多個。Codex 能讀取和修改每個加入的資料夾。

  3. 在某個資料夾上選擇 Make primary，設為主要資料夾。

主要資料夾有特別的地位：

  • 新對話從主要資料夾開始。
  • Git 操作預設作用在主要資料夾。
  • Codex 只會在主要資料夾自動尋找 AGENTS.md、技能與 config.toml。其他資料夾仍然可以搜尋、讀取、編輯，但這些專案檔不會自動載入。

彼此無關的工作，或希望對話只能碰到其中一部分時，就建立不同的專案。

專案不是安全圍籬

專案與 worktree 負責「整理工作」。真正限制 Codex 執行的指令能讀寫哪些檔案、能不能連網的，是沙箱。

整理專案與對話

動作用途
釘選專案讓常用專案固定在側邊欄上方
釘選對話常回來看的對話不會被新對話擠下去
重新命名對話用描述成果的短標題，例如「成績報告：資料驗證」
搜尋在 Projects 畫面搜尋專案；記得片段文字或分支名稱時，用 Search chats 找舊對話
封存對話完成後封存；也可以從專案選單一次封存該專案的所有對話

釘選只改變顯示的位置，不會讓 Codex 多知道什麼，也不會改變它能存取的內容。桌面版封存的對話可以從 Settings > Archived chats 還原。在 CLI 中，用 /new 開新對話，用 /resume 或 codex resume 接續舊對話。

03把專案規則寫進專案

一個「交給任何人打開都能順利工作」的 Codex 專案，通常長這樣。以 . 開頭的資料夾在 macOS 的 Finder 和 Windows 檔案總管中預設會隱藏，但在 VS Code 的檔案總管裡看得到。

AGENTS.md：Codex 開工前先讀的規則

Codex 每次開始工作時，會把找到的規則檔串成一份指示：

  1. 全域：Codex 家目錄（預設是 ~/.codex）裡的 AGENTS.override.md；沒有的話讀 AGENTS.md。這是你個人套用到所有專案的規則。

  2. 專案：從專案最上層（通常是 Git 儲存庫的根目錄）一路往下，走到你目前所在的資料夾。每一層依序找 AGENTS.override.md、AGENTS.md，每層最多採用一個。

  3. 合併：由上往下串起來。越靠近目前資料夾的檔案越晚出現，所以會覆蓋前面的規則。

用例子看懂「越近越優先」

如果在 bookshop/backend/payments 裡啟動 Codex，它會依序讀到三份規則。「繁體中文」照樣適用；但測試指令的規則，付款模組那份最靠近，所以以「make test-payments」為準。

還要注意：

  • 空白的規則檔會被略過。所有規則合併後的大小上限預設為 32 KiB（約一萬多個中文字），超過就不再加入。專案很大時，把規則拆到各子資料夾。
  • 在要放規則的資料夾執行 /init，Codex 會產生一份 AGENTS.md 草稿，檢查、修改後再 commit。
  • 想確認 Codex 讀到了哪些規則，直接問它：「列出你載入的指示來源。」

.codex/config.toml：專案層級設定

個人預設設定放在 ~/.codex/config.toml；某個專案需要不同的設定時，在專案中加入 .codex/config.toml。CLI 與 VS Code 擴充套件共用同一套設定。

TOML 格式很單純：每一行寫「設定名稱 = 值」，文字值要加引號，# 後面是註解（給人看的說明，Codex 會忽略）。

同一個設定可能出現在好幾個地方，Codex 依下面的順序決定用哪一個（數字越小越優先）：

順序設定來源
1啟動 CLI 時直接加的旗標與 --config 覆寫
2專案的 .codex/config.toml（越靠近目前資料夾越優先，只在信任的專案生效）
3用 --profile 選擇的設定檔
4你的使用者設定 ~/.codex/config.toml
5工作區雲端管理的預設值
6系統設定（Unix 為 /etc/codex/config.toml）
7Codex 內建的預設值
安全提醒
  • 把專案標記為不信任時，Codex 會略過專案裡的 .codex/ 設定，包括專案設定、hooks 與 rules。從網路下載的陌生專案，先確認內容再信任。
  • 專案設定檔不能改和帳號憑證、服務供應商、設定檔選擇有關的設定（例如 model_provider、profile），Codex 會忽略並在啟動時警告。
  • 在 CLI 中執行 /status 可以看目前的模型、核准政策與可寫入路徑；/debug-config 會依優先順序列出各設定層。

04技能：把重複的做法打包起來

如果你常常要 Codex 做同一件事（例如「跑完所有檢查並整理結果」），每次都貼一大段提示很麻煩，也容易漏掉步驟。技能就是把這套做法寫成檔案，放在專案裡，需要時一句話叫出來。

技能的組成

技能是一個資料夾，裡面一定要有 SKILL.md，可以另外附上 scripts/（程式）、references/（參考文件）、assets/（範本或資源）。SKILL.md 開頭兩條 --- 之間必須寫 name（名稱）與 description（什麼時候用）：

Codex 怎麼使用技能

  • 明確呼叫：在 CLI 或 VS Code 擴充套件輸入 $ 接技能名稱，例如 $grade-report，或執行 /skills 選擇。
  • 自動選用：你的請求符合技能的 description 時，Codex 會自己選用。所以描述要精簡，把關鍵用途和觸發字放在前面。
  • 用到才細讀：Codex 一開始只看每個技能的名稱與描述，決定使用某個技能時，才讀完整的 SKILL.md。

技能放在哪裡

範圍位置適合放
REPO從目前資料夾往上到儲存庫根目錄，每一層的 .agents/skills跟這個專案有關的技能，隨專案一起 commit 分享給組員
USER$HOME/.agents/skills你個人在任何專案都會用到的技能
ADMIN/etc/codex/skills整台機器共用的預設技能
SYSTEMCodex 內建例如 skill-creator、plan

建立技能

  • 輸入 $skill-creator，Codex 會問你這個技能要做什麼、什麼時候觸發，然後幫你產生草稿。
  • 也可以手動建立資料夾和 SKILL.md。Codex 會自動偵測技能變更；沒出現的話，重新啟動 Codex。
寫好技能的四個原則
  1. 一個技能只做一件事。
  2. 除非需要每次都得到完全相同的結果，或需要外部工具，否則優先用文字說明步驟。
  3. 步驟寫成明確的命令句。
  4. 寫清楚輸入是什麼、輸出是什麼。

05本機環境（桌面版）

在 ChatGPT 桌面版的 Codex 中，可以為專案設定本機環境。設定存放在專案根目錄的 .codex 資料夾，可以 commit 分享給組員：

  • Setup scripts（設定腳本）：Codex 建立新 worktree 時自動執行，例如安裝套件、先建置一次。macOS、Windows、Linux 可以分別設定。
  • Actions（快捷動作）：常用任務的按鈕，例如「啟動網站」、「執行測試」，顯示在桌面版上方工具列，點下去就在內建終端機執行。

開啟 Codex

  1. 在 VS Code 的擴充套件頁搜尋並安裝 OpenAI 的 Codex 擴充套件（ID：openai.chatgpt），依畫面登入。

  2. 選單 檔案 > 開啟資料夾，打開你的專案資料夾。

  3. 點活動列上的 Codex 圖示。看不到的話，開啟命令選擇區，輸入並執行 Codex: Open Codex Sidebar。

VS Code 擴充套件會自動把你開啟的檔案當作脈絡。你也可以選取一段程式碼加入對話，讓 Codex 從你正在看的地方開始。每次任務前後記得建立 Git 存檔點。

  3. 搜尋 Codex 或指令 ID，例如 chatgpt.addToThread。

  4. 點鉛筆圖示，按下你想要的快捷鍵組合，再按 Enter。

把 chatgpt.addToThread 綁定到你習慣的快捷鍵。之後選取一段程式碼、按快捷鍵，就能一鍵加入對話。

VS Code 與桌面版同步

當 ChatGPT 桌面版和 VS Code 擴充套件開啟同一個專案時，兩邊會共用進行中的對話與編輯器內容：

  • 在桌面版輸入框開啟 IDE context，Codex 就能使用你在 VS Code 開著的檔案；不想帶入時關掉。
  • 可以從 VS Code 擴充套件打開桌面版的對話，也可以把 VS Code 的對話拿到桌面版繼續。

07在 VS Code 的代理工作階段中使用 Codex

VS Code 本身也有「代理」介面（Chat view 與 Agents window），可以選擇由哪個 AI 代理來執行一個工作階段（session）。Codex 是其中一個選項。一個工作階段包含一段對話、它用到的脈絡和修改，可以暫停、繼續或交接。

讓 Codex 出現在選單中

Codex 預設不在選單裡，下面兩種方式擇一即可：

  • 安裝 OpenAI Codex 擴充套件：在 Chat view 中使用。
  • 實驗功能 Agent Host：在設定中開啟 chat.agentHost.codexAgent.enabled，Codex 會出現在 Agents window。在 Agent Host 上可以選擇登入 ChatGPT，免費帳號即可。

09範例一：成績報告產生器

這個程式要做什麼

讀取一份學生成績表，依「作業 30%、期中 30%、期末 40%」算出總分與等第，輸出一份整理好的成績報告。成績表裡刻意放了兩筆有問題的資料（一位期中沒有分數、一位作業填了 105 分），程式必須把它們挑出來，不能算進統計。

輸入資料

第 1 行是欄位名稱：學號、姓名、作業、期中、期末。之後每一行是一位學生。注意第 6 行李承恩的期中是空的（兩個逗號之間沒有值），第 10 行鄭宇翔的作業是 105。

程式碼逐段解說

整個程式用 Python 寫成，只用 Python 內建的功能，不需要安裝其他東西。下面分段說明，每段先看程式碼，再看解說。

第 1 段：載入工具與定義規則

解說
  • 第 1-4 行：三個引號包住的是說明文字，告訴讀的人這個程式在做什麼、怎麼執行。
  • 第 5-8 行：import 載入 Python 內建的工具。argparse 讀取命令列參數，csv 讀表格檔，Decimal 做精確的小數計算，Path 處理檔案路徑。
  • 第 10 行：WEIGHTS 是一個字典，像一張「名稱對應數值」的對照表：作業 0.3、期中 0.3、期末 0.4。
  • 第 11 行：LETTERS 是等第門檻，從高到低排列：90 分以上 A、80 以上 B，依此類推。
  • 第 12 行：及格分數 60。

名稱全部大寫，是 Python 的慣例，表示「這是固定的規則，程式執行時不會改變」。把規則集中寫在最上面，要調整時只需要改這裡。

第 2 段：四捨五入、加權總分、等第

解說
  • round1（第 15-16 行）：把數字四捨五入到小數第一位。ROUND_HALF_UP 就是我們熟悉的「五入」。
  • weighted_total（第 19-20 行）：row 是一位學生的資料。對每個科目，把分數乘上權重，再全部加起來，最後四捨五入。
  • letter（第 23-27 行）：從最高門檻開始比，第一個「總分大於等於門檻」的就是等第。

用王小明算一次：作業 92 × 0.3 = 27.6，期中 85 × 0.3 = 25.5，期末 88 × 0.4 = 35.2。加起來 88.3。88.3 不到 90，但大於等於 80，所以等第是 B。

為什麼用 Decimal？電腦平常用二進位存小數，有些小數存不精確。例如作業 60.5、期中 70、期末 60，精確的總分是 63.15，四捨五入應該是 63.2；但用一般小數計算再四捨五入，會得到 63.1。成績差 0.1 分就可能影響及格與否，所以要用精確計算。

第 3 段：檢查資料是否正確

解說

validate 依序檢查作業、期中、期末三個分數。發現第一個問題就立刻回傳一段問題描述；三個都沒問題才回傳 None（代表「沒有問題」）。

第 4 段：讀檔、計算、排序

解說
  • 第 46 行：準備兩個空串列，students 放有效的學生，problems 放有問題的資料。
  • 第 47-48 行：打開 CSV 檔，csv.DictReader 讓每一行變成「欄位名稱對應值」的字典，逐行處理。

render 把計算結果組成 Markdown 格式的報告。lines 是一個串列，每個元素是報告的一行，最後用換行符號 \n 串起來。

Markdown 表格的寫法是用 | 分隔欄位，第二行 |---|---| 表示上面那行是標題列。

第 6 段：從命令列執行

解說

程式碼逐段解說

範例二用 JavaScript 寫成，在 Node.js 上執行。程式分成兩個檔案：src/board.mjs 只負責計算，build.mjs 負責讀寫檔案。這樣分工，測試時只要把資料交給計算函式、檢查結果，不必真的讀寫檔案。

第 1 段：把日期文字轉成日期

解說
  • 第 1 行：// 開頭是註解。
  • 第 3 行：export const 定義一個固定值，並讓其他檔案可以使用。這裡是四個區的顯示順序。
  • 第 5 行：一天有幾毫秒（24 小時 × 60 分 × 60 秒 × 1000 毫秒）。電腦裡的時間常以毫秒計算。
  • 第 8 行：用正規表示式檢查格式是不是「4 位數-2 位數-2 位數」。\d{4} 意思是「4 個數字」。不符合就用 throw 丟出錯誤訊息。

  • 第 10 行：建立日期。JavaScript 的月份從 0 開始算（1 月是 0），所以要 m - 1。用 UTC 可以避免不同時區算出不同天數。
  • 第 11 行：像 2 月 30 日這種不存在的日期，電腦會自動變成 3 月 2 日。這行檢查月和日有沒有被改掉，有的話就回報「日期不存在」。

解說

做法二：在 ChatGPT 桌面版中

  1. 在新對話畫面的輸入框下方選擇 Worktree，並選擇起始分支（例如 main）。

  2. 送出提示。Codex 會以這個分支建立 worktree，預設處於「detached HEAD」狀態，也就是還沒有掛在任何分支名稱上。

  3. 完成後二選一：

    • 在 worktree 上按 Create branch here 建立分支，再 commit、push、開 PR。
    • 按 Hand off 把對話和程式碼移回 Local，在你平常的 VS Code 視窗中檢查。

做法三：在 VS Code 的 Agents window 中

開新工作階段，Session Target 選 Codex，勾選 New Worktree 並選擇基準分支。記得 worktree 只包含已 commit 的檔案，開始前要先 commit。

Worktree 的注意事項

狀況說明與做法
同一分支不能兩處同時使用在 worktree 建了 feature/a 分支後，本機就無法切換到它。想在本機檢查，改用 Hand off
被 Git 忽略的檔案不會跟過去桌面版可在儲存庫根目錄建立 .worktreeinclude，列出要複製的忽略檔（例如 .env）
新 worktree 缺少套件在桌面版本機環境設定 setup script，建立 worktree 時自動安裝
占用磁碟空間桌面版預設保留最近 15 個 Codex 管理的 worktree；刪除前會存快照，重新打開對話可以還原
需要長期使用從側邊欄專案的三點選單建立 permanent worktree，不會被自動刪除

11總結與課後練習

檢核清單

  • 我知道桌面版、CLI、VS Code 擴充套件各自把什麼當作專案。
  • 我的專案有 AGENTS.md，並確認 Codex 讀到了它。
  • 我知道 .codex/config.toml 只在信任的專案生效，以及設定的優先順序。
  • 我能在 VS Code 中把選取的程式碼加入對話，並使用 /plan、/review、/worktree。
  • 我分得清 Codex 設定（config.toml）和編輯器設定（chatgpt. 開頭）。
  • 我完成了兩個範例，並用 $grade-report、$deadline-board 重現結果。
  • 我知道 worktree 隔離的是程式碼修改，不是安全邊界。

課後練習

  1. 整理專案：為自己的期末專題建立 Codex 專案，釘選專案、把現有對話改成描述成果的標題，並封存已完成的對話。
  2. 寫規則：在專題中執行 /init，把產生的 AGENTS.md 改寫成至少 5 條你們組的規則，並請 Codex 列出它載入的指示來源。
  3. 做一個技能：挑一件專題中會重複做的事（例如「產生週報」或「執行全部檢查並彙整結果」），用 $skill-creator 或手動建立技能，並準備一份預期結果讓技能自我驗證。
  4. 平行作業：在範例二用 worktree 完成兩個功能，最後用 /review 審查，截圖記錄 Hand off 或 Create branch here 的過程。
