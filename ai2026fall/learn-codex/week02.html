01先認識幾個會一直出現的名詞

這份講義會用到一些電腦與程式的名詞。先把它們用生活化的方式講清楚，後面讀起來會輕鬆很多。不必一次背起來，看到不懂的詞再回來查就好。

AI 代理（agent）
不只會回答問題，還能自己規劃步驟、使用工具、把事情做完的 AI。像一位助理：你交代目標，它會自己查資料、開檔案、做出成果給你檢查。
提示（prompt）
你輸入給 AI 的文字，可以是一個問題、一個指令或一個目標。
脈絡（context）
AI 在回答時能參考的背景資訊，例如你上傳的檔案、之前的對話、你說明的情況。脈絡越貼切，答案越符合你的需要。
檔案與資料夾
檔案是一份資料（一篇文件、一張圖、一個程式）；資料夾是裝檔案的容器，資料夾裡還可以有資料夾。
路徑（path）
檔案在電腦裡的「地址」，例如 專題/程式/main.py 表示「專題」資料夾裡的「程式」資料夾裡的 main.py。
程式碼（code）
用程式語言寫給電腦執行的指示。副檔名常透露它是哪種語言，例如 .py 是 Python，.js 是 JavaScript，.html 是網頁。
終端機（terminal）
一個用「打字下指令」操作電腦的視窗。在圖形介面裡你用滑鼠點「開啟」，在終端機裡你輸入一行指令讓電腦做同樣的事。macOS 叫「終端機」，Windows 常用「PowerShell」。
Bug
程式中的錯誤，讓程式的結果和預期不一樣，或直接當掉。
測試（test）
另外寫一小段程式，自動檢查「輸入這些資料時，結果是不是我們預期的」。每次修改後跑一次測試，就知道有沒有改壞東西。
Git
記錄檔案每一次變化的工具，像是遊戲的「存檔點」。改壞了可以回到之前的存檔。
Commit
在 Git 裡建立一個存檔點的動作，會記下「這個時間點所有檔案的樣子」和一句說明。

02ChatGPT 的三種工作方式

ChatGPT 是可以用日常語言溝通的 AI 代理。你可以從一個問題、一份筆記或一件待辦事項開始，需要時再加入檔案、網路搜尋等資訊，最後檢查結果並要求修改。第一個提示不必完美，也不需要學任何特殊指令。

同一個 ChatGPT 裡，有三種工作方式：

工作方式可以把它想成適合的時候大學生的例子
Chat隨時可以問問題的學長姐想來回討論、問問題、腦力激盪解釋看不懂的觀念、想報告題目、比較兩種做法
ChatGPT Work可以交辦一整件事的助理要一份可以檢查的完整成品把筆記做成簡報、整理文獻比較表、擬專題計畫書
Codex會寫程式的組員要處理程式碼，並看到技術細節找出程式錯誤、執行測試、審查組員的程式、做新功能
一句話記住

問問題用 Chat，要成品用 Work，碰程式碼用 Codex。

怎麼判斷該用哪一個？

拿到一件事時，依序問自己兩個問題：

  1. 這件事會動到程式碼嗎？ 會的話用 Codex，因為它會顯示修改了哪幾行、執行了哪些指令，方便你檢查。

  2. 我要的是「答案」還是「成品」？ 只要一個解釋、一個建議、一段短文字，用 Chat；要一份簡報、一張試算表、一份報告，用 ChatGPT Work。

另外兩件要知道的事：

  • ChatGPT Work 和 Codex 的能力有重疊。Codex 也能做研究和文件，差別在於介面：Work 會把 Git 或指令這類技術細節藏起來，Codex 則會把它們顯示出來。
  • ChatGPT Work 和 Codex 共用同一份用量額度。越大的任務用掉的額度越多，所以要把任務範圍說清楚。

03寫出清楚的提示

提示的四個要素

簡單的問題直接問就好。遇到比較大或比較重要的任務時，想想下面四件事，用得到的才寫進去：

要素要回答的問題例子
目標要 AI 做什麼？幫我準備資料結構期中考
脈絡哪些資訊會影響結果？考試範圍是堆疊、佇列、鏈結串列，我對遞迴比較不熟
產出要什麼格式、長度、詳細程度？10 題選擇題加 2 題手寫程式題，附詳解
界線什麼不能做？什麼要先問我？只出範圍內的題目；程式題先不要給答案，等我作答後再批改

寫提示時，先說「想要的結果」，而不是列出一長串步驟。只有當步驟本身很重要時，才需要把流程寫出來。

同一個問題的三個版本

下面用「Big-O」這個資工課常見的觀念示範。你不需要懂 Big-O 是什麼，重點是觀察提示怎麼一步步變清楚。

AI 只知道你要一個定義，會給出一般性的解釋，可能太深或太淺。

AI 現在知道你學過什麼、卡在哪裡，會針對你的困惑解釋。

AI 不只知道要解釋什麼，還知道要用表格、要出題、而且答案先保留。這就是一個完整的提示。

用追問把結果調整到剛好

第一個回答只是起點。看完後可以直接用一句話調整：

  • 「再短一點。」
  • 「給我三種不同的解釋方式。」
  • 「你做了哪些假設？」
  • 「繼續之前，先問我幾個問題。」

學習時好用的提示範例

用熟悉的事物類比，理解新觀念

為什麼有效：要求「指出類比哪裡不成立」，可以避免你把類比當成真的，學到錯誤的細節。

讓 AI 當家教，一步步引導你想

為什麼有效：自己想出來的答案記得最牢。「一次只問一個問題」讓對話變成真正的練習。

考前複習：出題、作答、批改

為什麼有效：「根據這份筆記」把範圍鎖在你的課程內容；「指出對應段落」讓你能回頭複習。

讀懂論文或原文教科書

比較選項，做出決定

為什麼有效：「組員會什麼、時間多長」是會改變答案的脈絡；沒有這些資訊，AI 只能給出一般的比較。

04檢查 AI 的答案

AI 的回答讀起來再流暢，也可能不完整或有錯。請把第一個結果當成草稿，而不是最終答案。

要親自檢查的內容

  • 重要的數字、人名、日期、引用的句子。
  • AI 產生的檔案：每一頁、每一張投影片、每一個工作表都要打開看。
  • AI 是否用了正確、最新的資料。
  • 有沒有缺漏的資訊，或沒有根據的假設。

請 AI 自己說清楚的問題

  • 「這個說法的來源是什麼？」
  • 「每個主要論點請附上來源。」
  • 「你做了哪些假設？」
  • 「有哪些資訊你無法取得？」
  • 「請對照我給的原始檔案，再檢查一次這份結果。」

需要最新資訊時，可以要求 ChatGPT 使用網路搜尋並附上來源，方便查證。如果 AI 沒辦法取得某個來源，請它明確說出來：一個說清楚的缺口，遠比一個自信的猜測容易處理。

重大決定一定要找專業人士

法律、財務、醫療、資訊安全等會影響重大決定的內容，AI 只能幫你整理思路，最後一定要請相關專業人士確認。

學習誠信

作業和考試是用來確認「你」學會了什麼。用 AI 解釋觀念、出練習題、批改你的作答都很好；把作業題目貼上去、直接交出 AI 的答案，就不是學習。每門課對 AI 的規定不同，交作業前請先確認授課教師的規定，並依要求註明 AI 的使用方式。

05專案、檔案與個人化

用「專案」讓 AI 記得你的課程

如果一件事會持續一段時間、會產出不只一份成果，或會反覆用到同一批檔案，就建立一個專案（Project）。專案會把相關的對話、檔案和指示放在一起，專案指示會套用到裡面的每一個對話。一次性的小問題，直接開新對話就好。

專案名稱放進去的檔案專案指示範例
資料結構 115 上課程大綱、講義 PDF、自己的筆記回答時以本課講義為準，程式範例使用 C 語言
畢業專題計畫書、會議紀錄、需求文件我們是 4 人小組，目標是期末完成可展示的 App
求職準備履歷、目標職缺說明用台灣企業常見的履歷格式給建議
  • 每個成果開一個對話：例如「期中複習」一個對話、「報告大綱」一個對話，讓每個對話保持聚焦。
  • 網頁版專案讀不到你的電腦：要讓 AI 使用檔案，需要上傳或透過外掛連接。桌面版則可以建立連到電腦資料夾的「本機專案」。

上傳檔案可以做什麼

可以上傳文件、簡報、試算表、PDF、圖片與資料匯出檔，請 ChatGPT 摘要或比較、找出規律或矛盾、整理資料，或當作做新檔案的素材。

最後兩句是界線：限制 AI 只能用講義內容，並把不確定的地方標出來，你就知道哪裡要回去查。

個人化設定

想套用到所有對話的偏好（例如「一律用繁體中文回答」、「我是機械系學生，舉例請偏向工程情境」），放在 Settings > Personalization 的自訂指示裡。只跟這次對話有關的細節，直接寫在提示中。

06ChatGPT Work：交辦一整件事

Work 能做什麼

研究與分析

搜尋網路、瀏覽網站、比較來源、讀檔案、分析資料並整理發現。

使用你的檔案與工具

上傳的檔案、專案、記憶，以及安裝的外掛（例如 Google Drive）。

產出完成的檔案

文件、簡報、試算表、PDF，可以預覽、要求修改、下載。

視覺與互動作品

產生或編輯圖片、做互動圖表，並用 Sites 建立與分享網站。

重複有用的流程

設定排程任務，或用技能（skill）重複使用同一套做法。

適合交給 Work 的任務，通常符合下面幾點：需要多個來源或步驟、自己做會花不少時間、產出是你之後要檢查或重複使用的東西、需要定期重做。快速的問題和簡短的改寫，用 Chat 就夠了。

雲端或本機

  • 網頁版：Work 在雲端執行。
  • 桌面版：可以選 Cloud（關掉 App 或電腦後任務仍繼續，也能從網頁或手機接著看），或 Work locally（使用你電腦上的檔案、App 或瀏覽器）。

Work 會顯示進度，需要資訊或授權時會暫停等你。重要的動作先檢查再核准，最後的成果也要檢查過才使用或分享。

寫給 Work 的提示：同一件事的兩種寫法

AI 不知道主題、聽眾、長度、資料來源，只能自己猜，做出來的東西多半要大改。

拆解：這個提示好在哪裡？
句子對應要素作用
閱讀附上的三份文獻和讀書筆記脈絡指定資料來源，AI 不會亂找
8 張投影片、報告 10 分鐘產出決定份量
主題、聽眾是同學與老師目標、脈絡決定用詞深淺與重點
三個影響、附證據與出處產出決定內容結構，也方便你查證
分開發現與看法、標記證據不足界線避免 AI 把猜測寫成事實
先給草稿檢查界線保留你修改的機會

大學生常見的 Work 任務

文獻比較表（試算表）

專題選題決策

專題計畫書草稿

實驗數據分析

CSV 是一種用逗號分隔欄位的表格檔，可以用 Excel 或 Google 試算表打開。

定期更新（排程任務）

建議先在一般對話裡把提示調整到結果穩定，再在那個對話中設定排程。需要讀取行事曆或信件的排程，必須先連接對應的外掛。

建立網站（Sites）

Sites 目前為公開測試版，適用 ChatGPT Plus、Pro、Business、Enterprise 與 Edu 方案，並有用量限制。

讓 Work 更有效率的五個習慣

  1. 設下界線：「只用這些來源」、「比較前五名就好」、「送出任何東西前先停下來」。

  2. 只給相關的資料：必要時限定日期範圍。

  3. 區分必要與加分：把一定要做的和「有空再潤飾」的分開寫。

  4. 先要計畫：做法重要時請它先提出計畫；要寄出、發布或修改別人依賴的資料前，一定要先經過你核准。

  5. 偏離方向就喊停：縮小範圍或直接停止，不要讓它繼續做你不需要的事。

Codex 做的事，就是在這樣的資料夾裡讀檔案、修改檔案、執行指令，最後告訴你改了什麼。

使用介面適合的情境開始方式

打開終端機

安裝 CLI 或執行程式時需要終端機：

  • macOS：按 Cmd+Space 開啟 Spotlight，輸入「終端機」或「Terminal」後按 Enter。
  • Windows：按開始鍵，輸入「PowerShell」後按 Enter。

終端機打開後會看到一行提示符號（例如 % 或 >），在後面輸入指令、按 Enter 執行。

安裝 Codex CLI（選一種方式即可）

這些指令在做什麼？
  • curl ... | sh：curl 從網址下載安裝程式，|（管線）把下載的內容交給 sh 執行。
  • irm ... | iex：PowerShell 版的同一件事，irm 下載、iex 執行。
  • npm install -g：用 Node.js 的套件管理工具安裝，-g 表示安裝成整台電腦都能用的指令。

從網路下載並執行程式前，一定要確認網址是官方來源。

安裝好之後，用終端機進到專案資料夾，輸入 codex 啟動。第一次使用時選擇 Sign in with ChatGPT 登入。Codex 會把你啟動它時所在的資料夾當成這次工作的專案。

cd 是 change directory（切換資料夾）的縮寫，後面接要進去的資料夾路徑。

08先設好安全網

Codex 會讀檔案、改檔案、執行指令。為了確保一切在你的掌控之中，有兩個機制一起運作：

沙箱（Sandbox）

像是一道圍籬，技術上限制 Codex 能碰哪些檔案、能不能連網。Codex 執行的其他工具（例如 Git、測試工具）也都在圍籬內。

核准（Approvals）

決定 Codex 什麼時候要停下來問你。例如要跨出圍籬時，先徵求你同意。

大多數情況建議使用 Ask for approval 模式：Codex 可以在目前的專案資料夾內自由工作，要超出範圍時會先暫停問你。在 CLI 中輸入 /permissions 可以查看和切換模式。

用 Git 建立存檔點

每次請 Codex 動手前後，都建立一個 Git 存檔點。如果結果不滿意，就能回到修改前的狀態。第一次在一個資料夾使用 Git 時：

逐行解說
  • git init：讓 Git 開始記錄這個資料夾。每個資料夾只需要做一次。
  • git add -A：把「所有檔案目前的樣子」放進準備存檔的區域。-A 代表全部。
  • git commit -m "..."：正式建立存檔點，-m 後面引號裡是這個存檔點的說明，寫給未來的自己看。

之後每次要存檔，只需要執行後面兩行。第一次使用 Git 時，它可能會要求你先設定姓名與 email，照畫面提示輸入即可。

  • git status：列出哪些檔案被改過。
  • git diff：逐行顯示改了哪些內容，- 開頭是刪掉的行，+ 開頭是新增的行。
  • git restore .：放棄所有還沒存檔的修改，回到上一個存檔點。這個動作無法復原，執行前先用 git diff 確認。

09用 AGENTS.md 交代專案規則

每次請 Codex 做事，你可能都要重複交代「修改後要跑測試」、「不要改原始資料」。把這些規則寫進專案資料夾裡一個叫 AGENTS.md 的檔案，Codex 開始工作前會自動讀取，就不用每次重講。

Markdown 是什麼

.md 結尾的檔案是 Markdown 格式，一種用簡單符號標示格式的純文字檔：

  • # 標題：一個 # 是大標題，## 是小一級的標題。
  • - 項目：減號加空格開頭，是條列項目。
  • `文字`：用反引號包起來，表示這是指令或程式名稱。

範例：畢業專題的 AGENTS.md

Codex 怎麼找 AGENTS.md

  1. 全域：先讀你個人的 ~/.codex/AGENTS.md，套用到所有專案。（~ 代表你的使用者家目錄。）

  2. 專案：從專案最上層的資料夾一路往下到目前的資料夾，每一層最多讀一個規則檔。

  3. 合併：越靠近目前資料夾的規則越晚讀到，所以會覆蓋前面的規則。

懶得從零寫？在專案資料夾中對 Codex 輸入 /init，它會產生一份 AGENTS.md 草稿，你再修改成自己的規則。

10動手看一次：Codex 修好一個有錯的程式

這一節用一個很小的 Python 程式，完整走一遍「發現錯誤、請 Codex 修、檢查結果」的過程。就算你從來沒寫過程式，也能照著看懂。

下載本節範例（week02-average-bug.zip）

第 1 步：看懂這個程式想做什麼

這個程式想計算一串分數的平均。平均的算法是：把所有分數加起來，再除以分數的個數。

逐行解說
行號程式碼的意思
1def average(scores): 定義一個叫 average 的函式。函式像一台機器：把資料（這裡叫 scores，一串分數）放進去，它會算出結果。冒號後面縮排的幾行，都是這台機器的內部步驟。
2total = 0 建立一個叫 total 的變數，先放入 0。變數像一個貼了標籤的盒子，用來暫存數字。
3for score in scores: 迴圈：從分數串列中一次拿出一個分數，叫它 score，對每個分數都執行下一行。
4total = total + score 把目前的總和加上這個分數，再存回 total。迴圈跑完，total 就是全部分數的總和。
5return total / 3 把總和除以 3，當成結果交回去。問題就在這裡。
8-10print(...) 把結果顯示在畫面上。[80, 90, 70] 是一個有三個分數的串列，[] 是一個空的串列。

第 2 步：執行，發現結果不對

逐一檢查：

  • 80、90、70 的平均是 80，正確。
  • 100、60 的平均應該是 80，程式卻算出 53.33，錯誤。因為程式固定除以 3，但這裡只有 2 個分數。
  • 沒有任何分數時，程式回答 0.0。但「沒有分數」不等於「平均 0 分」，這個結果會誤導人。
觀察重點

第一個例子剛好是 3 個分數，所以結果看起來正確。只測一種情況，很容易漏掉錯誤，這就是為什麼需要多種情況的測試。

第 3 步：把問題描述清楚，交給 Codex

在 average-bug 資料夾中啟動 Codex（或在桌面版、VS Code 開啟這個資料夾），輸入：

為什麼要這樣寫提示？
  • 重現方式：給出「怎麼執行、看到什麼、預期什麼」，Codex 可以自己跑一次確認問題，比「平均算錯了」精確得多。
  • 限制：避免 Codex 順手改了其他地方，讓你難以檢查。
  • 驗證方式：要求它修完後再執行、加測試、回報結果，你不用盲目相信「我修好了」。

第 4 步：看 Codex 改了什麼

Codex 會顯示它修改的內容（稱為 diff）。下面是一份參考解答，Codex 實際的寫法可能略有不同，但重點一樣：

改了哪裡、為什麼
  • + 開頭是新增的行，- 開頭是刪掉的行，前面是空格的行沒有變。
  • 第 2 行三個引號包起來的文字是說明文字，寫給閱讀程式的人看，不影響執行。
  • 第 3-4 行：len(scores) 是串列裡有幾個分數。如果是 0 個，就直接回傳 None（Python 裡代表「沒有值」），不往下算。
  • 第 8 行：除以 len(scores)，也就是「實際的分數個數」，不再固定除以 3。

第 5 步：用測試確認真的修好了

參考的測試檔如下（Codex 寫的測試名稱或順序可能不同）：

逐行解說
行號程式碼的意思
1載入 Python 內建的測試工具 unittest。
3從 average.py 取出 average 函式來測試。
6建立一組測試，名字叫 AverageTest。
7-8第一個測試：assertEqual 意思是「斷定兩者相等」。算出來的平均必須等於 80，否則測試失敗。
10-11第二個測試：兩個分數的平均也必須是 80。原本的錯誤就會在這裡被抓到。
13-14第三個測試：assertIsNone 斷定沒有分數時結果是 None。
17-18直接執行這個檔案時，跑所有測試。

三個測試都顯示 ok，最後一行是 OK，代表全部通過。以後不管誰修改 average，只要再跑一次測試，就知道有沒有改壞。

13整合演練：一個專題從發想到展示

以「實驗室器材借用系統」為例，看三種工作方式如何接力：

  1. 1 發想Chat：腦力激盪使用情境、比較技術選項
  2. 2 規劃Work：計畫書草稿、時程表、分工試算表
  3. 3 建立專案Codex：/init 產生 AGENTS.md
  4. 4 開發Codex：做畫面、實作功能、寫測試、修 bug
  5. 5 審查Codex：每次合併前 /review
  6. 6 展示Work：期末簡報與展示網站

課堂活動（兩人一組）

  1. 選一個你們想做的專題題目。

  2. 用 Chat 寫一個包含四要素的提示，請 AI 列出 5 個核心功能與可能的風險。

  3. 至少追問兩次，例如：「你做了哪些假設？」、「哪一個功能最可能做不完？為什麼？」

14總結與課後練習

五個使用守則

  1. 選對工具：問問題用 Chat，要成品用 Work，碰程式碼用 Codex。

  2. 說清楚：目標、脈絡、產出、界線，用得到的就寫上。

  3. 要驗證：追問來源與假設，親自檢查數字、引用與每一頁內容。

  4. 留退路：Codex 動手前後建立 Git 存檔點，預設使用 Ask for approval。

  5. 守誠信：AI 是幫你學會，不是替你交差；依各課程規定使用並註明。

課後練習

  1. Chat：挑一個本週課程中最不熟的觀念，用「讓 AI 當家教」的提示對話至少 5 回合，記錄你在哪一回合想通。
