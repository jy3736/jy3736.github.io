01範例二：截止日看板與平行作業

這個程式要做什麼

讀取各科作業、考試、報告的截止日，依一個「基準日」算出每一項還剩幾天，分成「已過期、緊急、本週、之後」四區，產生一個可以用瀏覽器打開的網頁。基準日一律由指令指定，所以不論哪一天執行，結果都一樣，方便檢查與重現。

先照第 08 節的方式，用 VS Code 開啟 02-deadline-board，執行 git init、git add -A、git commit 建立存檔點。

輸入資料

整份資料是一個串列 [ ]，裡面每一組 { } 是一筆截止日，有四個欄位：科目 course、名稱 title、類型 type、截止日 due。

分類規則

剩餘天數分到哪一區顯示文字
小於 0已過期逾期 N 天
0緊急今天到期
1 到 3緊急剩 N 天
4 到 7本週剩 N 天
8 以上之後剩 N 天

程式碼逐段解說

範例二用 JavaScript 寫成，在 Node.js 上執行。程式分成兩個檔案：src/board.mjs 只負責計算，build.mjs 負責讀寫檔案。這樣分工，測試時只要把資料交給計算函式、檢查結果，不必真的讀寫檔案。

第 1 段：把日期文字轉成日期

解說
  • 第 1 行：// 開頭是註解。
  • 第 3 行：export const 定義一個固定值，並讓其他檔案可以使用。這裡是四個區的顯示順序。
  • 第 5 行：一天有幾毫秒（24 小時 × 60 分 × 60 秒 × 1000 毫秒）。電腦裡的時間常以毫秒計算。
  • 第 8 行：用正規表示式檢查格式是不是「4 位數-2 位數-2 位數」。\d{4} 意思是「4 個數字」。不符合就用 throw 丟出錯誤訊息。
  • 第 9 行：用 - 把文字切成年、月、日三段，並轉成數字。
  • 第 10 行：建立日期。JavaScript 的月份從 0 開始算（1 月是 0），所以要 m - 1。用 UTC 可以避免不同時區算出不同天數。
  • 第 11 行：像 2 月 30 日這種不存在的日期，電腦會自動變成 3 月 2 日。這行檢查月和日有沒有被改掉，有的話就回報「日期不存在」。

第 2 段：算天數、分區、顯示文字

解說
  • daysLeft：截止日減基準日得到毫秒數，除以一天的毫秒數就是天數。例如 2026-10-02 減 2026-09-21 是 11 天。
  • statusOf：依剩餘天數，從上往下判斷分到哪一區。一碰到符合的條件就 return，後面不再判斷。
  • label：產生顯示文字。反引號 `...` 裡的 ${days} 會換成實際的數字。

第 3 段：整理成四個區

解說
  • 第 34-37 行：map 對每一筆資料做同一件事：算出天數與分區，連同原本的欄位（...item 表示「複製原本所有欄位」）組成新資料。
  • 第 38 行：sort 排序。先比天數，天數少的在前；天數相同再依科目名稱排序。
  • 第 39 行：依「已過期、緊急、本週、之後」的順序，用 filter 挑出每一區的項目。

第 4 段：安全地產生網頁

解說
  • escapeHtml（第 42-43 行）：把 <、>、& 這類在網頁中有特殊意義的符號換成安全的寫法。如果有人把科目名稱填成一段網頁程式碼，它只會被當成文字顯示，不會被執行。
  • renderHtml（第 45 行起）：把每一區組成一個 <section>，區裡每個項目是一個 <li>；沒有項目時顯示「沒有項目」。
  • 第 59 行起：整份網頁的外框，包含標題、基準日、簡單的樣式（<style>），以及各區內容。

網頁裡沒有放「產生時間」，所以同樣的資料和基準日，每次產生的檔案都一模一樣，才能和預期結果逐字比對。

第 5 段：命令列程式

解說
  • 第 2-4 行：載入 Node.js 內建的讀寫檔案工具，以及 board.mjs 裡的兩個函式。
  • 第 6-9 行：option 從指令中找出 --today 這類參數後面的值，找不到就用預設值。
  • 第 11-13 行：基準日、輸入檔、輸出檔。沒指定基準日時才用今天的日期。
  • 第 15-18 行：讀 JSON、整理分區、建立輸出資料夾、寫出網頁，最後印出每區的數量。

執行測試與產生網頁

package.json 裡的 scripts 定義了捷徑：npm test 會執行 node --test，npm run build 會用基準日 2026-09-21 產生網頁。範例不需要安裝任何套件，所以不用執行 npm install。

在 VS Code 檔案總管中對 dist/index.html 按右鍵，選 在檔案總管中顯示（Windows）或 在 Finder 中顯示（macOS），再用瀏覽器打開。

看產生出來的網頁原始碼
看測試檔：每個測試在檢查什麼
測試檢查的事
daysLeft counts calendar days跨月份的天數計算正確，過期會是負數
daysLeft rejects malformed dates格式錯誤或不存在的日期會回報錯誤
statusOf uses 0-3 urgent-1、0、3、4、7、8 天分別落在正確的區
label wording逾期、今天到期、剩 N 天的文字正確
renderHtml escapes user text資料中的特殊符號會被安全轉換，不會變成網頁程式碼
sample data matches the expected page範例資料產生的網頁和預期網頁一字不差

用技能重現

預期回報：6 個測試通過；已過期 1、緊急 2、本週 2、之後 2；dist/index.html 與預期頁面一致。

看技能檔 SKILL.md

和範例一的技能結構相同。特別的是 Inputs 規定「重現時一律用基準日 2026-09-21，不能用今天的日期」，否則每天產生的網頁都不同，就無法比對。

用 worktree 平行做兩個功能

現在要同時加兩個功能，而且不希望兩份修改互相干擾：

功能一：類型顏色

作業、考試、報告顯示不同的標籤顏色。

功能二：統計列

在標題下方顯示「共 7 項，其中作業 4 項、考試 2 項、報告 1 項」。

為什麼要用 worktree

如果兩個對話同時修改同一個資料夾，它們會改到彼此的檔案，很難分清楚哪個修改是誰做的。Worktree 讓每個對話有自己的一份檔案副本，本機（Local）像是前景，worktree 像是背景，兩邊互不打擾，完成後再整合。

做法一：在 VS Code 的 Codex 擴充套件中

  1. 對話一在本機做功能一：

  2. 開新對話，先輸入 /worktree，讓這個對話在新的 Git worktree 裡做功能二：

兩個功能都會讓測試中的「和預期網頁一字不差」失敗，這是正常的，因為網頁內容本來就改變了。整合時再更新預期網頁（見下方「整合與審查」）。

做法二：在 ChatGPT 桌面版中

  1. 在新對話畫面的輸入框下方選擇 Worktree，並選擇起始分支（例如 main）。

  2. 送出提示。Codex 會以這個分支建立 worktree，預設處於「detached HEAD」狀態，也就是還沒有掛在任何分支名稱上。

  3. 完成後二選一：

    • 在 worktree 上按 Create branch here 建立分支，再 commit、push、開 PR。
    • 按 Hand off 把對話和程式碼移回 Local，在你平常的 VS Code 視窗中檢查。

做法三：在 VS Code 的 Agents window 中

開新工作階段，Session Target 選 Codex，勾選 New Worktree 並選擇基準分支。記得 worktree 只包含已 commit 的檔案，開始前要先 commit。

Worktree 的注意事項

狀況說明與做法
同一分支不能兩處同時使用在 worktree 建了 feature/a 分支後，本機就無法切換到它。想在本機檢查，改用 Hand off
被 Git 忽略的檔案不會跟過去桌面版可在儲存庫根目錄建立 .worktreeinclude，列出要複製的忽略檔（例如 .env）
新 worktree 缺少套件在桌面版本機環境設定 setup script，建立 worktree 時自動安裝
占用磁碟空間桌面版預設保留最近 15 個 Codex 管理的 worktree；刪除前會存快照，重新打開對話可以還原
需要長期使用從側邊欄專案的三點選單建立 permanent worktree，不會被自動刪除

02總結與課後練習

檢核清單

  • 我知道桌面版、CLI、VS Code 擴充套件各自把什麼當作專案。
  • 我的專案有 AGENTS.md，並確認 Codex 讀到了它。
  • 我知道 .codex/config.toml 只在信任的專案生效，以及設定的優先順序。
  • 我能在 VS Code 中把選取的程式碼加入對話，並使用 /plan、/review、/worktree。
  • 我分得清 Codex 設定（config.toml）和編輯器設定（chatgpt. 開頭）。
  • 我完成了兩個範例，並用 $grade-report、$deadline-board 重現結果。
  • 我知道 worktree 隔離的是程式碼修改，不是安全邊界。

課後練習

  1. 整理專案：為自己的期末專題建立 Codex 專案，釘選專案、把現有對話改成描述成果的標題，並封存已完成的對話。
  2. 寫規則：在專題中執行 /init，把產生的 AGENTS.md 改寫成至少 5 條你們組的規則，並請 Codex 列出它載入的指示來源。
  3. 做一個技能：挑一件專題中會重複做的事（例如「產生週報」或「執行全部檢查並彙整結果」），用 $skill-creator 或手動建立技能，並準備一份預期結果讓技能自我驗證。
  4. 平行作業：在範例二用 worktree 完成兩個功能，最後用 /review 審查，截圖記錄 Hand off 或 Create branch here 的過程。
