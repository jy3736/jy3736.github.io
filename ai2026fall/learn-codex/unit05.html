第 5 單元

動手實作截止日看板

這一節不是讀程式，是做第二次完整的練習：你把看板的規則說清楚，Codex 做出最小可行產品，你用眼睛驗收那一頁網頁，最後用 worktree 同時交辦兩個要求，再整合起來。

01練習目標

做出一個在自己電腦上就能執行的小工具：讀進一份各科的截止日資料，依一個指定的「基準日」算出每一項還剩幾天，分成「已過期、緊急、本週、之後」四區，產生一頁可以用瀏覽器打開的看板。

重點不在寫出程式碼，而在四件事：把分類與排序的規則講清楚、要求結果每次都一樣（可重現）、用眼睛驗收一頁網頁、以及同時交辦兩個要求還能整合得乾淨。

只用虛構資料

範例裡的科目、作業名稱與日期都是虛構的。請勿放入真實的課程名單、同學姓名或其他個人資料；這份練習的成果也不可作為實際的成績或繳交依據。

  • 說清楚分類、排序、頁面與可重現的要求
  • 請 Codex 做先短版提示詞，再完整版
  • 自己核對手算四筆天數，對照頁面
  • 平行交辦用 worktree 同時做兩個要求再整合
和上一個單元的差別

第 4 單元的產出是一份報告文字，這一次的產出是一頁網頁。真正的新東西是最後兩節：同時進行兩件事，以及合併之後怎麼確認沒有互相改壞。

02題目說明

輸入資料

一份 data/deadlines.json 的截止日清單，每一筆有四個欄位：科目 course、名稱 title、類型 type（作業、考試或報告）、截止日 due（年-月-日）。

整份資料是一個串列，最外面用中括號包住，裡面每一組大括號是一筆截止日。這份範例有 7 筆，刻意包含一筆已經過期的、一筆就是基準日當天的，以及剛好落在分區邊界上的兩筆。

基準日

剩幾天要從哪一天算起，叫做基準日。基準日一律由執行指令時指定，沒有指定時才用今天的日期。

為什麼一定要能指定基準日

如果每次都用「今天」，今天做出來的頁面和明天做出來的頁面就會不一樣，你永遠無法確定差異是因為日期換了，還是因為 Codex 改壞了什麼。把基準日固定成 2026-09-21，同樣的資料就應該每次產生一模一樣的一頁，才有辦法逐字比對。這是可重現的意思，也是這個練習最重要的要求。

分類與顯示規則

剩餘天數分到哪一區顯示文字
小於 0已過期逾期 N 天
0緊急今天到期
1 到 3緊急剩 N 天
4 到 7本週剩 N 天
8 以上之後剩 N 天

排序規則

四個區一律照「已過期、緊急、本週、之後」的順序出現。每一區裡面，剩餘天數少的排前面；天數相同時，依科目名稱排序。

頁面要有的內容

  1. 標題與基準日：頁面最上面是「截止日看板」，下面一行寫出這次用的基準日。
  2. 四個區塊：每一區有自己的標題，標題上要帶出這一區有幾項，例如「緊急（2）」。
  3. 每一項的內容：截止日、類型、科目、名稱，以及剩餘天數的顯示文字。
  4. 空的區塊也要在：某一區剛好沒有項目時，還是要列出這一區，裡面寫「沒有項目」。
  5. 一個檔案就能打開：樣式直接寫在頁面裡，不連到外面的網站，用瀏覽器打開就能看。

流程圖解：一筆截止日怎麼變成看板上的一列

  • 1 讀一筆科目、名稱、類型、截止日
  • 2 算天數截止日減基準日
  • 3 分區比對四區的門檻
  • 4 產生文字逾期、今天到期、剩 N 天
  • 5 排序天數少的在前、同天數依科目
  • 6 輸出一頁可以打開的看板

看流程時請注意兩件事。第一，天數是整天的差，同一天到期就是 0 天，不是「剩不到一天」。第二，門檻是含邊界的：剛好 3 天屬於緊急，剛好 4 天就變成本週；剛好 7 天還是本週，8 天才是之後。這兩件事都要在提示詞裡講清楚，否則就是 Codex 替你決定。

03MVP 驗收清單

你不需要看懂程式碼。以下每一項都是執行一次、把頁面打開用眼睛看就能檢查的；只要有一項做不到，就把它寫進「學生驗收紀錄」，再請 Codex 修。

  • Codex 會告訴你要執行哪一行指令；照著執行就會產生看板頁面，不必自己安裝額外套件。
  • 把 Wi-Fi 關掉再執行一次，工具照樣產生得出頁面，打開後版面也正常。
  • 終端機上會印出一行摘要，告訴你四個區各有幾項。
  • 用基準日 2026-09-21 執行時，四區的數量是已過期 1、緊急 2、本週 2、之後 2，合計 7 項，和資料筆數一致。
  • 頁面最上面看得到「截止日看板」和基準日 2026-09-21。
  • 四個區塊依「已過期、緊急、本週、之後」的順序出現，區塊標題帶著該區的項目數量。
  • 每一項都看得到截止日、類型、科目、名稱與剩餘文字，沒有缺欄位。
  • 同一區裡面，剩餘天數少的排在前面。
  • 用同一個基準日再執行一次，產生出來的頁面和上一次完全相同（頁面上沒有「產生時間」這類每次都會變的內容）。
  • 換一個基準日執行一次，例如 2026-10-01，四區的項目會跟著改變，數字也合理。
  • 複製一份 data/deadlines.json 成 data/test.json，在副本裡把某一筆的日期改成 2026-13-45 這種不存在的日期，再對副本執行一次：工具會用看得懂的話告訴你哪一筆有問題，不會產生一頁怪怪的看板，也不會噴出看不懂的錯誤。原始的 deadlines.json 保持不動。
  • 請先自行手算，再用下列四筆核對頁面：
項目截止日剩餘天數應分到顯示文字
作業二：堆疊與佇列2026-09-18-3已過期逾期 3 天
實習二：Git 操作2026-09-210緊急今天到期
第一次小考2026-09-254本週剩 4 天
讀書心得2026-09-287本週剩 7 天

後面兩筆是邊界案例：4 天剛好跨過緊急與本週的界線，7 天則剛好還留在本週。如果工具把小考放進緊急、或把讀書心得放進之後，就是門檻的比較條件寫錯了。第二筆也值得注意：當天到期顯示的是「今天到期」，不是「剩 0 天」。

  4. 這個資料夾附了一份現成的實作。練習的重點是自己把需求講清楚，所以先把答案移走，只留下截止日資料與專案規則。

做出來以後先別急著往下。執行一次、把頁面打開看兩分鐘，然後把下面這些問題問自己一遍：分成幾區、每一區的界線是誰決定的？「剩幾天」是從哪一天算起的，明天再跑一次還會一樣嗎？同一區裡面的順序是照什麼排的？已經過期的那一筆被放到哪裡去了？如果資料裡有一個不存在的日期，它會怎麼處理？

短版沒有錯，它只是把這些決定全部交給了 Codex。你在頁面上看到的每一個「它自己決定的細節」，都是你沒講的部分。

接著請 Codex 依照下面這段重做一次。完整版講的就是你剛才發現自己漏掉的那些事：

兩次的差別在哪

把兩次產生的頁面並排看一次。多出來的內容幾乎都不是「Codex 變聰明了」，而是你把原本沒說的話說了出來。其中最關鍵的一句是「同樣的資料配同樣的基準日，產生出來的那一頁必須一模一樣」，因為它讓你之後每一次修改都有辦法驗證。

05用 worktree 同時交辦兩個要求

MVP 驗收通過之後，再把以下兩個要求加上去。這一節的重點不是這兩個功能本身，而是同時進行兩件事而不互相干擾。

要求一：類型顏色

作業、考試、報告三種類型，在看板上用不同的底色標示，一眼分得出來。

要求二：統計列

在標題下方加一行統計：「共 7 項，其中作業 4 項、考試 2 項、報告 1 項」。

為什麼要用 worktree

如果兩個對話同時修改同一個資料夾，它們會改到彼此的檔案，很難分清楚哪個修改是誰做的。Worktree 讓每個對話有自己的一份檔案副本，本機（Local）像是前景，worktree 像是背景，兩邊互不打擾，完成後再整合。

做法一：在 VS Code 的 Codex 擴充套件中

  1. 對話一留在本機，做要求一：

  2. 開一個新對話，先輸入 /worktree，讓這個對話在自己的工作副本裡做要求二：

兩邊都會遇到同一件事：原本「產生出來的頁面要和上一次一模一樣」的那項自動檢查會失敗。這是正常的，因為頁面的內容本來就被你改變了。正確的處理順序在下一節，不是先把預期結果改掉。

做法二：在 ChatGPT 桌面版中

  1. 在新對話畫面的輸入框下方選擇 Worktree，並選擇起始分支（例如 main）。

  2. 送出提示。Codex 會以這個分支建立 worktree，預設處於「detached HEAD」狀態，也就是還沒有掛在任何分支名稱上。

  3. 完成後二選一：

    • 在 worktree 上按 Create branch here 建立分支，再 commit、push、開 PR。
    • 按 Hand off 把對話和程式碼移回 Local，在你平常的 VS Code 視窗中檢查。

做法三：在 VS Code 的 Agents window 中

開新工作階段，Session Target 選 Codex，勾選 New Worktree 並選擇基準分支。記得 worktree 只包含已 commit 的檔案，開始前要先 commit。

Worktree 的注意事項

狀況說明與做法
同一分支不能兩處同時使用在 worktree 建了 feature/a 分支後，本機就無法切換到它。想在本機檢查，改用 Hand off
被 Git 忽略的檔案不會跟過去桌面版可在儲存庫根目錄建立 .worktreeinclude，列出要複製的忽略檔（例如 .env）
新 worktree 缺少套件在桌面版本機環境設定 setup script，建立 worktree 時自動安裝
占用磁碟空間桌面版預設保留最近 15 個 Codex 管理的 worktree；刪除前會存快照，重新打開對話可以還原
需要長期使用從側邊欄專案的三點選單建立 permanent worktree，不會被自動刪除

想一想

為什麼要先改規則說明、再改程式、最後才更新預期結果，而不是直接把預期結果換成程式現在產生的那一頁，讓比對「通過」？如果反過來做，這項檢查還能幫你抓到什麼？

08課程總結與課後練習

檢核清單

  • 我知道桌面版、CLI、VS Code 擴充套件各自把什麼當作專案。
  • 我的專案有 AGENTS.md，並確認 Codex 讀到了它。
  • 我知道 .codex/config.toml 只在信任的專案生效，以及設定的優先順序。
  • 我能在 VS Code 中把選取的內容加入對話，並使用 /plan、/review、/worktree。
  • 我分得清 Codex 設定（config.toml）和編輯器設定（chatgpt. 開頭）。
  • 我完成了兩次練習，並用 $grade-report、$deadline-board 重現結果。
  • 我會要求「同樣的輸入每次要產生一樣的結果」，並用它來驗證每一次修改。
  • 我知道 worktree 隔離的是檔案修改，不是安全邊界。

課後練習

  1. 整理專案：為自己的期末專題建立 Codex 專案，釘選專案、把現有對話改成描述成果的標題，並封存已完成的對話。
  2. 寫規則：在專題中執行 /init，把產生的 AGENTS.md 改寫成至少 5 條你們組的規則，並請 Codex 列出它載入的指示來源。
  3. 做一個技能：挑一件專題中會重複做的事（例如「產生週報」或「執行全部檢查並彙整結果」），用 $skill-creator 或手動建立技能，並準備一份預期結果讓技能自我驗證。
  4. 平行作業：用 worktree 完成截止日看板的兩個要求，最後用 /review 審查，截圖記錄 Hand off 或 Create branch here 的過程。
