從問題集資料夾產生自主測驗網頁實作教學

Module 2 教學帶你把考古題 PDF 變成「一題一張乾淨圖片 ＋ 標準答案 JSON」的問題集資料夾。這份教學接著往下一步走：把問題集資料夾交給 build-quiz-app 這個 Claude Code skill，產生一個不用架站、雙擊就能打開的學生自我測驗網頁，外加一個老師用來彙整全班成績的頁面。一樣不需要自己寫程式，在 Claude Code 對話視窗用自然語言下指令即可；文中也附上每個步驟對應的指令列指令，給想手動執行、或想確認 Claude Code 有沒有跑對的人參考。

本教學對應 module3/ 資料夾，裡面已經有兩份完整跑過、可以直接打開來玩的成品，你可以隨時對照「正確結果長什麼樣子」。

這兩份問題集資料夾，其實就是 Module 2 教學做出來的東西 —— 只是換了一組資料，重跑一次「下載／切題／清理」流程而已（module3/raw/ 放原始 PDF，module3/repo/ 放切好清好的圖片＋keys.json）。module3/raw/ 底下其實還有第三組資料（115 學年度數學(C)）已經下載好、但還沒切題清理，留給本教學「動手做」單元練習整條 Module 2 ＋ Module 3 的流程。

學習目標

做完這份教學，你應該能夠：

  • 用 Claude Code，把 Module 2 產出的問題集資料夾（一題一張圖片 ＋ keys.json），轉成一個雙擊即可開啟的學生自我測驗網頁。
  • 看懂 analyze_folder.py 印出的分析報告在講什麼，知道哪些欄位可以放心略過、哪些欄位出現異常就要先停下來問人。
  • 看懂 config.json 的「assessments 陣列」設計 —— 同一個 app/ 底下可以疊加好幾份測驗，之後每週只要多加一筆、不用整個重建。
  • 分得清楚 dist/*.html（雙擊即用成品）跟 quiz.html／config.json（可編輯原始碼）的差別，知道原始碼版本本機測試為什麼要另外開伺服器。
  • 自己動手，把 module3/ 裡還沒處理的第三組資料，走一次「切題 → 清理 → 建立測驗」全流程，疊加成 module3/app/ 的第三份測驗。

先備條件

  • 已經完成 Module 2：考古題下載、切題與清理實作教學，手上至少有一組「*.png 圖片 ＋ keys.json」的問題集資料夾。本教學直接沿用 module3/repo/114、module3/repo/math-115a 這兩組已經做好的資料當範例，你也可以換成自己練習做出來的資料夾。
  • 已經能開啟並使用 Claude Code。若還沒設定好工作環境，請先參考 Module 1：Windows 11 環境建置。
  • 本機已安裝 Python 3 —— 這一步不需要另外 pip install 任何套件，analyze_folder.py 和 build_bundle.py 只用到 Python 內建函式庫（跟 Module 2 需要額外安裝 pymupdf／pillow／numpy 不同）。
  • 能開啟終端機（Terminal／PowerShell），並且知道如何切換到專案根目錄（也就是能看到 module3/、.claude/ 這兩個資料夾的那一層）下指令。
  • 這一整套流程都是離線的、不需要網路連線（Module 2 的下載階段才需要網路）。
這個工具一樣包成 Claude Code 的 skill，放在 .claude/skills/build-quiz-app/ 資料夾底下。你只要在 Claude Code 對話視窗打自然語言描述你想做的事，Claude Code 會自動判斷該用哪個 skill；如果想更保險、或想離開 Claude Code 直接跑，文中每個步驟都附上對應的指令列指令。

整體流程總覽

build-quiz-app 這個 skill 內部分成六個步驟，前一步的輸出就是下一步的輸入：

步驟在做什麼輸入輸出
① 找輸入輸出確認問題集資料夾在哪、app/ 要蓋在哪問題集資料夾路徑決定 app/ 的位置
② 分析資料夾用腳本掃描 keys.json 與圖片，推論檔名規則問題集資料夾一份 JSON 分析報告
③ 寫進 config.json把分析結果整理成一筆 assessment 設定②的分析報告app/config.json 多一筆資料
④ 打包把圖片轉成 base64，塞進 quiz.html 樣板③的設定app/dist/<examLabel>_quiz.html
⑤ 驗收確認檔案存在、大小合理、實際點開能用④的成品放心交付
⑥ 交付把兩種產出分開講清楚，附上教師端彙整頁—學生拿到測驗、老師拿到彙整工具

整個 app/ 資料夾只需要建立（或請 Claude Code 建立）一次；之後每多一組問題集資料，只需要重跑②～④，把新的一筆設定疊加進同一個 config.json，不需要砍掉重建。module3/app/ 現在已經疊了兩筆 —— 待會的「動手做」單元會讓你親手疊上第三筆。

步驟一：找輸入輸出資料夾

位置規則

app/ 固定蓋在問題集資料夾的同層（sibling），不是塞進問題集資料夾裡面。以 module3/ 為例，問題集資料夾是 module3/repo/<name>/，所以 app/ 蓋在 module3/app/，跟 module3/repo/ 平級 —— 這樣以後問題集資料夾即使被整理、封存或換掉，app/ 這個「引擎」也不會受影響。

如果 app/ 已經存在（就是 module3/app/ 這種情況）：代表之前已經對同一層底下的另一組問題集資料夾跑過這個 skill。這是正常情況，不是衝突 —— 預設做法是在既有 config.json 的 assessments 陣列裡再加一筆，而不是整個覆蓋掉。quiz.html、build_bundle.py、report-aggregator.html 這三個檔案是共用引擎，可以直接用最新版樣板覆蓋，不會影響已經疊進去的其他測驗。

用一句話請 Claude Code 做

module3/repo/114 這個問題集資料夾（圖片 + keys.json）已經做好了，
麻煩幫我用 build-quiz-app 這個 skill，把它變成一個雙擊就能打開的自我測驗網頁。

Claude Code 會自動判斷輸出要放在 module3/app/（module3/repo/ 的同層），不用你自己算路徑。

步驟二：分析問題集資料夾

腳本：analyze_folder.py

這一步只讀取、不寫入任何檔案，目的是讓 Claude Code（或你自己）在動手寫設定之前，先確認這個問題集資料夾的形狀 —— keys.json 在哪、圖片在哪、檔名有沒有規律。

指令

python3 .claude/skills/build-quiz-app/scripts/analyze_folder.py module3/repo/114

對 module3/repo/114 實際跑起來，會印出這樣的報告：

{
  "folder": "module3/repo/114",
  "keysFile": "114keys.json",
  "questionCount": 100,
  "answerLetters": ["A", "B", "C", "D"],
  "multiAnswerCount": 0,
  "multiAnswerSample": [],
  "repoDir": ".",
  "missingImages": [],
  "missingImageCount": 0,
  "extraImageFiles": ["114keys.json"],
  "extraImageFileCount": 1,
  "filenamePattern": "^114專業(?<group>[12])Q(?<number>\\d+)\\.png$",
  "filenamePatternNote": "group token candidates: ['1', '2']"
}

每個欄位在講什麼

欄位怎麼解讀
keysFile / questionCount找到的答案 JSON 檔名、裡面有幾題。跟你預期的題數（例如專業科目 50 題 × 2 科 = 100）對一下。
repoDir圖片放在哪個子資料夾。如果是 "."，代表圖片跟 keys.json 直接放在同一層，沒有再包一層 repo/ 子資料夾 —— module3/repo/114、module3/repo/math-115a 都是這種情況。這時 config.json 裡要把 "repoDir": "." 明確寫出來，不能省略（省略等於預設值 "repo"，會找錯地方）。
missingImages / missingImageCountkeys.json 裡有寫、但找不到對應圖片檔的題目。這裡是 0，代表 Module 2 的清理成果沒有缺檔；如果不是 0，打包時這些題目會被自動跳過，記得先跟自己確認是否要接受。
extraImageFiles / extraImageFileCount資料夾裡有、但 keys.json 沒提到的檔案。這裡列出 114keys.json 自己 —— 這是正常現象：因為 repoDir 是 "."，分析器把整個資料夾掃過一輪，keys 檔本身當然不會出現在 keys 的內容裡，被算成「多出來的檔案」，可以放心忽略，跟圖片缺漏無關。
multiAnswerCount / multiAnswerSample答案有一個字母以上的複選題數量。這裡是 0；如果不是 0 也不用特別處理，測驗頁面本來就用「整組答案完全相同」判對錯，只是提醒你別意外。
filenamePattern / filenamePatternNote從檔名推論出來的規則（JS 具名捕獲群組語法）。114 這組因為檔名裡有「專業1」跟「專業2」兩種，被抓出一個 group（用來分科目）加一個 number（題號）；math-115a 檔名只有題號沒有科目差異，所以只有 number、沒有 group（見下方）。如果這裡是 null，不是失敗 —— 代表這組檔名沒有清楚規律，config.json 就直接不寫這個欄位，測驗頁面會退回用原始檔名逐題顯示，一樣能正常運作，只是不會按科目平均分配抽題。

module3/repo/math-115a 跑出來的報告比較單純，可以對照著看兩者的差別：

{
  "folder": "module3/repo/math-115a",
  "keysFile": "115keys.json",
  "questionCount": 25,
  "answerLetters": ["A", "B", "C", "D"],
  "repoDir": ".",
  "missingImageCount": 0,
  "extraImageFiles": ["115keys.json"],
  "filenamePattern": "^115數學AQ(?<number>\\d+)\\.png$",
  "filenamePatternNote": "single template — number-only pattern"
}

驗收重點

  • questionCount 跟你預期的題數一致。
  • missingImageCount 是 0（如果不是，先決定要不要接受這些題目被跳過，不要直接無視）。
  • answerLetters 如果超出 A～D，記得下一步 config.json 的 choiceLetters 要跟著改，不然那些字母選項在作答畫面上不會出現。
  • filenamePatternNote 裡如果列出 group 候選字元，肉眼確認一下這些字元真的代表有意義的分類（例如「1」「2」對應兩個不同科目），不是湊巧撞到的雜訊；如果看起來不合理，寧可不寫這個欄位。

步驟三：把資料寫進 config.json

檔案：app/config.json

config.json 放的是一個 assessments 陣列，每一筆對應一份測驗。module3/app/config.json 目前實際的內容如下 —— 兩筆都是直接把上一步分析報告的欄位對應過來：

{
  "assessments": [
    {
      "examLabel": "Formative_Assessment_115_MathA",
      "assetsDir": "../repo/math-115a",
      "keysFile": "115keys.json",
      "repoDir": ".",
      "questionCount": 20,
      "choiceLetters": "ABCD",
      "filenamePattern": "^115數學AQ(?<number>\\d+)\\.png$"
    },
    {
      "examLabel": "Formative_Assessment_114",
      "assetsDir": "../repo/114",
      "keysFile": "114keys.json",
      "repoDir": ".",
      "questionCount": 20,
      "choiceLetters": "ABCD",
      "filenamePattern": "^114專業(?<group>[12])Q(?<number>\\d+)\\.png$"
    }
  ]
}

每個欄位怎麼填

欄位怎麼填
examLabel這份測驗的名字，會變成輸出檔名的一部分（<examLabel>_quiz.html）。陣列裡每一筆都要不一樣 —— 加新的一筆之前，先看一眼既有陣列裡已經用過哪些名字。
assetsDir從 app/ 這個資料夾出發，走到問題集資料夾的相對路徑。這是唯一一個分析報告不會直接告訴你的欄位，要自己算 —— 例如問題集資料夾是 module3/repo/114、app/ 是 module3/app/，相對路徑就是 ../repo/114。
keysFile / repoDir / questionCount（原始題數）/ filenamePattern直接照抄步驟二分析報告的對應欄位。filenamePattern 是 null 時整個欄位不寫。
questionCount（config.json 裡實際寫的值）不是原始題數，是「每次作答預設抽幾題」，公式是 min(20, 分析報告的 questionCount)。114 有 100 題、math-115a 只有 25 題，兩筆卻都寫 20 —— 就是因為兩者都超過或等於 20，取 min 之後都是 20。學生開始作答時仍然可以自己把題數改成 1～全部題數之間的任何數字，這裡只是預設值。
choiceLetters沒特殊情況固定寫 "ABCD"；只有分析報告的 answerLetters 超出 A～D 才需要換成對應字母組合。

如果是對已經有內容的 app/config.json 疊加新測驗（就像 module3/app/ 現在的狀態），記得先讀出既有內容，用陣列 push 的方式加一筆，不要整個檔案覆蓋掉，不然會把之前疊上去的測驗設定弄丟。

步驟四：打包成單一檔案

腳本：build_bundle.py

這一步把 config.json 裡每一筆設定指到的圖片，逐一轉成 base64 字串，塞進 quiz.html 樣板裡一個叫 window.QUIZ_DATA 的區塊，輸出成一個完全自包含、不需要 fetch()、不需要網路的 HTML 檔。

指令

cd module3/app
python3 build_bundle.py

不加任何參數，預設會重建 config.json 裡全部的測驗。如果只想重建剛剛新加的那一筆（例如另外兩份都已經是最新的，重新打包全部只是浪費時間、每份都可能是好幾十 MB），加 --only：

python3 build_bundle.py --only Formative_Assessment_114

產出：每一筆測驗對應 module3/app/dist/<examLabel>_quiz.html 一個檔案。終端機會印出類似：

Wrote module3/app/dist/Formative_Assessment_115_MathA_quiz.html (25 questions, 2.6 MB)
Wrote module3/app/dist/Formative_Assessment_114_quiz.html (100 questions, 15.1 MB)
Built 2/2 assessments

驗收重點

  • 最後一行 Built N/M assessments 的 N 要等於 M。如果不相等，代表某一筆被跳過了，往上看那一筆對應的 Warning: skipped ... 訊息，通常是 keysFile／repoDir／assetsDir 路徑寫錯。
  • 如果某一筆印出「Warning: N image(s) ... are missing」，代表這一批圖片有缺檔，那幾題會被靜靜跳過、不會出現在測驗裡 —— 回頭跟步驟二的 missingImageCount 對一下，數字應該一致。

步驟五：驗收成果

不要只信任「腳本沒報錯」

  • 確認 dist/ 底下每份預期的檔案都存在，檔案大小落在合理範圍：大約是「來源圖片總大小 × 1.37」（base64 編碼會讓檔案膨脹約 37%）。以 114 為例，module3/repo/114 底下所有 PNG 加起來約 11 MB，11 × 1.37 ≈ 15.1 MB，跟實際輸出的 Formative_Assessment_114_quiz.html 大小吻合；如果輸出檔案明顯小很多，通常代表大部分圖片沒被塞進去。
  • 直接雙擊（或用瀏覽器開啟本機檔案路徑）打開 dist/ 裡的檔案，不要另外開伺服器 —— 整個重點就是驗證「不架站也能用」。輸入姓名、選一個較小的題數、作答幾題、按送出，確認會出現分數跟逐題對錯畫面。
  • 如果暫時沒辦法用瀏覽器操作，至少打開檔案搜尋 window.QUIZ_DATA 有沒有出現，並抽查幾筆 data:image/png;base64, 開頭的內容是不是非空字串。

步驟六：教師端成績彙整

檔案：report-aggregator.html

學生在測驗頁面送出作答後，畫面上有一顆「下載成績單 (CSV)」按鈕，會把這次作答的逐題結果存成一個 CSV 檔（檔名自動帶學生姓名跟時間戳記）。module3/app/report-aggregator.html 就是給老師用來把全班這些 CSV 檔合併起來看的工具 —— 一樣是雙擊即可開啟、不需要架站，也不會把任何資料上傳到網路上。

  • 把收到的多個 CSV 檔，拖曳（或點擊選取）到頁面上的拖放區。
  • 畫面會自動依考試名稱分組，列出「每位學生答對／總題數／正確率」跟「每一題的出現次數／答對次數／答對率」兩張表 —— 後面這張表特別適合用來看哪幾題全班普遍答錯，回頭檢討教學重點。
  • 可以按「匯出合併 CSV」把所有載入的紀錄存成一份檔案，或按「列印 / 存成 PDF」留存書面紀錄。

report-aggregator.html 是通用的，複製一份就能重複用在任何一份測驗、任何一個班級，不需要為了不同考試另外設定。

動手做：疊加第三份測驗

module3/raw/math-115c/ 底下已經有 115 學年度數學(C) 的試題與標準答案 PDF，但還沒切題、也還沒清理 —— 整個 module2/repo/ 跟 module3/repo/ 都還沒有任何一組叫 math-115c 的資料夾。這剛好是一個從頭走完整條「Module 2 切題清理 → Module 3 建立測驗」流程、疊加成 module3/app/ 第三份測驗的完整練習。

第一步：切成單題圖片＋答案 JSON（Module 2 的 skill）

共同科目通常是 25 題，記得加 --total；輸出檔名會固定寫「專業」兩字（slice-exam-pdf 目前的已知限制，跟 Module 2 教學處理數學(B) 時遇到的狀況一樣），之後要手動改名成「數學」：

python3 .claude/skills/slice-exam-pdf/scripts/slice_exam_pdf.py \
  --year 115 \
  --subject "C:module3/raw/math-115c/115數學C試題.pdf:module3/raw/math-115c/115數學C答案.pdf" \
  --total 25 \
  --out-dir module3/repo/math-115c

切完後檔名會是 115專業CQ<n>.png，請 Claude Code 幫忙統一改成 115數學CQ<n>.png（keys.json 裡的 key 要同步改）：

剛剛切出來的檔名是 115專業CQ<n>.png，這其實是數學科，
麻煩幫我全部重新命名成 115數學CQ<n>.png，
keys.json 裡對應的 key 也要同步改成新檔名。

第二步：清理圖片（Module 2 的 skill）

對 module3/repo/math-115c 資料夾裡的每張 *.png：
1. 裁掉下面多餘的空白（含「以下空白」殘影），但不要裁到真正的內容。
2. 清掉題號，但 (A)(B)(C)(D) 選項不要動。
執行塗白之前，先「乾跑」一次，把每張圖偵測到的題號區塊印出來讓我看過，
確認每張圖都剛好抓到 1 個題號區塊之後，才正式塗白存檔。

驗收重點跟 Module 2 教學步驟三完全一樣：乾跑時每張圖剛好偵測到 1 個題號區塊、選項字母沒被動到、底部沒有殘留不相關的文字。

第三步：跑分析、疊加進 config.json、打包（本教學的 skill）

python3 .claude/skills/build-quiz-app/scripts/analyze_folder.py module3/repo/math-115c

報告應該會看到 questionCount: 25、repoDir: "."、filenamePattern 類似 ^115數學CQ(?<number>\d+)\.png$ —— 跟 math-115a 是同一個模子刻出來的，可以直接拿 config.json 裡 Formative_Assessment_115_MathA 那一筆當模板改。把新的一筆加進 module3/app/config.json 的陣列（記得 examLabel 要跟既有兩筆不同，例如 Formative_Assessment_115_MathC），然後只重建這一筆：

cd module3/app
python3 build_bundle.py --only Formative_Assessment_115_MathC

最後照步驟五驗收：檔案存在、大小合理、雙擊打開能正常作答送出。完成後 module3/app/config.json 應該有三筆 assessments，module3/app/dist/ 也應該多一個檔案，另外兩份既有測驗完全不受影響。

狀況代表什麼該怎麼做
analyze_folder.py 印出 error: ambiguous_or_missing_keys_file資料夾裡有不只一個、或完全沒有 .json 檔，腳本猜不出哪個是答案 key看 candidates 列出的檔名，用 --keys-file 明確指定再重跑
repoDir 是 null 或出現 error: could_not_locate_image_folder腳本找不到圖片放在哪確認圖片路徑後用 --repo-dir 明確指定再重跑
repoDir 是 "."，但 config.json 裡漏寫了這個欄位repoDir 省略時的預設值是 "repo"，跟 "." 不一樣，打包時會去找不存在的 repo/ 子資料夾"repoDir": "." 一定要明確寫進 config.json，不能省略
filenamePattern 找出來了，但 group 候選字元看起來是雜訊檔名剛好符合腳本的推論規則，但那個「差異」其實不代表任何有意義的分類不要硬寫進 config.json，直接省略這個欄位，讓測驗頁退回用原始檔名逐題顯示
build_bundle.py 印出 Built N/M assessments，N < M至少一筆 assessment 打包失敗往上找對應的 Warning: skipped ...，通常是 assetsDir／keysFile／repoDir 路徑寫錯
新加的 examLabel 跟既有某一筆撞名examLabel 同時決定輸出檔名，撞名會互相覆蓋加新的一筆之前，先看一眼 config.json 既有陣列用過哪些名字
直接雙擊 app/quiz.html（不是 dist/ 裡的檔案），畫面空白或作答按鈕沒反應quiz.html 是「可編輯原始碼」版本，要用 fetch() 讀取 config.json 跟圖片，瀏覽器基於安全性會擋掉 file:// 底下的 fetch()要測原始碼版本，在 app/ 資料夾下開一個本機伺服器再開瀏覽器：python3 -m http.server；真正要交給學生的是 dist/*.html，不需要伺服器
改了 config.json 之後，dist/ 裡的檔案內容沒變dist/*.html 是打包當下的快照，不會隨 config.json 即時更新改完 config.json 一定要重跑一次 build_bundle.py（可以只加 --only 那一筆）
